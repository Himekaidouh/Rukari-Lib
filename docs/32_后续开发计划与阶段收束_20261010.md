日期：2026-10-10。当前决定：暂停全局/点光照路线，把它保留为实验档案，不纳入下一版稳定用户包。后续开发回到已经有实际用户价值、能够通过官方工程流程保存和播放的功能。

## 光照路线的处理

最近部署的 1.6.4 候选版已经证明 UI 事件能够触发、方向光 shader 能加载，但没有证明画面像素真正改变。日志还显示人物实际使用的 `Spine/Skeleton Tint` 未被材质适配器接受，背景 draw call 也没有完成独立材质的视觉证明。因此，这条路线现在的状态是“实验接入完成、视觉验收失败”，不是一个可以继续堆功能的稳定基础。

本轮已执行以下收束动作：

1. 全局光照、点光源、光源图层和相关 UI 已从下一版稳定用户包路径移除。
2. 光照源码、失败边界、测试日志、备份和部署回执已移入 `lighting-removal-archive-20261010`，作为独立实验档案。
3. 1.6.5 清理版只保留人物、镜头、预设动作、屏幕文字和 AAP2 兼容投影；当前 AA1.01 的 1.6.4 候选安装保持不动，回滚时使用已有备份和部署脚本，不手动覆盖 DLL。
4. 不再把“颜色变亮”“统一乘色”当作光照替代品。未来若重新评估，只从分层合成、遮罩、景深和 2D 视差等低风险方案开始。

## 下一阶段优先级

### 第一阶段：稳定现有功能

- 固定 AA 1.0、1.01 的支持矩阵和每个版本对应的用户包。
- 对编辑预览和正式播放分别测试：空对白、非空对白、AUTO、手动推进、绿色重播、首次冷启动、切卡和换场景。
- 对三号槽位及其他槽位验证连续位移继承、初始位置、归位和重复重播。
- 将 FL 开启/关闭、同句同时出现官方与 AAVT 指令、不同存档路径列入固定兼容测试。
- 处理 `AzureArchive.VideoTools.Core.dll is not registered in il2cpp` 这类环境问题的诊断信息，但不把一次成功启动当成所有用户都兼容。

### 第二阶段：完成人物与镜头表现

- 保留四类预设动作：左右摇摆、Y 轴原地转身、头槌、挤压拉伸。
- 补齐动作的次数、频率、持续到下一句、结束归位和贝塞尔曲线，并明确暂停、快进和跳卡语义。
- 完成 X 轴旋转，同时保持旧 `rotation` 和 Y 轴转身的含义不变。
- 完成整体镜头与仅背景镜头的独立继承、独立复位和全部复位；确认对白、按钮和工具窗口不被缩放。
- 优先做资源缓存和异步加载，减少换差分、切场景和预览时的卡顿；不通过逐帧读取工程文件解决实时预览。

### 第三阶段：收紧保存与播放链路

- 让编辑器预览和正式播放尽量消费同一份规范化指令表示。
- 明确空对白的动作时间轴：由动作时长自动等待，或由工程显式记录 wait；不能靠空行是否被播放器跳过来决定动作是否执行。
- 继续保留官方工程保存、编译、发布入口，避免直接改写 `.aap`、`.aas` 或官方工程清单。
- 每次发布同时提供用户包、版本说明、SHA256 和回滚包；源码、开发文档与用户包分开组织。

### 第四阶段：语音与模组兼容

- 保留全局配音音量和 AUTO 专用等待；手动点击或 Enter 应能跳过语音等待。
- 导入时去重、限制扫描范围并对自定义存储路径给出明确诊断，避免重复音频和无界扫描。
- 继续检查页面遮挡、第三方模组窗口、FL 指令共存和模组加载顺序。
- PE/Android 适配在桌面稳定矩阵完成后单独推进，不与桌面稳定包混发。

## 暂缓项目

完整光照系统、法线和阴影、三维背景、骨骼级头部动画、战斗系统、完整播放页面重制、官方原生注册迁移的最终替换，以及实验性 Spine 叠加台都暂不进入下一版稳定计划。它们可以保留为设计文档或独立实验分支，但不应继续扩大稳定版的改动面。

## 稳定版发布条件

下一版只有在以下条件同时满足时才标记为正式版：

- 用户包不再包含实验性光照入口、命令和资源。
- AA1.0 与 AA1.01 都完成预览/正式播放、AUTO/手动、空/非空对白、FL 共存和自定义存档路径验证。
- RukariLib、更多画面效果、人物配音支持的版本号和依赖关系一致，旧工程可以打开并保存。
- 托管测试、实机视觉测试和用户日志诊断分开记录；没有用“构建通过”替代“画面生效”。
- 发布包、源码包、文档和回滚包来自同一构建回执。

当前最合理的下一步是先恢复无光照实验的稳定效果包，再做人物动作、镜头双范围和官方保存/播放链路的实机矩阵，而不是继续修补光照材质适配。
