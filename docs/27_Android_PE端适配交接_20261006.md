## 4. 工程结构与可复用边界

下列路径均相对源码仓库根目录。

| 目录 | 职责 | Android 处理方向 |
| --- | --- | --- |
| `src/Rukari.Lib` | 公共契约、服务宿主、主线程队列、工具/设置模型、编辑事务、指令路由 | 优先复用；验证宿主运行时支持的托管 API |
| `src/Rukari.Lib.Runtime` | BepInEx 插件、Unity/NGUI UI、编辑器对象读取、共享编译补丁 | Android 接入重点 |
| `src/AzureArchive.VideoTools.Core` | 自有指令解析、变换规划、继承、预设采样、身份/授权/时长策略 | 优先复用；它是托管库，不是游戏组件 |
| `src/AzureArchive.VideoTools.Formats` | AAP JSON、AAS FlatBuffer 读取，Mod 自有工作区/sidecar | 验证 PE 格式与路径，再复用；不直接重写官方工程 |
| `src/Rukari.MoreEffects` | 效果插件、立绘/镜头编辑、预设窗口与运行实现 | 替换游戏接入和移动输入，保留算法 |
| `src/AzureArchive.VideoTools` | MoreEffects 实际链接编译的历史共享源码 | 必须一起交接、按 csproj 的 Include/Exclude 选择有效文件 |
| `src/Rukari.CharacterVoice` | 配音绑定、音频导入/发布、原生音频通道、AUTO 等待 | 平台文件选择、存储、音频生命周期都需验证 |
| `src/Rukari.SpineSupport` | Spine/记忆大厅适配 | 后置；不要加入第一组节点闪退对照 |
| `src/examples` | 四个公共接口示例 | 用于公共 API 回归和开发者接入示例 |
| `src/assets/rukari-lib/ui` | Lib 独占共享图集、坐标元数据、装饰与哈希清单 | 原样保留配套文件，校验路径/纹理，不依赖 PE 官方图集位置 |

当前上述主项目为 `net6.0`。全游戏构建通过 `Directory.Build.props/targets` 引用 `{GameRoot}/BepInEx/core` 与 `interop`；Runtime 使用 `BepInEx.Unity.IL2CPP.BasePlugin`、Il2CppInterop、Harmony，以及 AA / Unity / NGUI / Spine 声明。

当前 `build.ps1` 的 Target 仅 `Release10`、`Preview10`，二者部分功能项目都定义 `AA_PREVIEW_10`；这不是 Android 目标。原构建回执还收集 `GameAssembly.dll`、`UnityPlayer.dll` 等桌面输入。

不要用 PC interop 冒充 Android interop；不要把 `libil2cpp.so` 政名成 `GameAssembly.dll` 来骗过构建。应新增明确 Android 目标/引用根与输入回执，或建立专用宿主项目，记录实际 Android 声明和加载器版本。

## 5. 当前功能链：不是日志执行器，也不是全量官方指令注册

### 5.1 编辑与编译

```text
当前 Script 行
  → Lib 的 IEditorDocumentService 读取行、内容与修订身份
  → MoreEffects 草稿生成 / Voice 绑定
  → UIInput.Set(text, false) → ScriptNodeInspector.SetAdditionalPrompt()
  → 官方编辑会话保存当前额外指令
  → Lib 共享编译边界摘取已登记的 Mod 指令
  → AA 编译剩余的官方文本
  → 功能 Mod 解析自己的指令并取得执行所需身份
```

共享补丁在 `src/Rukari.Lib.Runtime/Commands/EmbeddedDirectivePatch.cs`，目标为：

```text
Script.get_ScriptKr
Script.CompileScriptStandalone
Script.CompileScriptContinuous
```

处理器在 `src/Rukari.Lib/Commands/EmbeddedDirectiveService.cs`。只摘取注册命名空间拥有的指令行，未知指令继续由官方处理；不能为兼容 PE 全局关闭官方校验、吞掉其他 Mod 文本，或把编译 getter 变成播放入口。

MoreEffects 使用 `src/AzureArchive.VideoTools/Runtime/EditorEmbeddedDirectivePatch.cs` 消费共享服务，不应再安装一套互相覆盖结果的编译净化补丁。

当前正式实现 **没有把全部 AAVT 指令登记成官方原生解析器自身的指令类型**。最新候选接入官方动画列表，也不等于完成全量官方指令注册。普通日志历史上参与识别/关联，但命令解析、当前场景核对和执行授权是独立层；不能收到任意带 `#aavt` 的日志就执行。

## 6. Script 节点闪退：优先检查的具体位置

下面是排查优先级，**不是已确认根因排序**。以最小对照和崩溃堆栈决定下一步。

| 边界 | 代码入口 | 为什么节点打开时值得查 |
| --- | --- | --- |
| 共享 UI 的工作区识别 | `Rukari.Lib.Runtime/Editor/EditorWorkspaceContext.cs` | Script Inspector 出现后才读取 container、node、UIPanel 祖先与 WindowManager；PE 层级/声明可能不同 |
| 当前台词文档读取 | `Rukari.Lib.Runtime/Editor/NativeEditorDocumentBackend.cs` | 首次读缓存行、selected、index、scripts、UIInput 与活体对象 |
| 编译净化 | `Rukari.Lib.Runtime/Commands/EmbeddedDirectivePatch.cs` | 进入/预览节点可能首次实际调用被 detour 的 getter / compiler |
| DataList 观察 | `AzureArchive.VideoTools/Runtime/EditorDataListEventProbe.cs` | MoreEffects Load 中安装；关闭视觉面板不等于撤销它 |
| UI 输入拦截 | `Rukari.Lib.Runtime/Tools/ToolInputService.cs` 与 `Rukari.MoreEffects/Runtime/VisualEditorInputGuard.cs` | 当前拦截 NGUI 鼠标/键盘路径，Android 触摸流未验证 |
| 工具栏与面板创建 | `Rukari.Lib.Runtime/Tools/ToolboxDrawer.cs`、`Rukari.MoreEffects/Runtime/VisualEditorBehaviour.cs` | 可能直到进入 Script 工作区才首次创建/读取原生 UI、字体或变换 |
| 编辑器即时预览/播放器 | `AzureArchive.VideoTools/Runtime/PlayerCommandObservationRuntime.cs` | 如果节点打开自动重播，Test、slot 与编译输入会同时被访问 |
| 配音解析/资源桥 | `Rukari.CharacterVoice/Runtime/VoiceSupportPatch.cs` | 钩住 preSubScript、ParseScript、VoiceExists、TryGetVoiceOverridePath；无配音工程也要测试是否触发 |
| 配音原生加载状态机 | `Rukari.CharacterVoice/Runtime/VoicePlaybackRuntime.cs` | 编译生成的预加载类型、SetVoice 重载及协程形状可能随 PE 构建变化 |
| 路径桥与索引加载 | `AzureArchive.VideoTools/Interop/OfficialStoragePathBridge.cs` | 开始预览/播放时读取 Authoring 会话与 ResourceManager；PE 自动化类型不一定相同 |
| 新动画等待（仅最新候选） | `AzureArchive.VideoTools/Runtime/PlayerActionTimelineRuntime.cs` | ParseScript 返回列表、WaitAnimation、协程和回调需要单独验证 |

`WasCollected=false`、`Pointer!=0` 与反射找到属性都不能证明一次原生调用一定安全。`try/catch` 能处理托管异常，不能当作原生 SIGSEGV / SIGABRT 的防护措施。若是 MissingMethod / 类型初始化 / JIT 入口失败，方法体内的 catch 也可能没有执行机会。

## 7. 必须保留的已知危险边界

以下是项目历史隔离项，不应为了“读当前选中台词”或“捕获更多事件”重新启用：

- `ScriptNodeInspector.selectedScriptItem` 原生 getter：已有实现改为核对可见行，不能回退到这个 getter。
- `ScriptNodeInspector.OnChildSelect(Selectable)`：接收原生子对象的回调在本项目被列为黑名单；`EditorSelectionEventProbe` 当前只是托管确认，没有该原生 hook。
- `Test.Clear(Nullable<uint>)`：项目记录过生成 native→managed trampoline 在 `Buffer.Memmove` 中失败，配音明确不 patch Clear；不能因为 Harmony prefix 不带参数就认为整个 trampoline 安全。
- 官方生产编译的带 byref IL2CPP 值型闭包生成 emitter：当前空节点修复没有触碰它；不可用桌面签名猜 ARM64 调用约定。
- `Script.VoiceJp` getter：VoiceSupportPatch 明确避开它，避免共享原生 getter 地址影响无关字段。
- `VoicePlaybackRuntime` 中旧版本注释提到的 RVA / `script.json`：不是 Android 地址契约，不可复制过去作为 hook 地址。

普通 `Core.dll` / `Formats.dll` 是托管算法库，不是 Unity 组件。遇到 `Assembly ... is not registered in il2cpp` 时，应追踪谁把托管类型交给了 IL2CPP 的组件/类型查找；**不要批量给所有程序集/类做 IL2CPP 注入注册，也不要简单屏蔽这条错误。** 真正继承 Unity MonoBehaviour 的自定义组件才需要按当前加载器的注入流程验证。

只查项目自有源码、当前运行日志、官方随包/加载器生成的声明与所需文件元数据；不读取或复制 AA 官方反编译方法体。本次交接核查也没有读取 APK 中的官方函数实现。

## 9. 收集日志与识别崩溃类别

### 9.1 需要的证据

- 从本次启动开始的 BepInEx `LogOutput.log`，不是只有最后一条警告。
- Launcher 的崩溃诊断导出、logcat 的 main/system/crash 内容；原生 signal、线程和堆栈尤其重要。
- 若系统允许取得，原生 tombstone / crash 摘要；不可假定普通文件管理器有权限读取系统目录。
- 一段精确复现步骤：刚进入节点，还是第一行预览、选人物、打开更多效果、导入音频时崩溃。

NextBep 当前项目说明有日志查看、崩溃诊断导出与下次启动的 debug snapshot。ci.2 的具体入口和位置需实际确认；优先使用它的导出能力，不要求用户手动访问应用私有目录。[NextBep 诊断说明](https://github.com/NextBep/BepInEx.Android.Launcher)

BepInEx 配置/日志路径应从当前 `BepInEx.Paths` 和加载日志取得，不能硬编码桌面 `BepInEx/LogOutput.log`。MoreEffects 额外诊断的源码规则为：

```text
<BepInEx.Paths.ConfigPath>/AzureArchive.VideoTools/diagnostics/
  player-command-observation-YYYYMMDD-HHMMSS.log
```

教程将 ConfigPath 放在 Profile 的 `configs` 下；日志根仍应核对实际运行。若崩溃发生在该功能初始化之前，没有这份附加日志也是有意义的证据。

### 9.2 只读 ADB 收集示例

设备序列号由 `adb devices` 取得，不复制教程中的私人序列号。使用自己 Android SDK 的 adb；教程本机例子在 `H:\Program Files\Netease\MuMuPlayer-12.0\shell\adb.exe`，本次没有核验该程序是否存在。

```powershell
$adb = 'C:\path\to\platform-tools\adb.exe'
$serial = '替换为实际设备序列号'
& $adb devices
& $adb -s $serial shell getprop ro.product.cpu.abi
& $adb -s $serial shell getprop ro.build.version.release
& $adb -s $serial shell dumpsys package com.foxxlight.AzureArchive
& $adb -s $serial shell dumpsys package com.bepinex.android.launcher

# 第一窗口先开始收集，然后在手机复现；出现闪退后停止这次收集。
& $adb -s $serial logcat -v threadtime -b main -b system -b crash > '.\android-script-crash.log'

# 第二份为当前 crash 缓冲区快照，可能受设备权限限制。
& $adb -s $serial logcat -b crash -d > '.\android-crash-buffer.log'
```

不要先清空系统日志；不要只按 AA 包名过滤，因为游戏在 Launcher 容器内运行，加载器/CoreCLR 的关键错误可能被过滤掉。只收集复现时间段并在分享前去除无关个人信息。Android 日志具有多个缓冲区，默认 main 不包含所有系统和崩溃信息。[Android Logcat 文档](https://developer.android.com/tools/logcat)

### 9.3 判断表

| 证据 | 优先调查 | 不应直接得出的结论 |
| --- | --- | --- |
| MissingMethod / TypeLoad / TypeInitialization / AssemblyLoad | PE 声明、依赖、实际程序集副本、运行时 API | 不是只改一个 catch 就一定解决 |
| SIGSEGV / SIGABRT、native→managed trampoline 堆栈 | ARM64 detour、封送、类注册、对象寿命、共享原生地址 | 不是普通空引用就能托管捕获 |
| 进程退出但没有 C# 异常 | 系统 crash/exit reason、Launcher 诊断、低内存 | 不能只看 BepInEx 最后一句认定某 Mod |
| UI 卡住 / ANR | 主线程文件读取、解码、资源枚举、锁与同步等待 | 和立即闪退需分开处理 |
| 编辑正常、正式播放没效果 | 存储根、AAP/AAS 配对、当前行与编译身份、AUTO 首卡 | 不能直接关闭索引校验来强行执行 |

## 10. 第二阶段：建立 Android 运行适配层

### 10.1 能力探测与构建

启动先产出平台能力报告：OS/ABI、Unity、CoreCLR、BepInEx/Harmony/Interop 版本、实际引用来源、所需类型/完整方法签名、是否可安装相应 hook。签名存在只是静态条件，状态仍需区分“声明匹配”“hook 已装”“首次调用通过”“完整功能通过”。

Android 构建必须使用**当前 Android 游戏/加载器生成的 interop**，不得随用户包携带 PC `Assembly-CSharp.dll`、UnityEngine 或另一平台的 Il2CppInterop。所有 Unity 同名程序集和 extern alias 要指向同一套声明，避免 PC 与 Android 类型混在同一进程。

若 Android 宿主确实支持当前 net6 API，优先保留 TFM；如果不支持，再有针对性地多目标或替换 API，记录取舍。不要仅为“手机”全仓库降级，也不要在纯算法库中引入 AndroidJNI/Unity 对象。

建议新增以下职责的宿主接口/兄弟接口，名称可调整，这些接口目前**尚未实现**：

- 平台能力与日志输出。
- 编辑器当前文档读取/写回。
- 播放窗口、当前行与动画完成边界。
- 人物、镜头的原生姿态读写。
- 指针/触控/文本输入及输入占用。
- 官方工程/资源路径与外部音频选择/读取。

维持 Lib 现有公共接口签名与程序集版本约定（当前 `Rukari.Lib` AssemblyVersion 是 `0.2.0.0`）；通过新接口/重载增加能力，不改变旧方法参数来冒称兼容。PC 和 Android 的原生实现分离，Core 的解析/算法/授权逻辑共享。

### 10.2 类注册、主线程与寿命

重点验证 Lib `RuntimeBehaviour`、MoreEffects 各 Behaviour、Voice Behaviour 的 `BasePlugin.AddComponent<T>` 路径，以及 `IntPtr` 构造、回调和当前类注入机制。记录实际需要注入的自有 Unity 类，不对整包做自动注册。

Unity/NGUI/IL2CPP 活体对象只在游戏主线程取得和使用；后台只接收托管字符串、数值、只读快照与文件任务结果。不要为了减少 Android 开销跨帧/跨线程缓存 Inspector、Script、Character、AudioSource 包装器。

项目/节点/行/人物实例或存储根变更时，旧缓存、预览租约、pending、后台结果和等待都必须失效。仅凭名字相同不能确认还是同一人物。退出/暂停/恢复后重新确认当前对象，避免向销毁后的 native 对象写入。

### 10.3 触控、布局与文本输入

现有工具栏、设置窗与效果编辑器主要依赖 `Input.mousePosition`、鼠标按下/拖动/松开、滚轮及键盘/IME。部分设备可能模拟单指鼠标，但不能据此保证触控、软键盘、多指和滚动都正常。

Android 实现需将统一指针事件送入现有工具模型，明确主指针归属；拖动角色/旋转/镜头时不可同时触发官方台词选择或播放推进。验证实际 NGUI 触摸处理签名，再选择触摸占用边界，不能只拦 `ProcessMouse()` 就宣布完成。

保留工作区规则：侧边栏仅在可见且就绪的 Script 编辑区接受输入；打开人物、表情、背景、音乐、音效等官方选择窗时隐藏工具及其输入占用，返回后恢复当前工作区状态。

布局处理横屏比例、安全区域、系统栏、分辨率/缩放、软键盘遮挡和最小点击面积；增添触控滚动/数字页码跳转。不要依赖 Alt+1..5、Ctrl+F6、F 键或滚轮作为唯一操作方式。共享图集仍只由 Lib 提供，缺资源时回退外观，不对错误图集应用旧坐标。

### 10.4 文件与存储

确定需要替换的代码：

```text
src/Rukari.CharacterVoice/Runtime/WindowsVoiceFolderPicker.cs
src/Rukari.CharacterVoice/Runtime/VoiceFolderController.cs
```

前者 P/Invoke `ole32.dll`、`user32.dll` 并使用 Windows 文件对话框；后者默认创建它。`PickAsync` 会先检查 `OperatingSystem.IsWindows()`，在 Android 抛出 `PlatformNotSupportedException`，因此不能用“引用 Windows DLL”直接推断它在打开 Script 时已经执行原生调用。可以确定的是当前文件夹选择功能未适配。

应按平台选择 `IVoiceFolderPicker` 实现。该接口现在也定义在 `WindowsVoiceFolderPicker.cs` 开头；若 Android 构建排除整个文件，先把接口移到独立契约文件，否则会一起删掉 Controller 和测试所依赖的接口。

Android 系统目录选择可以考虑 Storage Access Framework 的 `ACTION_OPEN_DOCUMENT_TREE`。返回结果是授权 URI，不应冒充普通磁盘目录交给 `Directory.EnumerateFiles`；需要 URI/流的读取适配，或复制到明确受管理的导入暂存目录，再沿现有发布链导入。目录选择存在系统限制，取消、授权失效和应用恢复都应返回可理解状态。[Android 文件访问文档](https://developer.android.com/training/data-storage/shared/documents-files)

当前 `IVoiceFolderPicker` 形状以目录字符串为中心；若采用 URI 流读取，不要伪造绝对路径，需增加兄弟接口或由 Android 层显式管理暂存，确保扫描器/导入器的能力与接口一致。用户反对的是为增益生成额外增强音频副本；正常资源导入复制与该增益副本是不同事情。

可先给诊断版提供受管理导入目录作为有限过渡，但正式版本应提供直接可用的选择入口，不要求用户寻找 inbox 或反复切页面。

工程/资源根应读取当前 Android 官方会话与 ResourceManager 的有效路径。PC 路径桥目前使用 `AuthoringEditorSession.Current.FilePath` 和 `ScenarioResourceManager.Instance.LocalOverrideData.basePath`；必须先核对 PE 声明与寿命。路径不存在/不可读取时停止该功能，不能退回另一个已安装 AA 的默认目录执行旧指令。

处理大小写、路径分隔、`/sdcard` 别名、中文/空格文件名、URI 权限和目录切换。`ConfigPath`、插件根、官方工程根、资源根分开；读取 `/sdcard` 和 `/storage/emulated/0` 同一对象时不得制造两套索引。不要递归扫描手机全盘来碰运气找工程。

背景单独放大与整体放大是不同范围；整体处理 Back + Spine，背景范围只处理对应背景层，Front UI 不随镜头变换。PE 需按实际层级/对象验证，不把 PC 的 GameObject 布局和坐标单位视为必然相同。

首次测试只用有文字卡片、已占用三号槽位、瞬时位移，避免把空节点映射与原生动画时序一起引入。通过后再逐项加持续动画、继承、预设、贝塞尔、镜头双范围。

## 12. 配音：移植时保留的行为

关键源码为 `VoiceSupportPatch.cs`、`VoicePlaybackRuntime.cs`、`VoicePublicationRuntime.cs`、`Core/VoicePlaybackMethodPolicy.cs`、`Core/ProjectVoiceImportPolicy.cs` 和 `Runtime/VoicePlaybackSettingsPage.cs`。

配音使用 AA 原生语音资源/播放通道，自己的指令负责绑定；不应另建一套无资源归属、无法发布的临时 AudioSource 来绕过现有链。

`AudioManager.SetVoice` 在已检查 PC AA 中存在单参/双参差异，预加载协程的生成编号也会变化。现有最新代码按实际声明选择路径；PE 仍需重新核对类型和调用行为。不得硬编码生成类编号、给官方回调造不等价替代参数，或拿旧 PC 的具体函数地址作为 Android 依据。

最新要求：语音完成及用户设置的额外间隔只约束 AUTO，默认额外间隔 0 秒；手动点播放推进区域或 Enter 可以跳过。Android 将经过核验的官方“手动推进”动作送入这条语义，不把任何触摸（包括点设置/拖人物）都当作跳过。

全局音量/间隔由 Lib 模组设置提供，每个 Mod 独立设置栏。保留当前默认音量 50% 的既有语义和原音频，**不重新引入增益音频副本或失效语音清理按钮**。当前音量控制受原生音源上限和音量资格检查限制，不能把滑块标成无限 dB 增益。

必须测编辑预览有声、发布后有声、重启后有声、自定义存储有声、直接 AUTO 首句有声，以及手动跳过后下一句仍能正常播放。

### 13.1 有限动作与官方时间轴（1.5.5 候选）

详见 `docs/26_有限动作与官方播放时间轴_20261006.md`。

实现借助真实 ParseScript 返回的 `scenarioAnimations` 中一个官方 `ScenarioAnimation.WaitAnimation`，而非写入 `#wait` 或主动调用 AdvanceScenario。有限动作并行时等最晚完成者；次数/频率计时，循环到下一句的动作不无限阻塞。只有实际派发成功后计算截止，冷索引只保留一个仍属于当前行的等待窗口。

当前启动等待上限 10 秒、动作结束诊断余量 3 秒。等待实例、当前播放器、行、模式、存储上下文和动画列表的归属要重新验证；完成只结束自己的等待，由官方回调推进，不改全局动画计数、不重复调用 Start。

Android 首先关闭/不编入这项新原生边界完成基础适配，然后单独核对 WaitAnimation 构造、原生 Task/协程、Complete 回调与取消。等待配置 false 只回退动作等待，不代表整个解析输入观察自动消失；完整隔离必须检查安装代码。

### 13.2 整段全空 Script 节点仍有边界

已有锚点的空卡片，与整个节点没有文字，是两件事。全空节点的 AAP→AAS 对应需要可靠的官方编译输出证据；当前安全捕获未覆盖所有生产编译路径。

```text
compile-mapping-capture: no observed script emissions; proof omitted
```

出现这句时不能凭卡片排列/行号猜正式播放绑定，也不能把“加入动画等待”当作映射已修复。Android 移植先分开记录此问题；整个全空节点必须单列验收，失败时明确降级/限制，不能错误应用其他场景的动作。

### 13.3 其他保留边界

- `.aap2` 等不同格式不能默认与已检查 `.aap` 配对规则相同。
- 改存储目录、多个可能前序、索引过期或身份冲突应拒绝执行，不选一个“看起来差不多”的工程。
- Android 后台/恢复、暂停和倍速与预设 Stopwatch 的时间语义尚未验收。
- FL 共存修复是 PC 已有经验，不构成 Android 对任意第三方 Mod 的兼容保证；不得覆盖对方 Harmony prefix/postfix 或本来有效的指令文本。
- UI Mod 单选/重启规则是 Lib 设置层的设计；这次节点崩溃任务先保证基础工具和设置安全，不顺带开始另一套播放 UI 大修。

## 15. 验收矩阵与最小测试指令

至少覆盖一台真实 ARM64 手机；教程 Pixel 7 可作为固定环境，但当前是否可用尚未确认。模拟器只能补充性能与分辨率测试，不能替代实际 ARM64 原生调用。

| 类别 | 必测 | 结果要求 |
| --- | --- | --- |
| 生命周期 | 主界面→项目→Script→返回，连续多次；项目 A/B 切换；后台恢复 | 无闪退、旧对象写入、异常洪泛和旧等待 |
| 编译/编辑 | 官方指令、AAVT、混合指令、非法 AAVT、未知其他指令 | 官方行为保留；错误只影响对应功能且有可读说明 |
| 预览 | 切卡片、绿色重播、同一句反复重播、保持三号选槽 | 坐标/起点一致、无漂移、不自动选回一号 |
| 正式播放 | 保存发布后首次手动、首次直接 AUTO、手动转 AUTO | 不是只有编辑预览正常 |
| 动画 | duration=0、有限动作并行、有限/循环预设、取消/换句 | 有限能完成；循环不永久锁死；不多推进一次 |
| 继承 | 连续两句同人物、新人物入场、显式 A、删除显式 A | 同人继承，新人默认，显式 A 优先 |
| 镜头 | 仅背景、整体、复位、与人物动作并行 | Front UI 不被缩放，双范围不互相污染 |
| 语音 | WAV/OGG/MP3、首次/重复加载、手动跳过、AUTO 间隔、音量 | 声音与下一句归属正确，不强制手动等完 |
| 文件 | 中文/空格、取消/拒绝权限、目录切换、重复导入、重启 | 不丢工程、原音频不被改写，导入/发布一致 |
| UI | 官方各选择窗、模组设置、软键盘、不同屏幕比例 | 工具隐藏/恢复正确，无输入穿透和挡住操作 |
| 共存 | 单 Mod 基线→三包→可用第三方 Mod | 每种组合单列结果，不把 PC FL 通过当 PE 通过 |
| 桌面回归 | fix6 与 1.0beta 同一指令集 | 构建/托管检查和必要原生操作分别记录 |

在一个有文字的卡片、官方已把人物放入三号槽位后，先测：

```text

```

再测有限位移：

```text
#aavt;char;3;set;x=600;y=0;duration=1500;easing=easeInOut
```

```text
#aavt;char;3;set;startX=-600;startY=0;x=600;y=0;duration=1500;easing=easeInOut
```

最新指令集的有限/循环预设：

```text
#aavt;fx;3;sway;amplitude=25;frequency=2;cycles=4;direction=right
#aavt;fx;3;sway;amplitude=25;frequency=2;cycles=0;direction=right
```
