# 候选 0.4.5 / 1.6.7：输入法与预览配额修复（2026-10-14）

本文记录 0.4.4 / 1.6.6 发布之后的两项修复。用户包在 `releases/20261014-输入法修复-candidate/`，面向 AA 1.01。

## 修复一：安装后无法呼出中文输入法

**现象**：装模组后 `Win+空格` 切不出输入法、候选窗不出现；输入法进程在运行，但游戏窗口不认它。英文输入一直正常。

**证据**（用户在自己的开发副本复现，助手读日志）：

```text
Shared compact toolbox created. …
[input] composition Auto; owners=0      ← 唯一与输入相关的行，出现在工具箱初始化那一刻
```

整场没有 `[input] composition On`，也没有 `[input] keyboard captured` —— 用户没有碰过任何工具输入框，我们却写入了进程级的 `Input.imeCompositionMode`。

**代码位置**：`ToolInputService.ApplyComposition()` 原来在"没有 owner 想要合成"时把开关写成引擎默认的 `Auto`，释放时同样写死 `Auto`。

**修复**：第一次真正需要合成时才读取并**保存**游戏当前的值，最后一个使用者释放时**还原**该值；**从未接管过就完全不写这个开关**。新增三行可读日志：`[input] composition observed …`（只读）、`engaged; game had …`、`restored to …`，以及键盘占用的 `captured/released`。

**复测**：修复后的部署里中文输入恢复正常，日志显示我们只读未写。

**边界**：观察到的值本身就是 `Auto`，与游戏原值相同 —— 所以坏的**不是值，而是"给这个属性赋值"这个动作**（Unity 在赋值时会重设窗口的输入法关联）。这一条是推断；已确认的是"去掉这唯一一次写入后症状消失"。配置开关 `[Input] TakeOverKeyboardAndIme`（默认 true）可让用户把键盘与输入法完全交还游戏。

## 修复二：一行多段人物/预设效果时整行预览失效

**现象**：一行里写超过 5 条人物指令时，绿色预览整行被拒（日志 `EDITOR_PREVIEW_LEASE_REJECTED … action=NO_OP`），界面上没有任何提示，效果也不出现。

**代码位置**：`EditorPreviewLeasePlanner.ValidateCommands` 对人物与预设按**指令条数**计数；镜头在 [docs/45](45_镜头窗口与层写入_20261013.md) §7.8 已经改成按资源计数。

**修复**：人物与预设也按**占用的资源**（槽位 / 预设公共槽）计数，上限仍为 5 个槽 / 5 个预设；Spine 继续按指令条数（它限制的确实是叠加轨道的数量）。

**测试**：新增 `TheCharacterBudgetCountsSlotsAndNotSegments` —— 六个效果跨三个槽、六个跨五个槽都必须通过，超出场景指令上限仍然被拒；原 `EnforcesCanonicalSixResourceLimitAndExplicitTombstones` 中"第七条同槽指令应被拒"的断言按新契约改为**接受**，测试改名为 `EnforcesCanonicalSpellingSlotBudgetAndExplicitTombstones`（它现在管的是规范化拼写、槽位预算与墓碑授权）。
