# 人物立绘操控技术实现

本文对应本源码包的 Rukari Lib 0.4.1 与 MoreEffects 1.4.0，说明人物槽位、图形摆放、变换指令、待入场状态、连续场景继承、预设动作与编辑事务的实际实现。源码链接均相对于本文件；内容依据当前源码核对，不把代码注释中的“已绑定”“候选”“待验收”统一解释为已经完成游戏内验收。

## 阅读路径

首次阅读建议依次看“人物占位与坐标模型”“变换指令如何执行”“空槽待入场”“跨场景继承与重播”。需要调整动作算法时，再看“四种预设和贝塞尔时序”；需要理解编辑器行为时，看“草稿、应用和撤销”。最后的源码索引和测试索引可以用于逐项追踪。

完整流程如下：

```text
当前台词与 additionalPrompt
    │
    ├─ 图形编辑器 / 预设动作面板
    │     → 数值草稿 → 单条公开指令 → 文档合并预览
    │     → 选择令牌与版本核对 → 官方输入路径写回 → 精确读回
    │
    └─ AA 编译边界
          → Rukari Lib 按注册命名空间净化文本
          → MoreEffects 提取、规范化并捕获指令
          → 编译身份 / 当前选择 / 场景观察窗口匹配
          → 运行队列
          → 空槽到场扫描、前序链重建、当前场景指令
          → CharacterTransformService 或 CharacterPresetRuntime
          → 现有 Character / Transform / NGUI Tween
```

其中，编辑“应用”负责把指令写入当前台词；画面中的角色变换由播放或重播此句触发。修改工程文本与修改当前显示帧是两个不同的动作。

## 1. 人物占位与坐标模型

### 1.1 物理槽位、人物身份和图形标记

立绘操控的公开槽位是 `1..5`。运行时 `CharacterTransformService.Resolve(publicSlot)` 读取 `Test.Instance.slots[publicSlot - 1]`，解析槽位内现有的 `Character`、根 `Transform`、`character.identifier` 与 `GetInstanceID()`。

槽位是剧情播放器的物理位置索引，不是学生编号，也不是一直绑定某个角色的虚拟实体。一个角色退场后，另一个角色可以占用同一个槽位。运行时变换和基线因此同时核对槽位、人物标识，部分路径还核对角色实例身份，防止把旧角色的数值套到槽位里的新角色上。

图形编辑器为五个槽位创建固定选择按钮、辅助线和可点击的槽位标记。已占用槽位显示当前运行状态；空槽显示“待入场”标记和可编辑草稿。空槽标记是编辑器中的操作对象，不会因此创建或隐藏一个实际角色。

这里所说的“人物占位”有几层含义：固定物理槽位、编辑器的槽位锚点、空槽图形标记、待入场变换，以及同一角色在连续场景中的状态继承。`charPending` 只负责其中的“空槽待入场变换”，不能用它概括整套人物摆放机制。

源码入口：

- [CharacterTransformService.cs](../src/AzureArchive.VideoTools/Interop/CharacterTransformService.cs)：`ReadSlotsOnMainThread`、`Resolve`、`ReadState`。
- [VisualEditorBehaviour.cs](../src/Rukari.MoreEffects/Runtime/VisualEditorBehaviour.cs)：`SelectSlot`、`SelectedPosition`、`UpdateInspector`、槽位选择按钮与图形标记。
- [CharacterTransformContracts.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterTransformContracts.cs)：槽位变换、状态、基线和目标的数据契约。

### 1.2 剧情坐标 = 槽位锚点 + 槽位内偏移

`VisualEditorCanvasMath` 中的逻辑剧情宽度是 `2960`，中心为 `0`。五个槽位锚点使用固定间距 `520`：

| 公开槽位 | 锚点 X | 锚点 Y |
| --- | ---: | ---: |
| 1 | -1040 | 0 |
| 2 | -520 | 0 |
| 3 | 0 | 0 |
| 4 | 520 | 0 |
| 5 | 1040 | 0 |

转换公式：

```text
anchorX(slot) = (slot - 3) × 520
storyX = anchorX(slot) + localOffsetX
storyY = localOffsetY
localOffsetX = storyX - anchorX(slot)
```

因此，角色指令中的 `x`、`y` 对应运行时 `Character.GetPos()/SetPos()` 使用的数值；在本图形编辑器中，这组数值按槽位内偏移表示。图形界面另行显示加上锚点之后的剧情坐标。

例如槽位 2 的 `x=100`，图形上的剧情 X 是 `-520 + 100 = -420`。把槽位 5 放在剧情中心，需生成 `x=-1040`，而不是 `x=0`。`x=0` 的含义是位于该槽位自身的默认锚点。

空槽的初始偏移由 `DefaultPendingPosition()` 返回 `(0,0)`，所以它的图形标记起初也在对应槽位锚点。拖动时先把鼠标位置转为剧情坐标，再执行 `StoryToSlotLocal()`，最终写入的仍是偏移。

源码：[VisualEditorCanvasMath.cs](../src/AzureArchive.VideoTools.Core/VisualEditor/VisualEditorCanvasMath.cs) 的 `SlotAnchor`、`SlotLocalToStory`、`StoryToSlotLocal`；[VisualEditorBehaviour.cs](../src/Rukari.MoreEffects/Runtime/VisualEditorBehaviour.cs) 的拖动处理与 `SlotLocalToStory`。

### 1.3 图形视口不改变运行时坐标

编辑器视口额外缩远至剧情宽、高的 `1.3` 倍，使稍微离开游戏画面的槽位标记仍可看到、点击。剧情高度按 `2960 × 屏幕像素高 / 屏幕像素宽` 计算。

`StoryToViewport` 与 `ViewportToStory` 负责编辑器图形坐标映射。这个 `1.3` 倍只影响编辑器视口显示，不进入人物变换指令，也不是剧情镜头的 zoom。

人物标记的旋转点击判定使用 `ContainsRotatedRect`，拖动启用阈值使用 `ExceedsDragThreshold`。这些是纯数值几何，独立于实际角色的骨骼、贴图轮廓和解剖部位。

## 2. 变换指令如何执行

### 2.1 公开语法、规范形式和数据模型

公开的额外指令语法：

```text
#aavt;char;3;set;x=100;y=20;rotation=-10;flipX=true;duration=500;easing=easeInOut
#aavt;char;3;move;dx=80;dy=-20;drotation=15;duration=400;easing=linear
#aavt;char;3;reset;duration=250;easing=easeOut
```

内部规范形式是 `#char;<slot>;<operation>;...`，命令家族 ID 为 `character.transform/v1`。公开文本到内部文本由 `EmbeddedAavtDirectiveExtractor` 转换，再由 `CharacterTransformCommandFamilyCompiler` 规范化。`CharacterTransformDirectiveParser` 解析分号分段、属性和值；重复属性、未知属性和与操作不兼容的属性都会返回错误。

`CharacterTransformCommand` 使用可空字段区分“明确设置”与“没提到这个轴”。后者不会自动补成零。命令带公开槽位、操作、绝对/相对位置、绝对/相对屏幕旋转、翻转、毫秒时长和缓动。

| 操作 | 数值语义 | 未指定的轴 |
| --- | --- | --- |
| `set` | `x/y/rotation` 指定目标值；`flipX` 指定相对原始朝向的翻转状态 | 保留当前值 |
| `move` | `dx/dy/drotation` 加到当前状态上 | 保留当前值 |
| `reset` | 回到该角色当前连续谱系保存的原始状态 | 整体恢复基线 |

`set` 至少要改变一个属性；`move` 至少要提供一个相对量；`reset` 不接受位置、旋转、翻转属性。`flipX` 只属于 `set`，不是 `move` 的相对属性。

验证范围来自 [CharacterTransformCommandValidator.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterTransformCommandValidator.cs)：槽位 `1..5`、时长 `0..600000 ms`、旋转或相对旋转 `±3600°`，所有数值必须有限。源码没有给 X/Y 限定为游戏可见区域，允许移到画外。

源码：[CharacterTransformDirectiveParser.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterTransformDirectiveParser.cs)、[CharacterTransformCommandFamilyCompiler.cs](../src/AzureArchive.VideoTools.Core/Commands/CharacterTransformCommandFamilyCompiler.cs)、[CharacterTransformPlanner.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterTransformPlanner.cs)。

### 2.2 rotation 是屏幕倾斜；flipX 使用 Y 轴半转

普通人物指令的 `rotation` 与 `drotation` 对应“画面上看到的 Z 轴倾斜”，并非原地转身预设使用的 Y 轴旋转。

实际横向翻转通过 Y 轴增加半周实现。`CharacterScreenRotation.IsHorizontallyFlipped()` 将 Y 角归一化后，以 `abs(signedY) > 90°` 判定当前横向朝向。Y 轴半转会反向映射物理 Z 轴的倾斜，因此读取状态时把原生 Z 转为屏幕 Z，写回时再把目标屏幕 Z 转回原生 Z。这样角色翻转前后，同一个 `rotation=10` 保持同一画面倾斜方向。

普通 `set flipX=true/false` 是相对于原始朝向基线的明确状态，重复播放同一条 `flipX=true` 不应反复翻回来。其目标由 `CharacterTransformPlanner.FlipY()` 结合原始 Y 角与当前 Y 角计算。

普通角度采用距离当前角度最近的等价角，避免 `-10°` 被误解释为向 `350°` 绕大圈。命令值绝对值 **大于** `360°` 时，`IsDeliberateMultiTurn()` 将它视为有意多圈路径，保留原始幅度；恰好 `360°` 不属于这个多圈条件。运行写回的 `ToPhysicalDegreesFromLive()` 同样保留多圈量。

源码：[CharacterScreenRotation.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterScreenRotation.cs)、[CharacterAngleMath.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterAngleMath.cs)、[CharacterTransformPlanner.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterTransformPlanner.cs)。

### 2.3 主线程解析现场、规划目标、写入 Tween

`CharacterTransformCommandDispatcher.DispatchOnMainThread()` 首先解析指令，必要时用手动选择的槽位覆盖命令槽位，再根据来源选择普通执行或重播执行。

`CharacterTransformService.ExecuteCommandWithOriginOnMainThread()` 的核心顺序是：

1. 检查 Unity 主线程、场景身份及命令参数。
2. `SuspendOverlay(slot)` 先移除该槽位暂时显示的预设偏移，防止把动作中途的倾斜当成作者基线。
3. 当次重新解析现有槽位与角色，读取位置和屏幕旋转。
4. 取得或捕获角色的原始谱系基线；普通非 reset 命令还捕获场景重播基线。
5. `CharacterTransformPlanner.Plan()` 只计算托管目标数值，不写游戏对象。
6. `Apply()` 按目标的 `PositionChanged/RotationChanged` 分别执行位置与旋转。

位置读取和写入走 `Character.GetPos()/SetPos()`；带时长的位置走 `character.posTweener` 对应的 `TweenPosition.Begin()`。旋转走根 `Transform.localEulerAngles` 或 `TweenRotation.Begin()`。

旋转 Tween 设置 `from/to` 为规划的欧拉角，并令 `quaternionLerp=false`，避免 Quaternion 重新转回 `0..360` 后丢掉最近角或有意多圈路径。普通人物变换的 `easing` 映射到 NGUI 的 `Linear/EaseIn/EaseOut/EaseInOut`。

零时长位置写入会停用旧的 position tweener；零时长旋转写入先建立一个零时长 `TweenRotation`，再停用它并直接写角度，防止上次长 Tween 下一帧继续覆盖恢复结果。

若写位置或旋转失败，`FailAfterRollback()` 尝试恢复本次修改过的轴；恢复失败的错误带 `ResidualMutationMarker`。这是可报告的失败结果，不构成所有原生写入都必定回滚成功的保证。

源码：[CharacterTransformCommandDispatcher.cs](../src/AzureArchive.VideoTools/Interop/CharacterTransformCommandDispatcher.cs)、[CharacterTransformService.cs](../src/AzureArchive.VideoTools/Interop/CharacterTransformService.cs) 的 `ExecuteCommandWithOriginOnMainThread`、`Apply`、`SetPositionImmediately`、`SetRotationImmediately`、`FailAfterRollback`。

## 3. 空槽待入场：charPending 的具体语义

### 3.1 它保存一次到场变换，不创建角色

```text
#aavt;charPending;2;set;x=-200;y=0;rotation=15;flipX=true
#aavt;charPending;2;move;dx=-200;dy=0;drotation=15
```

规范形式是 `#charp;...`，命令家族 ID 为 `character.slotPending/v1`。它复用人物变换解析器，但构造时设置 `allowTimingProperties:false`，因此不接受 `duration/easing`。也不接受 `reset`：空槽尚无角色基线可恢复。

`charPending` 指向空的物理槽位，不记录角色名，也不生成角色实例、改变学生选择、调用入场命令、隐藏立绘或决定角色退场。角色仍由 AA 原本的剧情内容进入该槽位；待入场变换只处理其下一次到场时的初始摆放。

图形草稿生成器根据当前占用状态选择 `char` 或 `charPending`。空槽草稿强制时长为零、缓动为线性；已占用槽位使用普通人物命令。

源码：[SlotPendingCommandFamilyCompiler.cs](../src/AzureArchive.VideoTools.Core/Commands/SlotPendingCommandFamilyCompiler.cs)、[VisualCharacterDraftBuilder.cs](../src/AzureArchive.VideoTools.Core/VisualEditor/VisualCharacterDraftBuilder.cs)。

### 3.2 已保存播放路径：暂存、检测到场、消费一次

`StoreSlotPendingOnMainThread()` 检查规范根令牌、参数和场景身份；如果成功解析到槽位已有实际角色，则拒绝暂存。`SlotPendingStore` 按槽位编号保存条目：同槽位后写覆盖前写，条目包含来源场景身份、变换命令和创建观察窗口序号。

`ScanSlotPendingsOnMainThread()` 在主线程扫描五个槽位，比较 `_previousSlotPresence`。只在槽位当前有角色、上次尚未观察到有角色时尝试消费。消费用 `TryConsume()` 先删除条目，再调用 `ApplyConsumedPending()`；本次应用失败也不会自动保留并反复重试这条命令。

消费后，以新到场角色的 AA 初始状态规划目标：

- `set` 的绝对 X/Y/屏幕旋转使用明确值；没写到的轴保留刚入场的官方值。
- `move` 的相对量加到刚入场的值上。
- 显式翻转以新到场的 Y 朝向为基础加半转，保持与初次变换一致。
- 目标时长始终为零；入场后立即摆放，不启动待入场 Tween。
- 先保存未修改的角色原始状态；成功应用后，把实际结果捕获为当前场景重播基线。

“下一句”是常见用法，但运行代码真正等的是**该槽位下一次从“尚未观察到有人”变为“观察到有人”**，不保证一定就在紧接着的一句。presence 扫描把上次 `null/false`、本次 `true` 都算到场；持续非空状态下的人物替换不算新的到场。条目不绑定指定人物，也不要求来源场景身份与消费时场景身份相等。

`SlotPendingStore.DefaultExpiryWindowCount=16`；过期条件为 `currentWindowSequence - CreatedWindowSequence > 16`，即超过 16 个观察窗口而未消费时丢弃。这个计数不是 16 秒，也不是无条件等于 16 条可见台词。索引重载和相关运行状态清理会清空待入场条目。

`PlayerCommandObservationRuntime.ScanSlotPendings()` 还要求处于 `SceneCommandDispatch`、开启 `SlotPendingEnabled` 且有可用播放索引。索引未就绪时，不应把暂存成功等同于已应用。

源码：[SlotPendingStore.cs](../src/AzureArchive.VideoTools.Core/Characters/SlotPendingStore.cs)、[SlotPendingTargetPlanner.cs](../src/AzureArchive.VideoTools.Core/Characters/SlotPendingTargetPlanner.cs)、[CharacterTransformService.cs](../src/AzureArchive.VideoTools/Interop/CharacterTransformService.cs) 的 `StoreSlotPendingOnMainThread`、`ScanSlotPendingsOnMainThread`、`ApplyConsumedPending`；[PlayerCommandObservationRuntime.cs](../src/AzureArchive.VideoTools/Runtime/PlayerCommandObservationRuntime.cs) 的 `ScanSlotPendings`。

### 3.3 未保存编辑预览路径：当前 pending 只作为文档状态

`DispatchEditorPreview()` 遇到当前场景的 `SlotPending` 命令时，记录 `DEFERRED_ONLY` 与 `unsaved-slot-pending-does-not-enter-runtime-store`，然后跳过。它不会把未保存预览的 pending 放入已保存播放使用的待入场队列。

后续预览到有角色的场景时，前序链解析器能够跨过空槽场景，寻找最近的 `#charp`，将它折叠为该角色的继承起点。这条路径依赖当前有效的工程图及指令索引，不等价于在未保存预览里启用了同一份实时 pending 队列。

源码：[PlayerCommandObservationRuntime.cs](../src/AzureArchive.VideoTools/Runtime/PlayerCommandObservationRuntime.cs) 的 `DispatchEditorPreview`；[PreviewChainResolver.cs](../src/AzureArchive.VideoTools.Core/Commands/PreviewChainResolver.cs) 中的 `seekingPendingAcrossEmptyEntry` 分支。

## 4. 跨场景继承、重播与 reset

### 4.1 两套基线解决不同问题

| 数据 | 解决的问题 | 关键身份 |
| --- | --- | --- |
| `CharacterTransformBaselineStore` | 同场景相对命令重播时，从原来起点重新执行，防止位移越播越远 | 场景、物理槽位、人物标识 |
| `CharacterTransformOriginBaselineStore` | 连续多句中保留角色最初的官方状态，让 reset 不把最近一句的变换结果误当原点 | 连续谱系、槽位、人物标识、角色实例 |

原始基线允许在谱系信息尚未到达时以空谱系捕获，之后由确切谱系“认领”，保持同一组数值。普通场景切换不会自动抹掉同一角色实例的原点；角色换人、实例换新或谱系变化则重新捕获。

这里的“原始”是该活角色实例在相应谱系中首次被本服务观察、且尚未执行本次修改时保存的值；它不是从角色资源中重建一份任意时刻都可查询的官方默认姿态。场景重播基线只保存当前场景，进入另一场景时旧场景的基线会清空。

`reset` 首次出现且此前没有保存原始状态时，会捕获当前未改动状态并形成一次成功的无变化操作；如果连续谱系里已经执行过前序变换，则使用保存的原始状态。

源码：[CharacterTransformBaselineStore.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterTransformBaselineStore.cs)、[CharacterTransformOriginBaselineStore.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterTransformOriginBaselineStore.cs)、[CharacterTransformService.cs](../src/AzureArchive.VideoTools/Interop/CharacterTransformService.cs) 的 `ExecuteCommandWithOriginOnMainThread`。

### 4.2 重播只先恢复本命令控制的轴

来自播放命令的 `DispatchOnMainThread()` 调用 `ReplayCommandOnMainThread()`。`PrepareReplay()` 如果没有场景基线就捕获；已有基线则用 `PlanReplayRestore()` 瞬时恢复本条命令控制的轴，再执行原命令。

例如 `move;dx=100` 重播前只恢复 X，保留 Y 和朝向；`set;flipX=true` 重播前只恢复 Y 朝向；`reset` 视为恢复全部。这样相对命令重复播放可以得到同一目标，同时没有参与本条指令的轴不被一并写回。

恢复前同样先剥离临时预设偏移，并停止旧 Tween；原始谱系基线用于 reset 与明确翻转，场景基线用于重播准备，两者不混用。

源码：[CharacterTransformPlanner.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterTransformPlanner.cs) 的 `PlanReplayRestore`；[CharacterTransformService.cs](../src/AzureArchive.VideoTools/Interop/CharacterTransformService.cs) 的 `ReplayCommandOnMainThread`、`PrepareReplay`。

### 4.3 直接预览中间句时，从工程图折叠前序指令

`PreviewChainDirectiveIndex.Build()` 提供“场景、槽位 → 规范人物指令”的查找。`StoryGraphPredecessorResolver` 找当前场景的前驱；`PreviewChainResolver.Resolve()` 针对所需槽位反向追踪，最多 512 步，然后按时间顺序正向折叠找到的指令。

每个轴保存 `PreviewChainAxisState`：相对官方原点的累计量、是否已有绝对值、绝对值，以及 `IsControlled`。`IsControlled` 区分“明确 reset 到零偏移”与“从来没碰过这个轴”。

折叠规则：

- `set x=...` 将该轴设为绝对值，未提及的轴继续保留已有折叠结果。
- `move dx=...` 加到已有绝对值或累计相对量上。
- `set flipX=...` 保存明确翻转状态，不通过反复 toggle 叠加。
- `reset` 明确控制并恢复 X、Y、屏幕旋转及翻转；后面的命令继续在其上折叠。

停止或划分继承边界的条件包括工程开头、人物更换、角色离场后再回来、存在多个前驱的汇合节点、图循环和深度上限。

若当前角色前面是空槽，解析器会跨过空槽段寻找 `charPending`。找到后使用最近的 pending 作为入场起点；如果走到同一人物之前那次占槽而中间有空缺，则停止，避免把角色退场前的旧姿态继承给新一轮入场。

源码：[PreviewChainResolver.cs](../src/AzureArchive.VideoTools.Core/Commands/PreviewChainResolver.cs) 的 `ResolveSlot`、`Fold`、`FoldPosition`；[PreviewChainDirectiveIndex.cs](../src/AzureArchive.VideoTools.Core/Commands/PreviewChainDirectiveIndex.cs)、[StoryGraphPredecessorResolver.cs](../src/AzureArchive.VideoTools.Core/Projects/StoryGraphPredecessorResolver.cs)。

### 4.4 官方位移只截断位置继承

工程快照中的 `HasOfficialPositionTransition` 表示 AA 自己在当前场景控制人物位置。继承解析器把最近的官方位移视为 X/Y 的新边界：更早的人物位置指令不再带到后面，官方位移场景及之后的明确人物位置指令仍能形成新的位置链。

旋转和翻转的追溯不因此停止，因为它们保存在仍存活的角色朝向上。当前场景有官方位移时，较早的 X/Y 不覆盖当前官方位移，较早的旋转/翻转仍可继承。

另外，同一场景内“官方位置过渡 + 本模组位置命令”会被 `CommandTimelineCompiler.CompileBatches()` 拒绝，包括 X/Y、dx/dy 与 reset。仅旋转/翻转不算位置写入。图形编辑器也会阻止相应位置草稿及应用，并说明该冲突会使播放命令索引编译失败。

源码：[CommandTimelineCompiler.cs](../src/AzureArchive.VideoTools.Core/Commands/CommandTimelineCompiler.cs) 的 `WritesPosition`；[VisualEditorBehaviour.cs](../src/Rukari.MoreEffects/Runtime/VisualEditorBehaviour.cs) 的 `RefuseDraftByOfficialTransition`、`ApplyVerifiedDraft`。

### 4.5 重建起点保持幂等，先继承再执行当前句

`CharacterInheritedStartPlanner.Plan()` 把已折叠状态叠到当前官方产生的角色上：受控轴按绝对值或“官方原点 + 相对量”计算；不受控轴保留当前实时值；位置 Z 和局部 X 旋转不属于公开继承轴，保留现场值。

继承翻转会比较当前翻转状态与目标 `FlippedFromOfficial`，只有不一致时才加/减半周，因此多次应用同一个继承起点不会反复翻转。运行服务在真正应用前还检查 `ExpectedOccupant` 与现场人物一致。

`ApplyInheritedStartOnMainThread()` 零时长应用继承起点，随后将该实际起点捕获为当前场景重播基线；同场景同人物已存在基线时保留第一份。当前句的变换再从这个起点规划，因此已经进入执行路径的中间句预览、同句重播和连续播放使用相同的前序状态概念。这是规划与执行层的语义，不表示每次绿色重播都能通过上游授权；现有预览缓存和下游授权的代际规则差异见 6.2。

`PreviewChainApplyPolicy.ShouldApplyChain()` 对编辑预览与正式播放采用同一规则：处于 `SceneCommandDispatch` 且启用前序链时，先应用已解析的继承链。具体运行路径、场景身份和预览代际标记不同，但不会仅因正式播放模式就跳过重建。

源码：[CharacterInheritedStartPlanner.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterInheritedStartPlanner.cs)、[PreviewChainApplyPolicy.cs](../src/AzureArchive.VideoTools.Core/Commands/PreviewChainApplyPolicy.cs)、[CharacterTransformService.cs](../src/AzureArchive.VideoTools/Interop/CharacterTransformService.cs) 的 `ApplyInheritedStartOnMainThread`；[PlayerCommandObservationRuntime.cs](../src/AzureArchive.VideoTools/Runtime/PlayerCommandObservationRuntime.cs) 的 `ApplyPreviewChainSlots`、`DispatchEditorPreview`、`DispatchSceneCommands`。

## 5. 四种预设和贝塞尔时序

### 5.1 预设是临时姿态偏移，和摆放指令分别占资源

公开预设格式是 `#aavt;fx;<slot>;<preset>;...`，内部规范根为 `#fx`，家族 ID 为 `character.preset/v1`。

| 预设 | 核心动作 | 常用参数 |
| --- | --- | --- |
| `sway` 左右摇晃 | 对现有姿态加入屏幕 Z 倾斜 | `amplitude/frequency/cycles/direction` |
| `spin` 原地转身 | 对现有朝向加入 Y 轴转身 | `frequency/cycles/direction` |
| `headbutt` 头槌 | 后仰、快速前顶、回到原姿态 | `back/forward/duration/direction` |
| `squash` 弹性拉伸 | 按相反比例改变现有 X/Y 缩放 | `amplitude/frequency/cycles/direction` |

`CommandResourceIdentity` 把普通人物变换和 pending 都归入 `character:<slot>`，把预设归入 `preset:<slot>`。因此同一句可以同时有该槽位的一条摆放命令和一条预设；同一句同槽位两条预设冲突，`char` 和 `charPending` 相互也冲突。

源码：[CharacterPresetContracts.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterPresetContracts.cs)、[CharacterPresetDirectiveParser.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterPresetDirectiveParser.cs)、[CharacterPresetCommandFamilyCompiler.cs](../src/AzureArchive.VideoTools.Core/Commands/CharacterPresetCommandFamilyCompiler.cs)、[CommandResourceIdentity.cs](../src/AzureArchive.VideoTools.Core/Commands/CommandResourceIdentity.cs)。

### 5.2 按绝对经过时间采样，不累加帧位移

`CharacterPresetEvaluator.Sample(command, elapsedSeconds)` 是纯数值函数，直接从开始到现在的时间算出临时帧：屏幕倾斜、Y 转角、X/Y 比例、是否完成。参数无效时返回已完成的中性帧；非有限或负时间按初始姿态处理。

记 `f=frequency`、`t=elapsedSeconds`，循环相位为 `phase=(t×f) mod 1`。`cycles>0` 的总时长是 `cycles/f`；到达终点返回完全中性的帧。`cycles=0` 的循环没有固定时间截止，由下一次有效对白边界和运行生命周期结束。

摇晃及拉伸使用正弦波：

```text
wave = sin(2π × phase) × direction × envelope
sway.screenZ = -amplitude × wave
squash.scaleY = exp(amplitude × wave)
squash.scaleX = 1 / squash.scaleY
```

正向 `direction=right` 让摇晃的头部向画面右侧倾斜，所以屏幕 Z 使用负号。拉伸采用指数与倒数，确保乘数为正，X/Y 乘数乘积为 1；它保留人物原有缩放比例和缩放符号，而不是把人物改成统一尺寸。

`envelope` 使用 `SmoothStep(v)=v²(3-2v)`，在第一段四分之一周期淡入；有限循环在最后四分之一周期淡出。它改变起止速度，不改变选定频率、循环数或名义峰值参数。

原地转身输出 `YawDegrees=direction×turns×360`，不会输出普通人物指令的 Z 倾斜。有限转身保留整圈数；无限循环只需要当前周期相位。完成时清除临时 Y 转角，恢复作者原朝向。

头槌总时长由 `duration` 决定，分为 `0..30%` 后仰、`30..45%` 前顶、`45..100%` 恢复。各段之间的角度端点固定；默认段内插值使用 SmoothStep。

源码：[CharacterPresetEvaluator.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterPresetEvaluator.cs)。

### 5.3 贝塞尔反求时间坐标，仅替换时序

四种预设均可追加：

```text
bezier=x1,y1,x2,y2
#aavt;fx;3;spin;frequency=1;cycles=2;direction=right;bezier=0.42,0,0.58,1
```

曲线起点为 `(0,0)`，终点为 `(1,1)`，两控制点的四个坐标必须为有限的 `0..1` 数值。内置线性、缓入、缓出、缓入缓出，对应 `Linear/EaseIn/EaseOut/EaseInOut`。

对归一化时间 p，算法不是把 p 直接当贝塞尔参数 u。它先反求 `x(u)=p`，再取 `y(u)`：

```text
B(u; a, b) = 3(1-u)²ua + 3(1-u)u²b + u³
求 B(u; x1, x2) = p
结果 progress = B(u; y1, y2)
```

`CharacterPresetBezier.Evaluate()` 使用最多 56 次二分迭代，处理端点斜率为零和 X 控制点顺序相反的情况；结果限于 `0..1`，无超调。非法曲线或非有限时间返回初值，p 的起点和终点直接返回 0/1；控制点均在对角线上时可直接返回线性 p。

预设使用方式：

- 摇晃和拉伸：曲线替换每一轮正弦波的相位。
- 转身：仅替换每一圈的小数相位；已转过的完整圈数、选定频率和总循环时长保留。
- 头槌：各阶段独立套用同一曲线；三个阶段时间边界和后仰/前顶角度不变。

省略 `bezier` 时保留原始预设时序。显式 `Linear` 对循环预设相当于线性相位，但对头槌会把默认 SmoothStep 改成线性段内插值，因此“省略曲线”与“选择线性”在头槌中不是同一件事。

这个贝塞尔实现属于四种临时预设，普通 `char move/set` 仍使用 NGUI 四种缓动；当前源码没有把 `bezier=` 作为普通人物位移属性。

源码：[CharacterPresetBezier.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterPresetBezier.cs)、[CharacterPresetEvaluator.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterPresetEvaluator.cs)；界面见 [CharacterPresetBezierContent.cs](../src/Rukari.MoreEffects/Runtime/CharacterPresetBezierContent.cs)、[CharacterPresetEditorSession.cs](../src/Rukari.MoreEffects/Runtime/CharacterPresetEditorSession.cs) 的 `TryBezier`、`SetBezierPreset`、`TryDirective`。

### 5.4 相对 overlay 的帧生命周期

`CharacterPresetRuntime.Begin()` 当次解析槽位、读取姿态并记录托管参数、开始时刻及 player/character/transform 的实例 ID。长期活动记录不保存 `Character/Transform` 原生包装对象，每次回调重新解析现场。

运行顺序：

1. `Update()` 先去掉上一帧由本预设持有的临时偏移。
2. AA 自身的动画、Tween 及当前指令可继续更新作者姿态。
3. `LateUpdate()` 再次清掉本预设尚持有的上一帧内容，读取此刻基底。
4. 从绝对时间采样本帧预设。
5. `CharacterPresetPoseOverlay.Apply()` 对现有欧拉角加相对角，对现有 X/Y 缩放乘相对比例。
6. 写回实际值，再读取 Unity 归一化后的角度，以它作为所有权判定的参考。

结束时 `RemoveOwned()` 只恢复仍由本预设持有的通道。普通倾斜按 Z 通道判断；Y 转身使用整组旋转的方向等价判定，因为 Unity 会把同一朝向表示成不同的 X/Y/Z 欧拉组合。判定在托管数学中转为 quaternion 比较，容差约 `0.01°`。缩放分别判断 X/Y，Z 缩放从未被预设持有。

如果 AA 或另一写入方已明确改动某个通道，清理保留新写入作为新基底，不机械地减角或除比例。逻辑人物快照还通过 `ProjectAuthoredState()` 剥离暂时的预设旋转，避免图形草稿读取动作摆动中的随机角度。

循环自然完成、进入下一有效对白、替换动作、进入已授权重播、离开有效模式、角色/Transform 实例变化或观察运行关闭，都会触发结束或清理。`CharacterPresetWindowGate` 保存最新对白水位，较旧的排队命令不能在新对白之后重新开启已结束的循环。同一播放行没有消息且行号没变化属于 hold/no-op，不被当作新对白；预设水位允许已获授权的新重播窗口开始动作，但水位本身不负责授予重播权限。

清理写入失败时，活动记录进入 `Stopping` 并在后续回调重试；日志给出 `CLEANUP_FAILED`，不能把这个状态描述成已经恢复。演员实例变化时删除活动记录，不向新人物套用旧人物的恢复值。

源码：[CharacterPresetRuntime.cs](../src/Rukari.MoreEffects/Runtime/CharacterPresetRuntime.cs) 的 `Begin`、`Update`、`LateUpdate`、`Tick`、`StopSlot`、`RemoveOverlay`、`SuspendOverlay`；[CharacterPresetPoseOverlay.cs](../src/AzureArchive.VideoTools.Core/Characters/CharacterPresetPoseOverlay.cs) 的 `Apply`、`RemoveOwned`、`SameRotation`、`ProjectAuthoredState` 和 `CharacterPresetWindowGate`。

## 6. 指令净化、编译身份与运行派发

### 6.1 编译钩子的共享所有者是 Rukari Lib

`Rukari.Lib.Runtime.Commands.EmbeddedDirectivePatch` 在 `Script.ScriptKr`、`CompileScriptStandalone()`、`CompileScriptContinuous()` 三个 managed-string 返回边界安装统一处理。`EmbeddedDirectiveHost` 将纯托管 `EmbeddedDirectiveService` 发布为 `IEmbeddedDirectiveService`。

MoreEffects 的 `EditorEmbeddedDirectivePatch.Install()` 向共享服务登记 `#aavt`，按配置还登记旧 `#char`；该特性层自身不再安装另一套编译钩子。

共享服务提供来源文本、净化后的官方文本、编译 ID、边界类型及是否 authoritative。线程局部 `DirectiveCompilationTracker` 与 MoreEffects 的 `AavtCompilationCaptureTracker` 处理嵌套编译，避免把同一次内部捕获之后的外层干净结果误当成删除指令。

`EmbeddedAavtDirectiveExtractor.Extract()` 提取公开人物/pending/预设指令，返回规范命令、错误列表和净化文本。声明但无效的自定义指令会被从官方解析文本里移除，同时返回错误，不直接派发。MoreEffects 使用净化后编译文本的 SHA-256、长度和行数作为 `CompiledScriptIdentity`。

权威编译结果用于更新指令缓存及一次性预览 lease；顶层真正干净的编译还会生成 tombstone，以便删除旧效果，而不是让已删掉的指令一直留在缓存中。

源码：[EmbeddedDirectiveService.cs](../src/Rukari.Lib/Commands/EmbeddedDirectiveService.cs)、[EmbeddedDirectivePatch.cs](../src/Rukari.Lib.Runtime/Commands/EmbeddedDirectivePatch.cs)、[EmbeddedDirectiveHost.cs](../src/Rukari.Lib.Runtime/Commands/EmbeddedDirectiveHost.cs)、[EditorEmbeddedDirectivePatch.cs](../src/AzureArchive.VideoTools/Runtime/EditorEmbeddedDirectivePatch.cs)、[EmbeddedAavtDirectiveExtractor.cs](../src/AzureArchive.VideoTools.Core/Commands/EmbeddedAavtDirectiveExtractor.cs)。

### 6.2 解析过指令不等于发生了播放事件

已保存工程路径由 `EmbeddedProjectCommandCompiler.Compile()` 读取工程场景的额外指令、生成 timeline，再由 `CommandTimelineCompiler` 产生绑定到具体播放记录的 projection；`PlaybackCommandBinder` 核对播放文件路径身份、版本、schema、记录指纹与编译文本身份。

编译后的 AAS 如果仍有原始 `#aavt/#char` 泄漏行，嵌入命令编译器返回 `aas-record-contaminated`，不把污染记录当成已净化播放内容。

运行观察窗口负责把实际当前消息与场景/播放记录匹配。重复编译文本的场景可以通过所观察的播放行号消歧；如果身份仍无法唯一确认，不能凭文字相同就决定槽位动作属于哪个场景。

`PlaybackSceneDispatchGate.TryAuthorize()` 再检查命令 ID、规范文本、顺序、`SceneEnter` 阶段、能力 ID 和资源重复，并在真正调用派发前消费观察窗口。一窗口只授权一次，过期或重复窗口不再次执行；新的有效播放窗口可以得到新的执行机会。

未保存编辑预览使用当前选中场景、一次性预览 lease 和实时工程图，不要求先发布 AAS；队列开始写画面前还会核对权威选择。编译回调本身只捕获托管资料，不直接操作角色。

当前还有两层规则不一致：上游 `EmbeddedEditorPreviewLeaseCache.TryClaim()` 支持同一 DataList generation 的新 `windowSequence` 再次 claim，但 `PlayerCommandObservationRuntime` 随后调用的 `EditorPreviewGate.TryAuthorize()` 仍由 Core `EditorPreviewLeaseGate` 按 `SelectionGeneration` 单次消费，首次授权尝试即使失败也会消耗该代；因此同一选中代的绿色重复预览可能被下游拒绝，不能仅凭缓存支持或链规划幂等就保证完整重复预览可用。详细过程见 [04_指令编辑保存编译与播放.md](04_指令编辑保存编译与播放.md)，源码见 [EditorPreviewLeasePlanner.cs](../src/AzureArchive.VideoTools.Core/Commands/EditorPreviewLeasePlanner.cs)。

源码：[EmbeddedProjectCommandCompiler.cs](../src/AzureArchive.VideoTools.Core/Commands/EmbeddedProjectCommandCompiler.cs)、[CommandTimelineCompiler.cs](../src/AzureArchive.VideoTools.Core/Commands/CommandTimelineCompiler.cs)、[PlaybackCommandBinding.cs](../src/AzureArchive.VideoTools.Core/Commands/PlaybackCommandBinding.cs)、[PlaybackSceneDispatchGate.cs](../src/AzureArchive.VideoTools.Core/Commands/PlaybackSceneDispatchGate.cs)、[EmbeddedEditorPreviewLease.cs](../src/AzureArchive.VideoTools/Runtime/EmbeddedEditorPreviewLease.cs)、[PlayerCommandObservationRuntime.cs](../src/AzureArchive.VideoTools/Runtime/PlayerCommandObservationRuntime.cs)。

### 6.3 主线程队列的帧内顺序

`ManagedDispatchSchedule` 支持同帧 LateUpdate 及下一次 Update 两种排期，把游戏对象写入放在编译/原生回调之外。

`PlayerCommandObservationRuntime.Update/LateUpdate` 的关键顺序是：清除上一预设 overlay、收集有效窗口与预览事件、扫描空槽待入场、执行预览/播放队列、最后采样并应用预设本帧 overlay。前序链起点在当前句的命令之前恢复；LateUpdate 再排空本帧晚到的已验证事件，使可执行的零时长状态在渲染前落定。

临时预设失败在当前派发路径中会被记录后继续处理其他命令；普通变换失败和恢复失败有独立的清理/残留记录逻辑。批次授权并不等于全批次提供数据库式原子回滚。

源码：[ManagedDispatchSchedule.cs](../src/AzureArchive.VideoTools.Core/Commands/ManagedDispatchSchedule.cs)、[PlayerCommandObservationRuntime.cs](../src/AzureArchive.VideoTools/Runtime/PlayerCommandObservationRuntime.cs) 的 `Update`、`LateUpdate`、`DispatchEditorPreview`、`DispatchSceneCommands`。

## 7. 草稿、应用和撤销

### 7.1 图形拖动先生成草稿

`VisualEditorBehaviour` 持有当前槽位快照、草稿位置/旋转/翻转、当前文档快照和校验结果。拖动、微调、旋转盘及翻转控件更新这些托管草稿字段，`VisualCharacterDraftBuilder.Build()` 生成公开指令。

拖动定位生成的是 `set`。已有 `move` 会被读取并显示为“相对移动，请用指令编辑”，当前图形位置控件不会把相对命令误装成绝对草稿。已有 `set` 的未涉及轴可以保持省略；微调某一轴不会为了填充界面数字而无条件补写其他轴。

切换槽位、台词、文档版本或读取同步状态变化会清除/重读相关草稿。预设面板的 `CharacterPresetEditorSession.Read()` 同样以选择令牌和内容版本检查来源；它只在同一台词来源有效时复用图形界面的槽位选择。

源码：[VisualEditorBehaviour.cs](../src/Rukari.MoreEffects/Runtime/VisualEditorBehaviour.cs) 的 `UpdatePositionDraft`、`EnsureSetDraft`、`PublishActiveDraft`、`LoadExistingCommandForSelection`、`VerifyDraftAgainstSelected`；[VisualCharacterDraftBuilder.cs](../src/AzureArchive.VideoTools.Core/VisualEditor/VisualCharacterDraftBuilder.cs)、[CharacterPresetEditorSession.cs](../src/Rukari.MoreEffects/Runtime/CharacterPresetEditorSession.cs)。

### 7.2 以文档版本和资源键合并

`EditorCommandDocumentComposer.Read()` 解析当前额外指令文本并计算 SHA-256 版本。`PreviewUpsert()` 要求草稿恰好是一条有效资源指令，检查期望版本与现文本一致，然后按 `CommandResourceIdentity` 的资源键替换原有同资源行或追加一行。

普通人物变换/pending 共享 `character:<slot>`，所以换用 `charPending` 会替换该槽位现有变换行；预设使用 `preset:<slot>`，可和摆放行并存。其他官方文本行继续留在文档中。它不是重新生成整段官方剧本或直接改 AAP/AAS 文件。

`EditorCommandDocumentService.PreviewUpsertSelectedOnMainThread()` 还检查 `RuntimeSelectionKey`；`DirectiveOwnershipError()` 调用共享命名空间快照，发现更具体的其他注册方已接管某行时返回冲突。

源码：[EditorCommandDocumentComposer.cs](../src/AzureArchive.VideoTools.Core/Commands/EditorCommandDocumentComposer.cs)、[AavtDirectiveOwnershipPolicy.cs](../src/AzureArchive.VideoTools.Core/Commands/AavtDirectiveOwnershipPolicy.cs)、[EditorCommandDocumentService.cs](../src/Rukari.MoreEffects/Interop/EditorCommandDocumentService.cs)。

### 7.3 应用通过 Rukari Lib 共享编辑服务

当前 MoreEffects 的实际服务实现位于 `Rukari.MoreEffects/Interop/EditorCommandDocumentService.cs`，不应把 `AzureArchive.VideoTools/Interop/EditorCommandDocumentService.cs` 中保留的旧实现误认为本包正在编译的版本。

应用过程读取当前选中行，核对选择令牌和 SHA-256 版本，生成合并预览，再通过共享 `IEditorDocumentService.Replace()` 写回。Rukari Lib 的 `EditorDocumentSession` 提供就绪/主线程/忙状态检查、重新读取、令牌与版本核对和一次撤销记录。

`NativeEditorDocumentBackend.Write()` 真正走 AA 官方 UI 路径：

```text
UIInput.Set(targetText, false)
    → ScriptNodeInspector.SetAdditionalPrompt()
    → 重新解析当前选择
    → 对比当前台词身份、台词正文与 additionalPrompt 精确值
```

后台会核对当前工作台可见、没有正在重排、恰好选中一条有效行，及指令输入框/正文输入框与 Script 数据已经同步。写回失败时重新解析当前选择：如果已切换到另一句，或内容/输入框已经有新的第三方修改，就不向新上下文覆盖旧文本；仍属于原上下文时尝试恢复原文本并读回核对。

源码：[EditorDocumentSession.cs](../src/Rukari.Lib/Editor/EditorDocumentSession.cs)、[NativeEditorDocumentBackend.cs](../src/Rukari.Lib.Runtime/Editor/NativeEditorDocumentBackend.cs)、[EditorCommandDocumentService.cs](../src/Rukari.MoreEffects/Interop/EditorCommandDocumentService.cs) 的 `WriteExact`。

### 7.4 撤销是共享会话的上一次修改

`EditorDocumentSession` 保存一次 `Before/After` 记录。仅当当前上下文、台词正文以及额外指令全文仍等于该记录的 After 时，`CanUndo` 才为真。撤销恢复 Before 并再次核对写回，成功后清掉此记录。

这不是无限历史栈，也不提供 redo；图形编辑器与预设面板使用同一共享编辑会话，所以撤销针对该会话当前仍可撤销的上一次修改。内容在应用后又被改动时，会拒绝拿旧快照覆盖新内容。

图形应用完成后提示“重播本场景后生效”，撤销也主要恢复当前台词的额外指令文本，随后重新加载草稿/文档状态。角色当前画面姿态由后续播放、重播或有效清理流程处理。

源码：[EditorDocumentSession.cs](../src/Rukari.Lib/Editor/EditorDocumentSession.cs) 的 `Replace`、`Undo`、`CanUndo`；[VisualEditorBehaviour.cs](../src/Rukari.MoreEffects/Runtime/VisualEditorBehaviour.cs) 的 `ApplyVerifiedDraft`、`UndoLastApply`；[CharacterPresetEditorSession.cs](../src/Rukari.MoreEffects/Runtime/CharacterPresetEditorSession.cs) 的 `Apply`、`Undo`、`ClearPreset`。

## 8. 当前源码边界与核对方式

本章说明的是当前实现及其可见边界：

- 公开人物控制固定为五个物理槽位；没有通用动态人物实体管理器。
- 待入场变换的触发依赖到场扫描，来源场景与消费场景不必相同，也不绑定人物名。
- pending 暂存只在 `Resolve()` 成功解析到已有角色时拒绝占用；其他解析失败也会进入暂存路径。因此异常现场的“解析不到角色”不能仅凭暂存成功当作已经证明槽位确实为空。到场扫描还需有效当前场景身份才能捕获基线，缺失时该消费结果会失败。
- 未保存预览的当前 pending 不进入已保存播放队列；后续场景通过前序链恢复其作用。
- 官方位置过渡与同场景模组位置写入冲突会使命令索引编译返回错误；旋转/翻转单独处理。
- 普通旋转的有意多圈阈值是 `abs(value)>360`；普通变换的界面视图、命令数学与原生欧拉读回不是同一层表示。
- 贝塞尔参数目前只属于四种预设；普通人物 Tween 没有自定义贝塞尔属性。
- 预设固定现有根 pivot；未建立脚底 pivot 定位。代码保留 `native preset/pivot acceptance pending` 与 `footPivotVerified=false` 的说明。
- pending 能力的运行绑定说明仍带 `arrival consumption proof pending`。存在实现和托管测试，不表示每种实际游戏版本已经完成入场场景验收。
- 变换错误可以尝试回滚，预设清理错误会重试并记录；这些结果必须按返回值与日志判断。
- MoreEffects 项目通过 Compile Link 引用 `AzureArchive.VideoTools/**/*.cs`，并有显式排除列表。本目录中的 Runtime/Interop 与 API 不能只按文件夹名称判断实际编译归属；以 csproj 为准。

入口：[Rukari.MoreEffects.csproj](../src/Rukari.MoreEffects/Rukari.MoreEffects.csproj)、[Plugin.cs](../src/Rukari.MoreEffects/Plugin.cs)。MoreEffects 自有 `VisualEditorBehaviour`、`EditorCommandDocumentService` 等替换实现与被链接的公共实现，共同构成本包的真实代码。
