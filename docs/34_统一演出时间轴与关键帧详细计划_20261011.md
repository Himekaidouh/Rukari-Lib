# 统一演出时间轴与关键帧详细计划

日期：2026-10-11

## 一、目标

把人物、镜头、语音、屏幕文字和预设效果统一为一份可保存、可预览、可正式播放的演出时间轴。

时间轴不是另起一套脚本语言，也不替换 AA 的 AAP/AAS 格式。它是 Rukari 内部的规范化表示：旧的 `#aavt` 指令仍然可以读取，新的 UI 先生成结构化时间轴，再由现有编译和发布适配器生成兼容的指令表示。

最终要达到以下效果：

- 编辑器预览和正式播放使用同一套动作规划结果。
- 空对白可以承载人物初始位置和动作，并按动作时长正确等待。
- 连续台词继承上一句的最终状态，重复预览不会累计偏移。
- AUTO 等待动画、语音和额外延迟；手动点击或 Enter 可以立即推进。
- 多个对象可以并行演出，单个对象的不同属性可以按规则合并。
- FL、官方指令和 AAVT 之间有明确的所有权和冲突提示。
- 保存、编译、发布后可以重新读取并验证，而不是只凭返回成功判断。

## 二、当前基础和已知缺口

当前已经具备：

- 人物 X/Y 位移、X/Y 旋转、继承起点和部分预设动作。
- 整体镜头与仅背景镜头。
- 摇摆、Y 轴转身、头槌、挤压拉伸和贝塞尔曲线候选实现。
- 配音导入、绑定、AUTO 等待、全局音量和手动跳过。
- `PlayerActionTimelineRuntime` 对官方动画列表和等待动画的运行时桥接。
- AAP/AAS 测试夹具、命令工作区证明和诊断脚本。

当前缺口：

1. `CommandTimeline` 的正式时间点仍主要是 `SceneEnter`，不能完整表达台词前、台词中、推进和离场阶段。
2. 人物和镜头的效果仍以独立指令规划为主，尚未形成统一的并行轨道模型。
3. 保存服务执行“保存 → 编译 → 发布”，但没有对最终 AAP/AAS 做重读、资源存在性和可播放性验证。
4. 空对白动作仍有一部分依赖继续行和播放器行为，缺少统一的显式时间轴边界。
5. 多个 Mod 同时修改同一人物或镜头时，缺少公开的 owner、优先级和释放机制。
6. 差分和语音导入、切换时仍可能触发扫描或同步加载，造成卡顿。

## 三、核心数据模型

### 3.1 时间轴文档

```text
TimelineDocument
  schemaVersion
  projectId
  sceneId
  lineId
  sourceRevision
  tracks[]
  diagnostics[]
```

每个 `lineId` 对应一张台词卡或一个显式动作行。空对白也必须有独立的 `lineId`，不能因为文本为空而丢弃。

阶段 1 的关键帧是“规范化的命令事件”，其中相对移动仍保留 `dx/dy/dzoom` 和 `operation`，不会被错误地当成绝对坐标。只有在后续状态解析阶段拿到当前人物、场景和人物实例身份后，才会解析成真正的 `from/to` 状态。

### 3.2 轨道

```text
TimelineTrack
  id
  kind: character | camera | voice | text | effect | transition
  target
  layer
  ownerModId
  events[]
```

第一版只允许 Rukari 自己创建上述轨道；第三方 Mod 的注册接口在时间轴内部稳定后再开放。

### 3.3 事件和关键帧

```text
TimelineEvent
  id
  startMs
  durationMs
  from
  to
  easing
  curve
  waitPolicy
  loopPolicy
  layer
  ownerModId
```

`from` 有三种来源：

- `inherit`：继承上一句同一对象的提交状态。
- `default`：新人物或没有可用继承状态时使用官方默认槽位。
- `explicit`：用户明确填写的初始状态。

省略 `from` 时默认使用 `inherit`。新人物没有上一状态时自动降级为 `default`，并在诊断信息中标明原因。

### 3.4 等待策略

```text
waitPolicy: none | auto | action | voice | all
```

- `none`：动作执行但不阻塞对白推进。
- `auto`：仅 AUTO 模式等待。
- `action`：等待动作完成。
- `voice`：等待语音完成及全局语音延迟。
- `all`：等待动作、语音和转场全部完成。

手动点击、Enter、数字键推进时，只解除等待门，不删除已经写入的最终状态。

## 四、统一生命周期

所有轨道必须遵循以下生命周期：

1. **Parse**：从当前台词和工程上下文读取 AAVT/官方相关数据。
2. **Validate**：检查槽位、资源、时间、曲线、图层和 owner 冲突。
3. **Stage**：生成当前句的暂存状态，不修改上一句已提交状态。
4. **Play**：在预览或正式播放中执行同一份事件计划。
5. **Complete**：确认动作、语音和转场完成或被合法跳过。
6. **Commit**：将最终状态提交为下一句的继承基准。
7. **Release**：释放音频、动画、对象和 owner 令牌。

预览适配器只能提供选句、重播和编辑输入；正式播放只能消费已经保存、编译、发布并通过验证的工程数据。

## 五、分阶段实施

### 阶段 0：冻结现状和建立基线

目标：在改时间轴前确定旧工程和旧指令不能被破坏。

工作项：

- 固定 AA 1.0、1.01、fix6、1.0beta 的测试矩阵。
- 为每个版本生成一套 AAP/AAS/命令工作区夹具。
- 记录旧 `#aavt` 指令的解析结果和规范化结果。
- 保存现有稳定用户包的 DLL、配置、版本号和 SHA256。
- 把光照、完整 3D、Spine 叠加台和实验 UI 保持在归档路径，不进入时间轴首版。

出口条件：旧工程可以打开；旧人物、镜头和配音测试全部有可重复的基线记录。

### 阶段 1：实现时间轴 IR

目标：先建立纯托管的结构化模型，不接新 UI。

工作项：

- 新增 `TimelineDocument`、`TimelineTrack`、`TimelineEvent`、`TimelineState`。
- 新增 schemaVersion 和向后兼容读取。
- 将现有人物、镜头和预设指令转换成事件和关键帧。
- 将单段 `set` 表示为起点关键帧和终点关键帧。
- 将 `duration=0` 保留为瞬时提交，而不是丢弃。
- 将 `cycles=0` 统一表示为持续到下一句或显式取消。
- 解析失败时保留原官方文本并给出诊断，不生成部分执行计划。
- 记录场景、槽位和可用的人物实例/谱系引用；只有槽位编号不能证明继承关系。

自动测试：

- 单人物、多人、空对白、非空对白。
- 瞬时动作、有限动作、循环动作。
- 缺少起点、显式起点、继承起点。
- 旧 AAVT 文本和新 IR 的双向稳定快照。

出口条件：同一输入在预览规划器和正式规划器中生成完全相同的规范化 IR；本阶段的 IR 仍不直接驱动正式播放。

### 阶段 2：状态快照和冲突所有权

目标：解决连续台词、重复重播和多 Mod 覆盖问题。

状态分三层：

```text
baseline   上一句已提交状态
staged     当前句暂存状态
committed  当前句完成后的状态
```

工作项：

- 每个槽位、镜头范围和文字对象都有稳定身份。
- 新句从 baseline 复制到 staged，再应用当前句事件。
- 重播只清理当前 owner 的 staged 状态，不重置其他 Mod 的状态。
- 完成或合法跳过后才把 staged 提交为 committed。
- FL 或官方占用同一属性时记录外部 owner，AAVT 不强行覆盖。
- 冲突时显示具体对象、属性、来源和处理结果。

出口条件：三号槽位连续两句位移、重复绿色重播、换人物、换场景、FL 共存均能保持确定性。

### 阶段 3：接入现有预览和正式播放

目标：消除“编辑器有效、正式播放失效”的分叉。

工作项：

- `EmbeddedEditorPreviewLease` 只负责提供输入和预览上下文。
- `PlayerActionTimelineRuntime` 改为消费 TimelineDocument，而不是自行重新推断动作。
- 扩展时间点：`BeforeText`、`OnEnter`、`DuringLine`、`OnAdvance`、`OnLeave`。
- 继续使用官方动画列表和等待机制，不新建替代播放器协程。
- 动作完成、语音完成和手动跳过都经过同一 CompletionGate。
- 空对白使用明确的动作事件，不依赖文本内容触发。

出口条件：

- 预览/正式播放一致。
- AUTO/手动一致。
- 空/非空对白一致。
- 冷启动/切场景一致。
- 默认/自定义存储路径一致。

### 阶段 4：保存、编译、发布后的验证闭环

目标：把“官方 API 返回成功”和“正式播放可用”区分开。

保存流程改为：

```text
保存 → 编译 → 发布 → 找到目标 AAP/AAS
     → 重新读取 → 校验工程身份和 revision
     → 解析时间轴 → 校验伴随资源
     → 写入 verified 结果
```

工作项：

- `EditorSaveReceipt` 增加 `verified`、`verifiedAap`、`verifiedAas`、`resourceCount` 和 `diagnostics`。
- 验证目标必须来自 AA 当前实际存储路径，不能猜测固定目录。
- 重新读取的工程身份、源 hash、场景和指令数量必须与本次提交一致。
- 缺失 AAS、资源路径不匹配、旧 revision 或解析失败必须明确显示。
- 保留一次“只保存不验证”的开发诊断模式，但用户按钮默认走完整流程。

出口条件：测试夹具和至少一份真实工程完成保存后重读；验证失败时不会显示“全部完成”。

### 阶段 5：关键帧编辑器

目标：在底层链路稳定后提供用户可操作的时间轴窗口。

第一版界面：

- 顶部：当前工程、场景、台词、播放/暂停/回到起点。
- 左侧：轨道列表和图层顺序。
- 中间：时间刻度、关键帧和动作区间。
- 右侧：目标属性、起点来源、终点、时长、曲线、等待策略。
- 底部：当前时间、总时长、验证状态和冲突提示。

第一版不做自由拖拽生成任意事件，只允许编辑现有动作和预设，避免 UI 产生无法保存的组合。

出口条件：修改关键帧后能实时预览；应用并保存后，重新打开仍能读回相同数据。

**宿主与数据源（2026-10-13 定）**：

- 宿主：**独立浮动窗口**，不是抽屉里的第三个页面。抽屉是模态的（同时只有一个页面、打开页面时模块条目列隐藏），而编辑关键帧时必须同时看到立绘操控页、画面与时间轴。窗口能力见 `docs/03` §5.5：`IToolWindowService.RegisterWindow`，默认贴左下停靠、标题带拖动、右下角缩放、双击标题带复位、会话内记忆位置、按下置顶。
- 轨道与段的数据源：`SlotActionQueuePlanner.PlanDirectives(row)` 的 `SlotActionQueuePlan`——**与运行时间轴同源**，不是另造一套显示模型。`Segments` 已经按 `SlotKey` 分好轨（`char:{slot}` / `camera` / `preset:{slot}`），每段带 `StartMs` / `DurationMs` / `Kind` / `Placement`，整行的 `TotalMs` 就是保持门要覆盖的时长，`OverBudget` 与 `Diagnostics` 直接进底部状态栏。
  - 之所以不采用 `PresentationTimelineBuilder` 的归一化模型：该模型目前只有它自己的校验器在用，运行时不消费它，用它渲染等于让面板显示一个与真实播放无关的投影。它可以作为将来的"模板/关键帧"层，但不能当作第一版的真值来源。
- 行的原文：`EditorCommandDocument.Commands`（含 `LineNumber`），用于段标签、冲突提示与"这一段是哪一行指令"。
- 第一版的编辑动作按下述顺序放开：选中段 → 右侧属性栏改 `at=` / `interrupt=` / 时长 / 曲线 / 等待策略 → `PreviewUpsert` 段级替换。**前置**：`EditorCommandDocumentComposer.Read` 目前强制"一份文档里同一资源只有一条指令"，替换/删除按资源键定位，所以要先把文档模型扩成"每资源有序 N 段 + 段级寻址"，否则第 2 段起无法被面板列出与替换。

### 阶段 6：整合现有预设动作和镜头

目标：把现有功能迁移为时间轴模板。

预设模板：

- 左右倾斜摇摆：角度、频率、次数、持续到下一句。
- Y 轴原地转身：角度、圈数、速度、是否归位。
- X 轴前后翻转：角度、方向、速度、是否归位。
- 头槌：后仰角度、前冲角度、后仰/前冲/回位速度。
- 挤压拉伸：X/Y 比例、周期、次数、曲线。
- 整体镜头缩放和仅背景镜头缩放。
- 淡入淡出、滑入、闪白、震动等固定转场。

每个模板只生成标准 TimelineEvent，不在运行时创建新的特殊路径。

出口条件：每个模板都通过空对白、非空对白、AUTO、手动、跳卡、换人和 FL 共存测试。

### 阶段 7：资源缓存和开发者接口

目标：降低差分、语音和切场景卡顿，并为其他 Mod 留出稳定入口。

资源登记：

```text
AssetRecord
  id
  type
  path
  hash
  size
  preloadPolicy
  ownerModId
```

工作项：

- 导入语音和差分时按 hash 去重。
- 预加载下一句所需资源，限制缓存上限并提供 LRU 释放。
- 所有资源加载记录耗时、命中、等待和失败原因。
- 文件夹扫描后台化并可取消，不在 UI 主线程全量扫描。
- 在 RukariLib 中稳定公开 `TimelineService`、`CharacterService`、`CameraService`、`AudioService` 和 `PresetService`。
- 接口包含版本号、能力协商、owner lease、取消和释放方法。

出口条件：差分浏览、切场景、语音播放的卡顿有可比较的诊断数据；第三方示例 Mod 只通过公开接口注册一条测试轨道。

## 六、测试矩阵

每个阶段都必须同时跑托管测试、AAP/AAS 夹具和实机测试。

| 维度 | 必测组合 |
|---|---|
| AA 版本 | 1.0、1.01、fix6、1.0beta |
| 播放方式 | 编辑预览、正式播放 |
| 推进方式 | AUTO、鼠标、Enter、跳卡 |
| 台词类型 | 空对白、非空对白、继续行 |
| 生命周期 | 冷启动、切场景、切卡、重复重播、重新打开工程 |
| 存储 | 默认路径、自定义路径、工程缺失、AAS 缺失 |
| Mod 组合 | Rukari 单独、FL 单独、FL 与 AAVT 同句、其他官方 Mod |
| 资源 | 无语音、单语音、重复导入、缺失资源、慢加载 |
| 动作 | 瞬时、有限、循环、取消、归位、冲突 |

每次实机测试记录：

- AA 版本和启动参数。
- Mod DLL 版本和 SHA256。
- 工程名、存储根、AAP/AAS revision。
- 当前场景、台词、槽位和 owner。
- 规范化时间轴摘要。
- 资源加载和等待耗时。
- 失败阶段：解析、暂存、派发、播放、完成、提交、发布后验证。

## 七、兼容和发布规则

- 不直接修改 AAP/AAS 二进制格式。
- 不复制其他引擎运行时，也不导入其脚本解释器。
- 保留旧 `#aavt` 指令的解析和输出格式。
- 新字段必须有 schemaVersion 和迁移策略，未知字段跳过并记录警告。
- 官方和 FL 的字段标记为外部 owner，Rukari 不强行覆盖。
- 时间轴 IR 稳定前，不公开第三方注册接口。
- 用户包仍拆为 RukariLib、更多画面效果、人物配音支持；开发诊断、测试夹具和开发者 SDK 单独打包。
- 每个 AA 版本单独构建、单独验证、单独发布，不能用一个版本的验收替代另一个版本。

## 八、暂缓内容

以下内容不进入时间轴第一版稳定路线：

- 全局光照、点光源和自定义 shader。
- 完整 3D 场景和自由相机透视。
- 战斗系统和骨骼级动作编辑。
- 改写 AA 官方脚本解释器。
- 直接接管官方选择分支和变量系统。
- 完整 NVL 播放页面重制。

条件分支、变量、Choice 和 Backlog 可以在官方保存/播放链路确认稳定后作为第二阶段扩展；它们必须建立在已经验证的状态快照之上。

## 九、最终完成标准

只有同时满足以下条件，才把“统一演出时间轴”标记为稳定功能：

1. 旧工程和旧 AAVT 指令可继续打开、保存和播放。
2. 预览和正式播放消费同一份规范化时间轴。
3. 空对白、AUTO、手动推进和语音等待有明确且可重复的行为。
4. 连续位移、旋转、镜头和预设动作正确继承并可重播。
5. 保存后 AAP/AAS 能重新读取，并显示 verified 结果。
6. FL 共存和冲突拥有明确诊断，不再静默覆盖。
7. 差分与语音资源有去重、预加载和卡顿诊断。
8. AA 1.0 和 1.01 都完成独立实机矩阵。
9. 用户包、源码、开发文档、测试夹具和回滚包来自同一构建回执。

下一步应从阶段 1 开始：先实现 Timeline IR、旧指令转换和纯托管快照测试，再接入正式播放；不要先做时间轴窗口。
