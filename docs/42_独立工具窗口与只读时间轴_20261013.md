# 独立工具窗口与只读时间轴（2026-10-13）

> **历史记录（2026-10-13 稍晚）**：本文 §3、§6.1、§6.2 描述的**只读时间轴面板已按用户决定删除**，连同 Core 的 `TimelinePanel*` / `TimelineRulerLayout` / `PresentationTimeline*` 与 MoreEffects 的 `TimelineApiSource` / `TimelineCompanion`。当前实现是"每个效果窗口一行层摘要"，见 `docs/44` §6。**窗口宿主（§1–§2、`docs/03` §5.5）没有变化**，预设效果窗口仍按本文的契约工作；本文其余部分保留为当时的工作记录与缺陷表。

## 1. 目的与范围

本轮把"通用浮动工具窗口"做成 Rukari.Lib 的能力，并把**只读时间轴面板**作为它的第一个新住户接上去。用户已明确选择：**先只读**（编辑留到 N 段文档模型落地之后），窗口形态为**独立窗口**而不是抽屉里的第三个页面。

不属于本轮范围：时间轴编辑、自由拖拽生成事件、`EditorCommandDocumentComposer` 的多段文档模型（见 §5）。

## 2. 窗口宿主

契约与规则见 `docs/03_RukariLib接口与统一UI.md` §5.5。落地文件：

| 文件 | 内容 |

| `src/Rukari.Lib.Runtime/Tools/ToolsHost.cs` | 发布 `rukari.tools.windows` 能力；窗口页出现在模块条目列，选中它**开/关窗口且不动树深度**；单条目模块的模块按钮直接开/关窗口；离开工作台隐藏、回来恢复；渲染器崩溃时窗口一并拆除。 |
| `src/Rukari.Lib.Runtime/Tools/ToolboxDrawer.cs` | 新增 `CoveredByWindow`：落点在窗口内时抽屉不动手，**含滚轮与滚动条**；正在进行的拖动不被打断。另外拖动面板时不再每帧写一行布局日志（拖动期间跳过，松手后写一行最终位置）——一次拖动会把日志刷满，而这份日志正是排查问题的依据。 |

规则要点：
- 页面 `PreferredWidth` / `PreferredHeight` 表示**内容尺寸**（与抽屉里同义），边框加在外面，再按屏幕夹取。
- **用户手动缩放之前**窗口尺寸跟随页面请求（预设页在选择器↔详情之间会改高度；时间轴按轨道数改高度）；拖过缩放角之后以用户为准。
- 位置记忆为会话级：关掉再开仍在原处，重启归默认；每次读取按当前屏幕重新夹取，换分辨率不会跑出屏幕。
- `RegisterWindow` 在注册时就把窗口建出来，建不出来即返回失败并撤掉页面，调用方退回 `RegisterHostedPage`。

测试：`ToolWindowLayoutTests` 8 项（7 项几何：内容尺寸/默认停靠/各分辨率可见/缩放边界/位置记忆与复位/窗体矩形不重叠/点包含；1 项层级归属与置顶）、`PublicContractTests` 冻结契约 1 项（窗口接口是并列接口、`RegisterWindow` 五参无可选参数、`IToolPanelContent` 仍是两个成员）。

### 2.1 指针状态机（`ToolWindowInteraction`）

宿主里最容易出错、又最看不出来的一段（拖动抓取偏移、缩放起点、双击复位、按下归属）被抽成纯逻辑 `src/Rukari.Lib/Tools/ToolWindowInteraction.cs`，宿主只做"喂一帧、照结果画"：`Handle(pointer, ownedByThisWindow, now, w, h)` 返回 `PlacementChanged / ResetRequested / CloseRequested / Ended`。归属由窗口层级表回答后传进来，默认位/记忆位由宿主 `Adopt`，所以这个类不需要屏幕、存储或页面。

`ToolWindowInteractionTests` 8 项：拖动保持抓取偏移且从不改尺寸、没移动的一按不写记忆、拖缩放角从按下点起算并从此接管尺寸、双击标题带只复位不拖动（慢速两次点击是拖动）、被上层窗口拥有的按下什么都不做、关闭键与"窗体占据自己那一按"、隐藏窗口取消未完成的手势、跟随页面尺寸与屏幕夹取。

抽出后立刻抓到三个缺陷（都在本文件记录前就已存在）：

1. **会话刚开始 0.35 秒内点标题带会被误判成双击**：`_lastTitleClick` 初值 0 与 `Time.unscaledTime` 的小值相减落在双击阈值内 → 变成"复位"。修法：先记"是否已经点过标题带"，第一次按下永远是拖动。
2. **双击复位后窗口不再跟随页面尺寸**：`_userSized` 没有被复位清掉，而"默认"本该同时包含位置与尺寸。修法：复位时把尺寸交还页面。
3. **拖动期间每帧写一行 `placement=` 日志**：一次拖动会把日志刷满。修法：手势进行中不写逐帧行，只在手势结束（位置真的变了）写一行；一次没移动的点击不再写"moved"。

## 3. 只读时间轴面板

面板本体在 `src/AzureArchive.VideoTools.Core/Commands/TimelinePanel.cs`（**Core，纯逻辑**，只实现 `IToolPanelContent` / `IToolPanelSizing` / `IToolPanelLifecycle`，一切通过 `IToolPanelSurface` 画），注册为窗口页（`rukari.moreeffects.timeline`，标题"时间轴"，图标 `card`，ownerId `Plugin.Guid + ".timeline"`）。数据访问抽成注入的 `ITimelinePanelSource`：MoreEffects 只留 30 行的 `TimelineApiSource`（读 `Plugin.Api.EditorCommandDocuments.ReadSelectedOnMainThread()` 并投影成 `TimelinePanelSnapshot`）。

把它放在 Core 的唯一理由是**可测试**：面板画什么、控件叫什么名字、点一下选中什么，都能在没有游戏时验证——而 hosted 页的错误平时只有盯着屏幕的人才会发现。`TimelinePanelTests` 7 项用纯 `ToolPanelBuilder` 当表面：分段/轨道/标签/状态、**面板显示的起点与玩家真正要用的计划一致**、点击选中并显示属性、刷新键立即重读、无台词时的诚实空状态与"同一原因只记一次"的日志、四种尺寸下控件 id 唯一且都落在面板内、以及队列不调度的行仍然报告状态。

面板本身每次**换行或换计划**会写一行 `[timeline] 工程 · 场景 n · 台词　指令 N 条 / 官方行 M · 总时长 … ms · 段 … · 轨道 …`——这是面板对"我正在显示什么"的自我陈述，用它就能把屏幕上的数字与运行时的 `queue-segment-due … startMs=…; durationMs=…` 对上，不必看屏幕。读不到台词时写 `Timeline source read unavailable: …`（同一原因只写一次）。

搬进 Core 后抓到的两个缺陷（都是用户一看就能发现的）：

1. **点击段块永远不会选中**：原写法 `surface.Area(id, bounds) && surface.WasClicked(id)` 中，`Area` 返回的是 **held**（要求按键仍按下），而 `WasClicked` 要求**已释放**，同一帧互斥、条件恒假。改为先 `Area(...)` 注册命中区（忽略返回值），再由 `WasClicked(...)` 决定。
2. **刻度标签在右端画到面板外**：最后一个刻度落在刻度尺右边缘，标签 `x + 2` 再加 46px 就超过面板宽度（渲染器不裁剪，文字会出现在窗口框外）。改为把标签位置夹在刻度尺内。

其中一项测试是**金标准**：`ThePanelMatchesARowVerifiedInTheGame` 直接用 `docs/38` §13 那张已实机验证过的卡（`camera;move;dx=200;duration=300` ＋ `camera;move;dx=60;duration=300;at=1500`，验收记录是第二段在 **+1500 ms** 落地、`durationMs=300`、整行约 **1800 ms**），断言面板的轨道数（两条相机指令共用一条屏幕轨）、`总时长 1800 ms`、两根段块的间距等于 1500 ms 在刻度尺上的映射，以及点中第二段后属性栏逐字显示 `起点 1500 ms` / `时长 300 ms` / `at=1500`。面板从此被钉在**真实运行证据**上，而不是我自己的算术。

数据路径（**与运行时间轴同源**）：
1. `Plugin.Api.EditorCommandDocuments.ReadSelectedOnMainThread()` → `EditorCommandDocumentSnapshot`（每秒最多 4 次，与预设页同频；仅在绘制时读取）。失败即清空并显示"当前台词不可用，请重新选中台词。"，不保留上一行的段块。
2. `snapshot.CanonicalDirectives` → `SlotActionQueuePlanner.PlanDirectives(...)` → `SlotActionQueuePlan`（`Segments` / `TotalMs` / `BudgetMs` / `OverBudget` / `Diagnostics`）。这与播放前 `PlayerCommandObservationRuntime.PlannedSecondsOf` 调用的是同一个函数，所以面板上的起点/时长就是游戏会用的数字。
3. 行号与槽位键来自 `new EmbeddedAavtDirectiveExtractor().Extract(snapshot.AdditionalPrompt)` 的 `Commands[i].LineNumber`。

**刻意不用编辑器文档模型**：`EditorCommandDocumentComposer.Read` 在"同一资源两条指令"时返回失败（这是立绘操控页保持 1:1 编辑规则的结果），而那正是时间轴要显示的行。提取器按作者顺序接受多条，与播放一致。

界面构成（窗口内，画布单位）：顶部一行（当前台词摘要 + 指令/官方行数 + 刷新按钮）→ 左侧轨道名（`char:{n}`→"角色 n"、`preset:{n}`→"预设 n"、`camera`→"镜头"）→ 中间刻度尺（1/2/5 梯级刻度、`总时长` 主色标、`预算 3000ms` 灰标）+ 每轨段块（选中高亮；`Collapsed` 段以禁用样式加"[折叠]"前缀；越界段标 `Clipped`）→ 右侧选中段属性（轨道/第几条指令与原文行号/起点/时长/终点/类型/授权 `at=` 或 `interrupt=`/原文）→ 底部状态（总时长、段数、轨道数、超预算与折叠段数、输入框是否与脚本同步、原文解析错误数、规划器首条诊断）。

刻度几何在 `src/AzureArchive.VideoTools.Core/Commands/TimelineRulerLayout.cs`（纯函数 + 5 项测试）：跨度下限 1000ms、时间↔像素双向映射与夹取、1/2/5 刻度梯级、段块裁剪、左右栏宽度与可见轨道数。

面板分区几何在 `src/AzureArchive.VideoTools.Core/Commands/TimelinePanelLayout.cs`（纯函数 + 6 项测试）：`Measure(width, height, trackCount)` 一次给出表头/刷新键/刻度尺/状态栏/轨道名栏/轨道区/属性栏/溢出提示的位置，加 `PreferredHeight(trackCount)`、`Lane(...)`、`LaneLabel(...)`。规则：所有区域都落在面板内且不重叠；刻度尺至少保留 60px，被挤时**先让出属性栏、再让出轨道名栏**；属性栏只在面板宽于 900px 时出现；轨道区从状态栏之上开始。测试覆盖 6 种面板尺寸 × 5 种轨道数、极端输入（0/负数/NaN）、以及"多出来的轨道要报告而不是消失"。

抽出后立刻抓到一个缺陷：**轨道区从面板原点（y=0）起算**，短窗口上会压到底部状态栏——旧的内联代码靠"从刻度尺往下逐行排"侥幸没露出来，改成区域后一测即现。已修（轨道区从 `状态栏高度 + 间距` 起算）。

## 5. 对抗性审查与修复（2026-10-13）

一轮"新鲜眼睛"的只读审查按"卡死的手势 / 永久捕获 / 输入区域与绘制不一致 / 坐标空间 / 控件 id 重复 / 生命周期泄漏 / 文档与代码不一致 / 每帧抛异常"八类清单过了一遍新增代码，报回 11 条。全部已修，其中 6 条配了离线回归测试：

| # | 级别 | 缺陷 | 修法 |
|---|---|---|---|
| 1 | 高 | 刷新键在同一帧里替换了行：区域是按**旧**轨道数量的，随后用旧数量去索引新列表 → 越界异常（而异常会让页面被隔离，见 #2） | 按下刷新后**重新量一次**区域，并把循环上界夹到 `min(可见轨数, 轨道数)` |
| 2 | 高 | 页面异常一次就永久失效：共享守卫按"注册身份"隔离失败页，而窗口每次都传同一个 `this`；横幅还劝用户"关闭窗口"——关掉再开没用 | 每次打开窗口传一个**新的注册身份**（`_showing = new object()`），与守卫既有且已被测试覆盖的"显式关闭并返回允许重试一次"语义一致 |
| 3 | 中 | `ResetPlacement` 只清记忆，不通知活着的窗口：`_placementResolved` 一次置位不再清，`_userSized` 也不动 → 文档承诺的复位对已存在的窗口无效 | 新增 `ToolPanelWindow.ResetPlacement()`（取消手势、交还尺寸、下一帧重新解析），服务侧调用它 |
| 4 | 中 | `CoveredByWindow` 让步分支早退，跳过了按键记账：被窗口吞掉的抬起会留下陈旧的 `_pressedKey`，之后可能触发错误的抽屉动作 | 让步时**清掉**自己的按下状态（`_pressedKey`/`_hostedPressed`）而不是原样保留 |
| 5 | 中 | 同一帧内释放 lease 再注册同一个 windowId 会失败：旧宿主还占着该 id 的输入区域键 | 注册前先拆掉同 id 的旧宿主 |
| 6 | 中低 | 面板过矮时仍会画半条轨道，压在底部状态栏上（最小窗口可达） | 容量改为"整条装不下就是 0"，改成报告"还有 N 条放不下"；删除 `TimelineRulerLayout.VisibleTrackCount`（规则唯一化到 `TimelinePanelLayout.TrackCapacity`） |
| 7 | 中低 | `TimelineBar.Clipped` 算出来没人用 | 越界段标签追加省略号。**说明**：在"显示整行"的跨度规则下，只有超过 1000 秒上限才会触发，属于防御性标记 |
| 8 | 低中 | 排序序号只到 +8，却允许 16 个窗口 → 10 个以上时"画在上面的"与"接到按下的"可能不是同一个 | 窗口注册上限设为 10（与序号区间一一对应），超限返回 Busy；文档记明这是绘制限制不是随意限制 |
| 9 | 低 | 页面不声明宽度时跳过 68% 默认上限（1024 屏上开出 73%） | 上限对所有页面生效 |
| 10 | 低 | 每帧稳态垃圾：`elements.ToArray()`（`as` 永远不匹配）、每帧拼两个诊断字符串 | 直接持有上一帧的列表引用（构建器当帧后即弃，不会改写）；诊断改为每 15 帧检查一次、拖动期间不检查 |
| 11 | 低 | `TimelinePanel._overBudget` 只写不读 | 删除死状态 |

审查同时逐项确认**没有**发现问题的部分：捕获永不释放（所有跳过 `HandleChrome` 的路径都经 `Hide`/`Dispose`，区域被释放，即使捕获残留也冻不住游戏鼠标）、键盘所有权平衡、`OnShown`/`OnHidden` 成对、三种坐标空间一致、控件 id 在列举的所有组合下唯一、无处无界增长、纯函数对 0/负数/NaN 全域有定义。

顺带修掉一个审查没覆盖的**跨界面干扰**：输入法组合（IME）在 Unity 里是全局开关，抽屉与窗口原先各自直写它——抽屉一次陈旧的 `SetIme(false)` 会把窗口输入框的输入法关掉，谁赢取决于当帧谁后跑。现在改为各表面只向共享输入服务**申报意愿**（`ToolCompositionState` + `ToolInputService.SetComposition`），"只要还有 owner 要就保持开启"，与顺序无关；新增 3 项纯逻辑测试。

**换算唯一化与跨组件集成测试**（本轮收尾）：窗口里"物理像素 ↔ 页面坐标"的三处换算（内容指针、控件落位、命中用屏幕矩形）抽到 `ToolWindowFrame`（纯函数，宿主与测试用同一份代码）——最初正是这里把内边距算了两遍，导致一个页面的控件整体偏移且点不中。同时新增一项**跨组件集成测试**：把窗口放在三个不同位置，用 `ToolWindowFrame.ScreenPoint` 算出"看着落在这根段块上"的屏幕点、再经 `ContentPointer` 回到页面坐标，断言它仍命中同一段，并且在拖动之后的那个位置上点击真的选中该段——这条正是用户能感觉到的"点了没反应"的那类缺陷，现在离线可测。

用户第一次实机测试后给出四条反馈，全部已改：

| 反馈 | 根因 | 修法 |
|---|---|---|
| 「时间轴的排版很糟糕」 | 三处重叠：① 刻度尺里"跨度读数"与"刻度标签"用了同一段像素（28px 内各自从偏移摆放，必然叠字）；② 状态行不截断，读不到台词时的长错误串横向溢出；③ 属性栏按固定偏移往下画，面板一矮就画到栏外/面板外 | 刻度尺加高到 34 并拆成**三条互不重叠的带**（读数/刻度线/标签，`TimelinePanelLayout.RulerBands` + 测试）；状态行按宽度截断（全文仍进日志）；属性栏改成"装不下就不画"的逐行排布 |
| 「当前台词不可用：…declares more than one directive for public slot 0」 | 面板读的是**编辑器命令文档模型**（`ReadSelectedOnMainThread`），它按设计拒绝"同一资源多条指令"——正是时间轴要显示的那种行 | 改读**共享编辑事务的原文**（`IEditorDocumentService.ReadSelection()`）+ 提取器解析：提取器按作者顺序接受同资源多条，与播放一致。快照随之改为 `(RowLabel, DialogueText, AdditionalPrompt, CanonicalDirectives, OfficialLineCount, AavtLineCount, Notice)`；行标识用事务上下文里的行序号（`台词 #n`），读不到就说读不到，不再声称知道"输入框是否与脚本同步" |
| 「打开预设效果/时间轴后，扩展工具的小窗不关闭，会有多个窗口叠加」 | 开窗口页时我刻意保留了树层级，于是入口卡与入口列留在屏幕上压在窗口之上 | 窗口页的入口一按就**收起一层**（卡与入口列一起消失），窗口成为唯一的工具界面 |
| 「不应该添加缩放功能，先把目前情况搞定，已经可以拖动了」 | —— | 窗口**不再画缩放把手**，交互机以 `resizable: false` 构造：把手既不是窗体占据区也不会启动缩放（否则会留下一个看不见的 24×24 热区偷走页面点击）。缩放的纯逻辑与测试保留，翻转构造参数即可重新提供 |
| 「时间轴面板应该自动在支持时间轴的面板打开后打开」 | 需要点两次（进编辑器页 + 点时间轴图标） | `VisualEditorHostedContent.OnShown/OnHidden` 打开/关闭时间轴窗口（`TimelineCompanion`，MoreEffects 本地逻辑，只调用公开的 `IToolWindowService`）。每次显示只请求一次：用户手动关掉它，它保持关闭 |

这一轮还顺手让面板的**默认高度覆盖属性栏**（`TimelinePanelLayout.DetailHeight`）：原来 0–4 条轨道时面板只按轨道数要高度，选中段后的那几行数字要等用户把窗口拉高才看得到。

### 6.1 改成剪辑时间轴的形态（同日第二次反馈）

用户反馈"最好做成 PR 那种形式，现在很不明显也很奇怪"，于是面板重新排版成**剪辑软件式时间轴**，并用测试把新结构钉住：

- **从上到下**：工具栏（行标识 + `光标 x.xx s` 读数 + 刷新）→ 信息行（选中片段的数字，一行）→ 刻度尺（跨越轨道区，刻度线与秒标签分带）→ **轨道头列 + 轨道行**（每行左侧是轨道名与段数，右侧是片段，行间有分隔线）→ 底部状态行。
- **去掉右侧属性栏**：PR 的数字在"效果控件"面板里，不占时间轴宽度；本面板把选中片段的数字放进**信息行**，把省下的宽度全部给时间轴（默认宽 1400，窗口上限仍受 68% 屏幕规则约束）。
- **片段更明显**：轨道高 40（原 34），片段有 6px 最小宽度（原来 3px 会细成一根线）、内缩 4px 不与邻轨相接、选中高亮、`Collapsed` 段用禁用样式并带 `[折叠]`。
- **没有播放头**（如实说明）：PR 的播放头显示"正在播放到哪"，本面板没有播放时钟，所以工具栏显示的是**指针处的时间**而不是编造一个位置。真正的播放头要等"已发布的播放时钟"这个能力（§6.3）。

重排过程中测试抓到两个真缺陷：① 信息行原先画在片段**之前**，于是点击选中后要等下一帧才显示数字（现在画在片段之后）；② 刻度线与"总时长/预算"标记在右边缘会画出面板 1px（现在夹在尺内）。另外面板空状态下的默认高度也一并修正为"工具栏+信息行+刻度尺+状态行+至少一条轨道"。

### 6.2 编辑的前置：N 段文档模型（等用户拍板）

现状与原因：

- 提取器 `EmbeddedAavtDirectiveExtractor.Extract` 按**作者顺序**接受同一资源的多条指令（播放与时间轴都用它），所以"一行多段"在数据层是合法的。
- 但 `EditorCommandDocumentComposer.Read`（`:82-91`）对"同一资源多于一条"直接返回失败，注释写明这是**立绘操控页保持"一资源一指令"编辑规则**的结果；`PreviewUpsert` / `PreviewRemove` 也按**资源键**定位，因此第 2 段起无法被替换或删除。
- 结论：面板第一版只读是当前唯一诚实的形态（已交付）。

若要把编辑接上，三个选项（用户上一轮已选"先只读"，此处保留待决）：

| 选项 | 改动 | 代价 |
|---|---|---|
| B. 扩成"每资源有序 N 段 + 段级寻址" | `EditorCommandDocument` 的文档模型与 `PreviewUpsert`/`PreviewRemove` 增加段标识（如行号或序号）；面板右侧属性栏可改选中段的 `at=` / `interrupt=` / 时长 / 曲线 / 等待策略 | 必须同时定义：立绘操控页的"应用草稿"遇到多段资源时是替换第一段、替换整条资源、还是拒绝并提示。**建议拒绝并提示**，保持它现有的 1:1 语义不动，多段编辑交给时间轴面板 |
| C. 面板只允许改该资源的第一条指令 | 不改文档模型，只加一层"选中的段必须是该资源第一条"的限制 | 手写出来的第 2 段起在面板里永远只读，与作者的实际写法脱节 |

无论 B/C，写入都必须走既有的共享事务（`IEditorDocumentService` 的 token + revision 核对 + 共享撤销），并保留 `docs/38` 里已实机验证过的排队语义。

#### 6.2.1 选项 B 的实现草图（供拍板，尚未开工）

**Core 侧（纯逻辑，全部可离线测试）**

1. 文档模型：`EditorCommandDocument.Commands` 保持有序；为"第几条指令"提供稳定标识。最稳的标识是**资源键 + 该资源内的出现序号**（如 `char:3#1`），因为行号会随文档编辑漂移，而作者顺序不会：
   - `EditorCommandDocumentComposer.SegmentKey(int directiveIndex)`（或在一个小记录 `EditorCommandSegment(string Key, int DirectiveIndex, string ResourceKey, int OrdinalInResource)` 上表达）。
2. `Read` 的 1:1 规则改成**可选**：新增 `ReadAll(text, acceptLegacyCharAlias)` 返回多段文档；现有 `Read` 语义与报错文本**一字不改**，立绘操控页继续用它（等于把 1:1 规则留在编辑器页，而不是留在文档层）。
3. `PreviewUpsert` / `PreviewRemove` 增加**段级重载**：`(sourceText, expectedRevisionSha256, segmentKey, directive, …)`。旧重载（按资源键）签名与行为不变，配音与既有页面不受影响。
4. 重载的内部规则：段不存在 → 失败并说明；段存在 → 只替换该段那一行，其余行逐字保留；不新增"生成新段"的能力（第一版仍不允许自由拖拽造事件，见 docs/34 阶段 5）。

**面板侧（`TimelinePanel`，仍然纯逻辑）**

右侧属性栏从只读文本变成可编辑控件：选中段后显示 `起点来源`（继承/默认/显式）、`终点`、`时长`、`曲线`、`等待策略` 与 `at=`/`interrupt=` 的取值；底部增加 `应用`（主操作）与 `撤销`（共享撤销）两个按钮，以及"草稿与来源不一致"的提示行。规则：

- 只有**选中了一段**且**当前行可编辑**（`InputAvailable && InputMatchesScript`）时按钮才可用；这与预设页的启用条件同源。
- 应用＝用 `displayed.RevisionSha256` + 当前 `SelectionToken` 走"预览 → 校验 → 应用"三步，失败不写盘、并把原因放进状态行（与预设页同一套守卫）。
- 应用成功后重新读取并**保持选中同一段**（用段键定位，不用序号），避免"应用一次跳一段"。
- 面板不自己拼字符串：`at=`/`interrupt=`/时长/曲线都通过 Core 的族编译器生成规范指令（`Describe` 的反向），保证与手写文本逐字一致。

**测试清单（全部无需游戏）**

- 段键稳定性：插入/删除另一条指令后，同一段的键不变。
- 段级替换只动目标行：其余行（含换行风格、空行、外来命名空间）逐字保留。
- 多段预览 → 应用 → 重新读取，段数与起点时长不变（往返一致）。
- 拒绝路径：段键不存在、revision 过期、token 过期、`InputMatchesScript=false`、`at` 与 `interrupt` 同写 —— 每条都必须不写盘并给出可读原因。
- 面板：编辑态只在选中且可编辑时出现；应用后选中不跳段；撤销后回到来源。

### 6.3 播放进度（后一阶段，需要新能力）

docs/34 阶段 5 顶部要求"播放/暂停/回到起点"、底部要求"当前时间"。这需要一个**已发布的播放时钟**，而且预览与播放两条路径语义不同（预览用实时场景图、播放要求 `index-load status=READY`）。这是新增能力而不是面板内部的事，需要用户决定是否要做、以及时间轴显示的是"计划时间"还是"正在播放的时间"。
