相对上一个发布版（Rukari Lib 0.4.2、更多的画面效果 1.4.1、人物配音支持 1.6.4），本批包含两轮更新。

### 新增功能

- **整行排成一条队列**：在台词卡的额外指令里加 `#aavt;queue`，这一行的效果按书写顺序一段接一段播放；不加就是各层同时开始。画面编辑器里有开关。
- **效果按层排**：人物、镜头、预设各成一层，层内按顺序播放，不同层同时开始。人物与镜头在画面编辑器对应模式里编辑，预设效果改为独立窗口。
- **效果就地修改**：人物、镜头、预设都有「载入第 k 段」与「替换第 k 段」，改一段不用删掉重加，位置不变。
- **同一人物或镜头的多个动作按顺序执行**：同一句里写多段动作，以前后面的会覆盖前面的，现在按书写顺序依次播放。
- **同一句设置人物起点与终点**：新增「初始位置 A」「目标位置 B」和「取消指定起点」，人物先定位到 A，再按设定时长与缓动移动到 B；只设 A 时立即定位。
- **有限动作完成后自动推进**：人物位移、旋转、镜头动画及设定了次数或时长的预设动作接入 AA 动画等待；多个动作并行时等最后完成的一个；「直到下一句」的循环不造成无限等待。
- **空台词卡也能触发效果**：只有效果、没有正文的台词卡现在会正常触发。
- **配音可以手动跳过**：点击对话区域或按 Enter 即可跳过配音及结束后的等待，AUTO 仍等待语音播完；跳过只作用于对话操作。

### 问题修复

- 一行里写两条相同的指令，会让整个工程的所有效果失效（`＋ 加为下一段` 连按两次就会触发）。
- 队列总时长上限 3 秒 → 10 秒。
- 正式播放时动作「只有结果、没有过程」（位移从 1 直接到 4，中间被跳过）。
- 带效果的行在编辑器里点绿色预览按钮不生效。
- 部分工程里扩展指令动作在播放模式不显现（`#wait` 短于动作时长、空白 Script 节点、有内容但未被上下文连接的节点）。
- 同一次推进收到重复回调时，指令可能重复执行、预设动作可能提前停止。
- 人物模式的层编辑器压住旧控件。
- `＋ 加为下一段` 在人物模式点不动。
- 切换镜头范围（整体 / 仅背景）后，上移或删除可能作用到另一层。
- 工具箱：打开独立窗口时，工具列一起收起。

## 已知问题（留待下一版）

编辑器预览的租约配额对**人物与预设仍按"指令条数"计数**（每种 5 条），只有镜头是按资源计数的（[EditorPreviewLeasePlanner.cs](../src/AzureArchive.VideoTools.Core/Commands/EditorPreviewLeasePlanner.cs) 的 `ValidateCommands`）。一行里写超过 5 条人物指令时，整个预览会被拒绝：日志是 `EDITOR_PREVIEW_LEASE_REJECTED … action=NO_OP`，界面上不会出现效果，也没有提示。本次验收里有两行命中：

    #aavt;queue
    char;1 set / char;1 move / char;3 set / char;3 move / char;5 set / char;5 move   ← 6 条指令，其实只占 3 个槽
    camera ×2 + fx ×3

    char;1 set / char;2 set / char;3 set / char;4 set / char;5 set / char;1 move     ← 6 条指令，占 5 个槽

层里现在可以放多段效果，人物 / 预设的这条旧配额因此会与「载入第 k 段」「替换第 k 段」冲突。修法是照镜头那样改成按资源计数、上限保持 5 个槽 / 5 个预设。本批按用户决定不修，留到下一版（1.6.7），并在更新日志中作为已修问题记录。正式播放走的是另一条链路，本批没有正式播放记录，因此这条限制对正式播放的影响未验证。
