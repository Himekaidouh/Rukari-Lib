# 构建与验证

## 环境

PowerShell 7、支持 net6.0 的 .NET SDK 和 .NET 6 Runtime。基线使用 SDK 7.0.403。完整游戏适配编译还需自己的 AA 1.0、BepInEx/core 与 BepInEx/interop。官方 DLL 不随仓库分发。

## 入口

在仓库根运行：

    pwsh -File src/build.ps1 -CoreOnly
    pwsh -File src/build.ps1 -GameRoot 'C:\Games\AzureArchive'

CoreOnly 构建并运行四套纯托管测试，不加载 Unity。完整构建另外编译四个稳定产品与四个示例，并检查四个产品的依赖。默认 Release，支持 -Configuration Debug 和 -SkipTests；跳过测试不得视为验证通过。

默认 `-Target Release10` 对应正式版适配；`-Target Preview10` 保留旧基线。两者沿用现有编译分支，本轮不以改名推断接口兼容性。SchemaVersion 2 构建回执记录目标目录及游戏、interop、模组加载器等输入哈希。

期望测试：Core 396、Lib 136、Voice 53、Spine 26，共 611。实际结果以本次命令输出为准。构建生成的 artifacts 回执不提交到 Git；Native=not-run 表示未做游戏内验证。

构建入口不复制文件到游戏、不改 Profile、不启动或关闭游戏。跨 AA 版本必须重新编译并进行游戏内验收。所有共享依赖须同批打包，不能仅替换单个旧消费者 DLL。

## 用户安装包（三个独立 ZIP）

    pwsh -File src/scripts/New-UserPackages.ps1 -OutputDirectory 'C:\Builds\Rukari-AA10-User'

这是本轮面向用户的交付入口，生成 RukariLib、更多的画面效果、人物配音支持三个独立 ZIP。两个功能包均依赖同批 Lib，只有 Lib 携带共享图集。输出目录仅有三个 ZIP，每个内含该模组的 `mods/模组名/版本/` 与一份简短安装说明；不附源代码、开发工具、配置、工程、音频、构建回执或 Spine 包。

该脚本调用下述完整打包验证，检查当前源码、构建、正式版输入和依赖，再从明确清单选取三个模组。生成后逐项读取 ZIP 内文件并核对哈希。构建暂存、校验记录放在 `src/artifacts/user-packages`，与用户交付目录分开。安装说明模板放在 `src/packaging/user`。尚未完成游戏内验收，ZIP 标记为 test，不创建稳定版标签或 GitHub Release。

## 完整四包候选（内部验证）

    pwsh -File src/scripts/New-ModPackages.ps1 -OutputDirectory 'C:\Builds\Rukari-AA10-Candidate' -Zip

输出目录必须不存在或为空。脚本要求完整 Release10 构建与测试通过，重新核对源码清单、游戏输入、四包依赖和 UI 素材校验，再按明确清单复制 7 个 DLL、四份 manifest、图标及许可。Lib 是唯一共享库与基础 UI 素材提供者；没有官方程序集、PDB、半成品字幕或实验叠加台。用户 ZIP 只带 mods 和短说明，含本机路径的构建回执留在外部。打包不安装、不切换配置、不启动游戏。

## 来源

provenance/original-source-files.json 保存稳定输入的原始 SHA256。所有生产 C# 与项目文件来自通过验证的 2026-09-29 贝塞尔基线。初始仓库整理未改插件行为、版本或公共 ABI。后续发布前清理的路径和测试依赖调整见第八篇审查文档；原始哈希仍用于记录来源，不代表之后每份文件保持逐字节相同。

共享 UI 放在 src/assets/rukari-lib/ui，仅 Lib 携带。构建入口校验其哈希，素材许可见同目录 NOTICE.md。不要将游戏 DLL、自己的工程、语音、本地日志或凭据提交到 Git。
