# 编辑器预览身份别名修复

日期：2026-10-13  
适用版本：AA 1.01，`E:\AA1.01`  
证据日志：`player-command-observation-20261013-003004.log`（用户 2026-10-13 00:30–00:31 操作）

## 1. 现象

在编辑器里选中任意带 `#aavt` 效果的行，单击绿色预览按钮，效果不出现。诊断日志里预览租约几乎全是拒绝：

```text
editor-preview-lease event=BIND; generation=N; scriptSha16=; commands=0;
reason=ambiguous-or-missing-window-intersection; intersections=0;
windowIdentities=1; selectionIdentityInWindow=True; candidates=1; duplicateWindowIdentities=0
```

值得注意的三点：窗口只带 **1** 个身份；这个身份**就是当前选中脚本自己的身份**；这一代只有 **1** 个候选。三者都不矛盾，却仍被判为“歧义”。

## 2. 排查过程

先排除了 `STALE_WINDOW`：

```text
event=STALE_WINDOW; generation=2; sequence=2; minimumWindowSequenceExclusive=4
event=STALE_WINDOW; generation=2; sequence=3; minimumWindowSequenceExclusive=4
event=STALE_WINDOW; generation=2; sequence=4; minimumWindowSequenceExclusive=4
```

被拒窗口的序号确实**小于等于**代际水位，它们是本次点击之前就已经关闭的兄弟窗口；真正属于本次点击的窗口序号更高（`activeWindow=5`），并且确实进入了匹配（才有后面的 BIND 行）。第 6 代甚至一条 `STALE_WINDOW` 都没有，照样能绑定成功。所以“水位差一”是误判，`STALE_WINDOW` 是设计行为。

把 17 个代际的内部身份（`CompileScriptContinuous` 边界，即 `CACHE_PUT`）与包装层身份（`ScriptKr` 边界，即 `CACHE_REMOVE_STALE`）对齐后，相关性是 17/17：

| 代际 | 内层身份 | 包装层身份 | 绑定结果 |
| --- | --- | --- | --- |
| 2、3、7、8、9、11、12、13、15、16 | `903AED712E77CDE5` | `D0C43EF3856D2684` | **拒绝** |
| 10 | `63FC11CD279355B7` | 与内层相同（无包装层行） | 通过 |
| 4、5、6、14、17 | 无内层行（无 `#aavt` 行） | `CE35BCD1…` / `47EDEFAA…` | 通过 |

规则非常清楚：**内层身份与包装层身份不一致时必被拒绝，一致时必通过。**

## 3. 根因

1. 嵌入式指令的捕获发生在**内层** `CompileScriptContinuous` 边界，候选以该边界的最终官方文本身份为键。
2. 编辑器选中事件与托管 Unity 日志（`ManagedUnityLogSelectionProbe` 取 DataList 之后第一条 Unity 消息）携带的是**外层** `ScriptKr` 包装层的最终官方文本身份。
3. 只要包装层又改动了文本（本次样本里每一行 `#aavt` 都改动了），两个身份就不同，于是：
   - 窗口身份与候选集合交集为 0 → `matched == null` → `ambiguous-or-missing-window-intersection`；
   - 即使强行匹配上，预览门也会因为 `SameSelection` 与 `exactMessages != 1` 拒绝（`EditorPreviewLeasePlanner.cs:254`），因为租约携带的身份必须等于引擎实际报告的身份。

所以这不是一个“容错不够”的问题，而是**候选键用错了身份**。

## 4. 修改

新增身份别名：把“引擎报告的身份”指向“捕获实际使用的身份”，只在有证据时连边，且只在能落到真实候选上时才生效。

- `src/AzureArchive.VideoTools.Core/Commands/EditorPreviewIdentityAliases.cs`（新增）
  - `EditorPreviewIdentityAliasMap`：有向边集合，`Add` 拒绝自环与空目标，同一报告身份保留最新边；`Resolve` 有界遍历（`MaximumDepth = 4`），只有目标身份**确实存在于本代候选集合**时才返回，因此环形边不会自旋，描述不实的边不会生效。
- `src/AzureArchive.VideoTools.Core/Commands/EmbeddedDirectiveCompilationTracker.cs`
  - `EmbeddedDirectiveCompilationCapture.PreviousAavtIdentitySha256`：同一次编译（`CompilationId` 在嵌套边界间共享）中最近一次带 AAVT 指令的捕获身份。外层边界就是靠它找回自己的捕获。
- `src/AzureArchive.VideoTools/Runtime/EditorEmbeddedDirectivePatch.cs`
  - 包装层边界（`ClearStaleEntryIfDeleted`）登记 `包装层身份 → 内层身份`；
  - 空对白 `#wait;1` 锚点（`AnchorOfficialScriptPostfix`）登记 `锚定后身份 → 锚定前身份`，让“完全空对白”也能找回自己的候选。
- `src/AzureArchive.VideoTools/Runtime/EmbeddedEditorPreviewLease.cs`
  - `PreviewGeneration.IdentityAliases`；`TryClaim` 与 `CommitAuthorizedOverlay` 都通过 `TryResolveCandidateKey` 解析候选键；
  - 租约、`IsCurrent`、预览门携带的仍是**引擎报告的身份**，所以 `SameSelection` 与 `exactMessages == 1` 现在成立；
  - 拒绝行补充 `aliasEdges`、`windowShas`、`candidateShas`，下一次日志可以直接看出别名是否命中。

### 安全性

- 别名只在“报告身份完全相等 **且** 目标身份是本代真实候选”时被跟随；描述不实的边不会带来任何行为变化，失败方向仍是拒绝。
- 不新增候选、不改指令内容、不改官方文本、不改 `CompiledScriptIdentity` 的计算方式。
- 拒绝时不再消耗代际（原有行为），被拒绝的窗口仍会留下完整诊断。

## 7. 实机验收（待用户执行）

1. 由用户本人启动 AA，打开测试工程。
2. 在编辑器里选中一条带 `#aavt` 效果的行，单击绿色预览：效果应当出现。
3. 连点绿色预览多次：不叠加、不跳槽。
4. 选中一条没有任何 `#aavt` 的行：行为与修复前一致（这条本来就正常）。
5. 选一条“完全空对白 + 仅附加指令”的行：预览应当出现；这条依赖锚点别名。
6. 查看最新 `player-command-observation-*.log`，应出现：

```text
editor-preview-lease event=ALIAS; generation=N; reported=…; captured=…; source=ScriptKr
editor-preview-lease event=BIND; … accepted=True
```

如果仍然出现 `ambiguous-or-missing-window-intersection`，新加的 `aliasEdges`、`windowShas`、`candidateShas` 会直接说明是别名没登记、还是别名目标对不上候选。
