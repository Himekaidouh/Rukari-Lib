# 2026.10.14 更新日志

本次更新把「叠加式效果模型」做完：效果按**层**组织、一层一个窗口负责、整行可以按**一条队列**播放，层内效果可以**就地载入并替换**。另外修掉一个会让**整个工程的所有效果**失效的问题。

## 更多的画面效果 1.6.6

### 效果现在按「层」组织

一个界面负责一层：画面编辑器的**镜头模式**负责镜头那一层（整体与背景各一层）、**人物模式**负责当前选中角色那一层、**预设效果窗口**负责该角色的预设层。层内按写的顺序播放，不同层默认同时开始。

原来那个独立的「镜头效果」窗口已经去掉——镜头就在画面编辑器里编。只读时间轴整条链也去掉了，取而代之的是每个层自己的一行摘要，例如「镜头 · 本层 2 段 · 共 1.20 s」。

### 新增：整行按一条队列播放

在台词卡的额外指令里加一行：

```
#aavt;queue
```

这一行的所有效果就按**写的顺序**一段接一段播（例如 人物-人物-镜头），而不是各层同时开始。不加这一行＝各层同时开始，与之前完全一致，**老工程不需要改**。

- 画面编辑器里有一个开关（`队列：串成一条` / `队列：各层并行`），按一下即时生效：它直接写上或删掉那一行标记。
- 接缝处的等待会写成 `at=` 偏移，就在指令里，看得见也改得动。
- 改任何一层之后不需要"再去另一个窗口应用一次"：队列每次播放前按当前文本重算。

### 新增：层内效果就地改（载入 / 替换）

每个层的编辑器都有 `载入第 k 段` 和 `替换第 k 段`：把某一段的数值读回编辑器，改完写回**原来的位置**。

- 以前改一段只能"删掉重加"，那会把这一段挪到本层末尾——六秒编排里想改第 2 段的角度，顺序就变了。
- 相对移动段（`move`）不能载入：它相对于"跑起来时"的画面，而编辑器编辑的是绝对构图，界面会直接说明这一点，指令仍可直接当文本编辑。

### 队列时长上限：3 秒 → 10 秒

一行排成队列后，总时长超过上限的部分会被「直接跳到结束状态」（不放动画）。原上限 3 秒太短：五段转身加一次镜头就是 3.6 秒，镜头刚排到就被截断，看起来像"镜头第一步就跑了"。现在上限 10 秒，开关按下去时会报这一行的总时长，超限时也会说明。

### 修复

1. **一行里写两条完全相同的指令，会让整个工程的所有效果失效**（不只是这一行）。触发方式很常见：`＋ 加为下一段` 连按两次、或复制粘贴同一行。现在重复指令是合法的，会正常播两遍。
2. 人物模式的层编辑器与旧控件重叠。
3. `＋ 加为下一段` 在人物模式点不动。
4. 切换镜头范围（整体 / 仅背景）后，上移与删除可能作用到另一层。
5. 预设效果窗口打开时，工具列会一起收起（与其他入口一致）。

## 安装

退出游戏，把 `mods` 合并进游戏目录，在官方 Mod 管理中启用 RukariLib 与需要的功能模组，重启游戏。工程文件不需要转换。

## 已知限制

- Spine 叠加轨不参与队列，也不在动作等待里。
- `#charp` 起点预置段不参与排队（它在同一帧提交）。
- 手写 `interrupt=true` 的行不能开队列，会按它自己的指令播。
- 相对移动段不能载入编辑器（只能直接编辑指令文本）。
