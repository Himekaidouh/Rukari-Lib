## Dot 的实际操作步骤

### 1. 建立可回滚的测试工程

优先使用副本或专门的测试工程，不要覆盖用户正在编辑的工程。测试工程至少包含：

- 一条有文字的对白；
- 一条空对白；
- 一个 AAVT 人物位置指令；
- 一个 AAVT 镜头指令。

示例附加指令：

```text
#aavt;char;3;set;x=120;y=80;duration=0;easing=linear
#aavt;camera;set;x=0;y=0;zoom=1.2;duration=0;easing=linear
```

空对白行只放指令，不要混入空格或占位字符。

### 2. 验证编辑器预览

选中包含指令的对白行，点击绿色重播：

- 三号槽位应保持三号槽位，不应跳回一号槽位；
- 人物位置和镜头应立即变化；
- 连续点击绿色重播，起点应回到当前场景基线，不应叠加漂移；
- 关闭并重新打开“更多的画面效果”窗口，当前页码和槽位应保留。

### 3. 验证官方保存与发布

在扩展工具中打开“工程保存”，点击“保存并发布”，等待页面显示完成。

记录点击前后的文件时间和大小：

```text
data\projects\<工程名>.aap
 data\saves\<工程名>.aas
 data\projects\<工程名>.build.json
```

成功判据：

- AAP 和 AAS 同名；
- AAP、AAS、build.json 在本次保存后同时更新；
- AAS 不再是旧版本；
- 日志出现以下顺序（具体时间可不同）：
  - `publish-receipt stage=AAP`
  - `embedded-compile status=OK`
  - `publish-receipt stage=PUBLISH`
  - `index-load status=READY`

如果只有 AAP 更新而 AAS 没有更新，说明只保存了编辑草稿，正式播放不能作为有效结果。

### 4. 验证正式播放

退出编辑器，进入正式播放，从第一条对白开始：

1. 手动点击推进一次，确认 AAVT 指令生效；
2. 重新从第一条开始，直接打开 AUTO，确认第一条带 AAVT 的对白也生效；
3. 手动推进一条后切换 AUTO，确认后续 AAVT 仍生效；
4. 连续两句使用人物位移时，第二句应从上一句的终点继承；
5. 空对白行应执行其指令并完成官方动作时间轴，再进入下一行；
6. 点击或按 Enter 跳过语音时，只跳过语音，不应被全局语音等待时间阻塞；AUTO 才应用语音结束后的延迟。

正式播放期间同时观察诊断日志。应能看到：

- `player-dispatch` 或等价的场景命令分发记录；
- 当前工程的 AAP/AAS 映射成功；
- 不应出现 `auto-discover-no-active-pair`；
- 不应出现 `publish-pending` 长时间不结束。

### 5. 失败时要收集的内容

保留失败现场，不要先重新保存或删除文件，收集：

- `E:\AA1.01\BepInEx\LogOutput.log`
- 诊断目录中本次最新的 `player-command-observation-*.log`
- 工程对应的 `.aap`、`.aas`、`.build.json` 的文件时间、大小和 SHA-256；
- 失败时的工程名、播放模式（手动 / AUTO）、对白序号；
- 是否修改过 AA 的存储路径。
