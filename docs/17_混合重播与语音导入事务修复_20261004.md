## C01：混合指令绿色重播

1.4.3 在 `CaptureDataListScene` 通过常规选中行读取时直接返回 scene，却没有返回 InputProof。FL 与 AAVT 混用时，同一个真实预览窗口里可能重复进入 DataList：第二次捕获没有完整证明，重复回调不能复用原代，会清除第一次已经观察到的真实 FIRST。用户已证实正常切卡可用、绿色重播失效；日志显示阻断发生在 AAVT 派发前。

1.4.4 保留已有 shared `ReadSelection` 与缓存选中行相互核对后的托管快照，再进行第二次完整读取。新纯托管 planner 要求两次项目、节点、行号、场景指纹、ContextId、台词和完整额外指令一致，才能生成原格式 InputProof。任何读取失败、缺失或漂移均拒绝。

选择令牌、文档修订号可能在 DataList 中刷新；它们不代替实际上下文及原文证明。后续 pump 仍必须重新取得选中行和共享文档确认，派发前的代次及窗口检查保留。同窗口重复回调可以保留真实 FIRST，但不能伪造 FIRST、重新接受已拒绝的 FIRST，或借用上一代身份。

未放宽原 unique-input fallback 对选中行的拒绝规则，未添加原生 getter、原生补丁或跨模块动画覆盖规则。诊断 `captureSource=confirmed-scene-input-proof` 表示已取得完整输入证明，既可能来自选中行也可能来自原输入 fallback；不再将选中行错误标成 unique-input 来源。

## C02：索引锁前快照不得覆盖并发导入

旧 lookup 先读取索引，再拿扩展名修复锁，拿锁后却继续使用之前的列表。两次操作之间如果后台导入已提交新条目，修复会将新条目覆盖掉。

新版仍使用零等待修复锁；后台导入持锁时不在 Unity 主线程等待。成功拿锁后重新读取索引、按内容 hash 重新定位当前条目，并重新检查当前路径和实际容器。条目已被另一次导入修复时使用最新路径，条目消失或字节损坏时拒绝；只有当前表上的实际修复才提交索引。

## C03：失败必须恢复已有文件的改名

原导入只记录本批新建的文件，没有记录已有私有语音从错误扩展名移到正确扩展名的动作。索引提交前取消或失败时，旧索引仍指向已经消失的旧路径。

新版分别记录新建文件和实际改名。导入未提交时，在持锁范围内逆序撤销本批新文件及改名；lookup 独立修复的提交失败也使用同一改名回滚。恢复前必须验证内容 hash、长度及目录边界；不能覆盖重新出现的旧路径或删除外部替换的字节。预先存在的正确目标不算本批移动，也不会在回滚时被删除。官方路径所属的 RestoredNative 条目仍禁止改名，用户来源音频不改动。

索引继续使用暂存写入和原子替换。新增 checkpoint 是逐操作的 internal 测试重载；原运行签名保留并传 null，没有静态测试开关。这里验证的是取消和可捕获异常的恢复，不宣称进程突然终止、磁盘故障或外部写入破坏时也能保证恢复完成。
