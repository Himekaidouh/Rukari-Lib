# 实现边界、代码与素材说明

本文件描述现有完整实现的边界和交付内容，供阅读源码时区分公共接口、宿主适配、自有算法及外部依赖。它不提出新的集成任务。

## 1. 实际采用的技术

本项目包含以下几类代码：

| 类型 | 内容 | 源码位置 |
| --- | --- | --- |
| 自有公共库 | 服务发现、主线程队列、统一结果、编辑事务、工具树、面板、设置、指令命名空间路由。 | `Rukari.Lib/` |
| 自有纯逻辑 | 指令解析/验证、坐标与旋转规划、基线恢复、前序链、pending、预设采样、overlay、贝塞尔反求和派发策略。 | `AzureArchive.VideoTools.Core/` |
| 自有数据读取与工作区 | 读取AAP的JSON结构、读取AAS的FlatBuffer结构；保存模组自己的工作区/投影/诊断数据。 | `AzureArchive.VideoTools.Formats/` |
| 游戏运行适配 | 调用当前AA的编辑、编译、保存和UI对象；使用Unity、NGUI、IL2CPP interop与显式Harmony补丁。 | `Rukari.Lib.Runtime/`、`Rukari.MoreEffects/`及链接的共享引擎 |

运行适配依赖当前AA中可用的类型、成员和时序，有些成员属于内部实现。文件读取层依赖已掌握的数据格式结构。因此，不能把整个项目描述为“完全只依赖公开稳定API”。

### 文件格式读取与写入的区别

[AapProjectReader](../src/AzureArchive.VideoTools.Formats/Aap/AapProjectReader.cs) 和 [AasScenarioReader](../src/AzureArchive.VideoTools.Formats/Aas/AasScenarioReader.cs) 是本项目中的读取器，用于验证、关联场景与构建指令索引。[CheckedFlatBuffer](../src/AzureArchive.VideoTools.Formats/Aas/CheckedFlatBuffer.cs) 是项目自己的有边界检查读取实现；本交付不依赖Google.FlatBuffers生成代码或NuGet包。

作者通过界面应用指令时修改的是官方编辑器的当前内存文档。工程/可播放文件的落盘由官方保存和编译方法完成。项目不会用自有序列化器直接重写用户的 `.aap` 或 `.aas`；模组工作区和缓存文件不属于官方工程文件。

旧版失效语音清理按钮与清单/索引写入实现已移除。当前仅保留 VoiceOverrideDiagnostics 的只读检查，不删除引用，不改写 manifest.json 或 voices.txt。

了解格式布局、检查API声明、对现有运行进行适配，与复制官方反编译函数源码是不同事情。此包提供的是项目文件中的现用源码；归档不包含官方的反编译代码、`dump.cs`、DummyDll、游戏程序集、interop副本、元数据或反编译工具。不过，仅凭打包文件和哈希清单不能证明全部历史开发过程、也不能替官方解释其规则。交付文档不作“获官方认证”之类保证。

## 2. 人物操控的边界

人物操控实现围绕五个物理槽位，而不是按姓名建立任意数量的动态实体。槽位锚点、剧情坐标与立绘局部偏移有明确转换关系。“空槽预设”暂存的是变换，**不会生成一个人物**；需要官方后续把人物放入槽位，运行时再消费到场变换或在预览链中恢复它。

普通旋转指屏幕内Z轴倾斜；预设转身使用Y轴旋转。左右翻转与屏幕倾斜之间有转换规则，以避免镜像后方向被误解。Y轴转身的侧身压缩和整圈轨迹属于预设临时姿态，不改变官方人物资源或Spine骨骼动画。

挤压拉伸通过根变换缩放来实现临时轮廓变化，与角色已有的缩放组合。实现没有在所有立绘资源上验证脚底pivot；不能保证每个人物的脚都绝对固定。预设计时来自 `Stopwatch`，也未承诺与故事暂停、倍速完全同步。

前序继承依赖可确定的工程路径、场景身份和角色到场信息。多个可能前序、无法对应的身份或资源冲突会返回失败，不能任意猜一个来源。原生姿态读写与回滚还需要有效当前对象；托管数学测试通过不等同于原生对象生命周期已全部验收。

四预设支持贝塞尔时序。普通set/move过渡当前使用已有的NGUI缓动选项，没有共用自定义贝塞尔参数。具体公式、指令和真实边界见 [人物立绘操控技术实现](02_人物立绘操控技术实现.md)。

## 3. 编译、预览与保存的边界

自定义指令不是放任官方编译器接受任意未知指令。Lib仅摘取已登记路由拥有的完整指令行，官方编译净化后的内容；摘出的部分交给拥有者解析和验证。未登记的未知指令仍走官方行为。没有关闭官方整体检查，也没有覆盖用户其他Mod的指令。

编辑预览按选择、编译快照与推进窗口确认来源。上游缓存允许同一选择代的新窗口认领，下游Core授权仍按选择代消费一次；重新发起DataList可以生成新代次，不能据缓存能力推断同代窗口可以无限重放。fix6 已修订选句捕获时序，用户反馈立绘重播正常；这项实际确认与同代授权边界分别记录，具体见[指令完整链](04_指令编辑保存编译与播放.md)及[首次正式发布](14_首次正式发布.md)。

保存按钮的完成回执表示官方保存、构建、发布调用没有抛异常；它不是对全部输出文件重新读取、逐项校验后的证明。当前提供者也没有完整实现“文件干净就跳过”的检测。正式播放还依赖对应播放文件与索引，不应把内存草稿的预览和已发布文件混为一件事。

## 4. 原生适配与生命周期

共享宿主有Ready/Stopped状态、主线程队列和服务注册lease。功能提供者负责自己的运行对象和资源清理；关闭窗口通常保留草稿，不等于注销功能。插件没有对所有原生补丁提供热卸载保证；切换模组组合应重启。

源码保留部分诊断和兼容探针，存在类名不代表默认全部启用。[播放器观察配置](../src/Rukari.MoreEffects/Runtime/PlayerCommandObservationOptions.cs) 区分关闭、仅观察、窗口、身份、试验与执行阶段；默认执行阶段的具体钩子见 [PlayerAdvanceScenarioObservationPatch](../src/AzureArchive.VideoTools/Runtime/PlayerAdvanceScenarioObservationPatch.cs)。不能因为静态反射找到成员就判定安全可调用。

当前适配没有把整个反射树当成可用契约。当前选句读取明确避开旧的 `ScriptNodeInspector.selectedScriptItem` getter，改读已显示行的选中状态，并核对节点、行号、对象寿命和输入同步；见 [NativeEditorDocumentBackend](../src/Rukari.Lib.Runtime/Editor/NativeEditorDocumentBackend.cs)。某些值类型装箱路径和接收原生Selectable子对象的回调也属于项目已知禁用边界。本文不为它们重新开放；实际调用和状态检查仍以源码为准。

更多画面效果连接共享UI、工作台和指令服务，其加载依赖Lib Runtime。修改公共契约时保留已有方法签名和接口；新增能力使用新重载或兄弟接口，不能靠给现有方法加可选参数来声称ABI兼容。详细契约见 [Rukari Lib接口与统一UI](03_RukariLib接口与统一UI.md)。

根目录 [LICENSE](../LICENSE) 保留原MIT许可及 `Copyright (c) 2026 Himekaidouh`。本次整理没有删除或替换版权信息。MIT适用于本项目自有代码及相应文档，不把外部游戏代码或美术的许可改成MIT。

### 外部程序集

游戏内宿主需要本地已有的BepInEx、Harmony、Il2CppInterop、AA/Unity/NGUI及Spine声明引用。这些引用在项目中 `Private=false`，本仓库不携带它们。具体名字与 `{GameRoot}` 相对路径见 [实际项目输入清单](../provenance/project-inputs.json)；构建环境由 [构建与验证](05_构建与验证.md) 说明。

### 共享UI素材

UI素材位于 `src/assets/rukari-lib/ui/`。它包含Common图集/坐标元数据、两张Popup装饰、NOTICE及SHA-256清单，共六个文件。只有Lib Runtime拥有这一份共享素材，功能Mod复用它，不在各自包中再带副本。

本仓库仅在 `src/assets/rukari-lib/ui/` 保存一份共享素材，Runtime构建时复制到自己的输出 `ui/`。

这些图片为第三方游戏美术；来源和权利归属以素材包 `NOTICE.md` 为准。随包交付不代表额外授权或官方背书。Lib读取时配套核验，失败后使用程序绘制备用外观，不把有误坐标搭到一张不同图集上。
