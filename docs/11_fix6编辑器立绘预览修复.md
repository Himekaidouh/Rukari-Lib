## 修复方式与边界

普通选行、文档写入和配音的选句路径保持原有严格规则。新增的回退只用于 DataList 当场的只读场景捕获，而且仅在共享服务明确返回「请先在工作台选择一句台词」时允许进入。

1. 要求共享 runtime 已就绪、当前调用在主线程、节点编辑工作台可见、列表未重排。
2. 同步读取两轮实际 inspector、node、缓存、scripts、输入框指针、完整台词输入与额外指令输入，以及每个缓存行的实际归属、索引、Script 指针和完整文本。指针只在本次调用消费；跨调用仅保存数值身份与托管字符串。
3. 只有零个活跃选中行，且完整台词与额外指令恰好匹配唯一可见行，才能冻结该行的实际 context、索引及文本。重复完整匹配、坏的活跃行、缺失读取或两轮变化全部拒绝；不会把空串当作通配符，也不会解读 DataList 的不透明 request 为场景索引。
4. 仍只关联本代序后的实际首条 Unity 字符串，保留完整编译哈希、长度、行数、主线程及原窗口检查。
5. 既有主线程泵必须通过普通严格选行 API 取得真正已选中的同一场景，并通过共享 `ReadSelection` 再次核对实际 ContextId、完整台词及额外指令。这一步额外核对 prompt，因为现有场景指纹不包含额外指令。
6. 新 DataList 会取代旧候选；处理完成后释放该候选的输入证明。原预览租约、截止水位、唯一候选、内容健康、场景与一次执行检查继续生效。

这不是「以后找得到哪一行就补认哪一行」。原捕获仍为空、输入没有同步、匹配歧义或后续严格选行失败时继续拒绝，不借后来的日志或场景复活候选。没有新增原生补丁目标，没有读取黑名单 getter 或恢复 Selectable 回调，也没有开启实验原生指令管线。
