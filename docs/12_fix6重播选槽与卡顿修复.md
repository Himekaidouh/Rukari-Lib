## 自动保存和重复发布的区别

官方负责自己的自动保存、自动编译。旧配音 Mod 在 `StudioCommon.Compile()` 返回后，又同步调用 `StudioCommon.Compile(projectName)` 完整发布一次。后者由 Mod 追加，包含官方发布工作的耗时；不能把这段额外工作称为官方自动保存本身。

22:24–22:37 会话记录了 104 次超过 500 ms 的主线程停顿，最长 9651 ms。Mod 追加发布共 48 次，单次 1305–3565 ms、平均 1698.5 ms、合计 81.5 秒。这 48 次调用全部在返回后 28.7–107.0 ms 内对应一次停顿。例如额外编译 1529 ms，对应停顿 1562 ms。这是需要移除的明确阻塞路径，但不能据此解释其余 56 次停顿或宣布全部卡顿已解决。

诊断中的 `ours=False` 仅表示观察器前次 `Update` 的计时未覆盖主要停顿；它没有计时配音回调、其他组件、`LateUpdate` 和官方编译，不能据此排除 Mod 或归责于 AA。

本轮删除 `PublishProbe.PublishPostfix` 及其自动追加的 `Compile(name)`。旧 `Compile/PublishPlayableAfterBuild=true` 也不再执行追加发布，旧键被标为退役。保留原有 Compile 作用域和实际 `PromoteSafeSave` 观察边界，没有新增原生补丁目标。

「工程保存 → 保存并发布」仍显式调用官方的 Save、Compile、命名发布三个入口。官方自动保存继续工作；后台编译不再由配音 Mod 强制发布完整作品。正式作品更新需使用手动「保存并发布」或官方真正发布入口。工程、语音伴随资源的手动发布仍须实机复核。

## 手动发布的语音伴随资源

原自动 postfix 的作用域覆盖了它内部的命名发布，但原手动按钮随后自己的命名发布在这个作用域结束后执行。只删除 postfix 而不补显式作用域，不能保证手动发布仍同步导入语音。

新增纯托管兄弟接口 `IEditorPublicationScopeService.Begin(string expectedProjectName)`，不改冻结的 `IEditorSaveService` 或其它接口签名。配音包注册可选 provider，更多效果保存服务在完整 Save → Compile → 命名发布链外使用其 `IDisposable` 票据。

- 开始前核对 runtime、主线程、当前资源根和真实编辑会话文件属于该工程；只有托管字符串进入票据，不跨调用保存原生对象。
- 没有导入语音索引的正常工程也可以保存；无有效项目、身份冲突或读取失败必须明确失败，不能返回空根的成功票据。
- provider 没安装时普通保存仍可用；provider 存在但失败时不执行保存。任何返回或异常都释放作用域。
- 语音伴随目录仍由既有成功 AAS 安全落盘观察触发。仍不直接修改 AAP/AAS/官方工程清单，仍不增强、转码或改写原音频。

## 槽位选择

重播期间，选句读取可能暂时失败，或者编译身份发生刷新。原代码在清除草稿时同时清掉窗口选槽；共享选句恢复后会生成新授权令牌，预设页的兜底又选择槽位 1。

新增纯托管 `VisualEditorSlotPreference`，只保存当前已观察台词的 context 与 1–5 的 UI 目标。内部 `RuntimeContextId` 直接来自现有、已核对的 `shared.ContextId`；没有新读原生属性或改动公共构造函数。

同一 context 恢复后重新读取当前指令，并恢复选槽。观察到不同台词则丢弃原偏好。所有旧草稿、验证预览、选择令牌与应用授权仍按原规则失效；来源不可用或输入未同步时禁用人物、镜头和屏幕文字编辑。没有修改官方人物栏选槽，也没有给官方播放按钮新增 hook。

此处 context 来自现有 inspector、node、script 和行号身份。若重播重新创建这些原生实例，即使文字相同，仍按不同 context 保守清除选槽；没有按文字或旧地址猜测同一台词。需要实机重播确认当前 AA 是否触及这个边界。
