# 极限测试流程：队列 / 层 / 编辑路径（2026-10-14）

> 用途：把「叠加式效果模型 + 队列标记 + 层编辑器」压到边界上，看它在哪里出现**不生效、悄悄改变语义、或者报错说不清**的情况。
> 用法：**每轮只动一个变量**（一条用例就是一轮），跑完不要清日志——我自己读。所有用例的判据都落在日志上，不需要你截图或描述现象。

## 1. 指令语法与硬上限（先看这张表，写错了会当成"功能不生效"）

```
#aavt;char;<1..5>;set;x=…;y=…;rotation=…;rotationX=…;flipX=…;duration=…;easing=…[;at=…]
#aavt;char;<1..5>;move;dx=…;dy=…;drotation=…;drotationX=…;duration=…;easing=…[;interrupt=true]
#aavt;char;<1..5>;reset;duration=…;easing=…
#aavt;charPending;<1..5>;set|move|reset;…            ← 起点预置：不接受 duration / easing / at
#aavt;camera;set;x=…;y=…;zoom=…[;scope=overall|background];duration=…;easing=…[;at=…]
#aavt;camera;move;dx=…;dy=…;dzoom=…;duration=…;easing=…
#aavt;camera;reset[;scope=…];duration=…;easing=…
#aavt;fx;<1..5>;sway|squash;amplitude=…;frequency=…;cycles=…;direction=left|right[;bezier=x1,y1,x2,y2]
#aavt;fx;<1..5>;spin;axis=x|y;frequency=…;cycles=…;direction=left|right
#aavt;fx;<1..5>;headbutt;back=…;forward=…;duration=…;direction=left|right
#aavt;queue                                          ← 行级标记：本行整行串成一条队列
#aavt;continue                                       ← 行级标记：连续对话
```

| 硬上限 | 值 | 越界后的行为 |
|---|---|---|
| `duration` | 0 … 600000 ms | 整条指令报错（`Duration must be between 0 and 600000 milliseconds.`） |
| `rotation` / `rotationX` | ±3600° | 报错 |
| 镜头 `zoom` | 0.1 … 8（**整体×背景的组合值也要在这个范围**） | 报错 |
| 槽位 | 1 … 5 | 报错 |
| 每行指令数 | **22** | 编译失败并指名卡片 |
| 每家族条数 | 人物 5 / 预设 5 / 镜头 scope 2 / spine 轨 10 | 同上 |
| 队列预算 | **10000 ms** | 超出的段被**折叠**（`kind=Collapsed`、时长截到上限、当帧应用结束状态） |
| 预设时长 | `cycles ÷ frequency` 秒（headbutt 用 `duration`；`cycles=0` 即 0 秒） | — |

轨的分配（决定"谁等谁"）：`char:{槽位}` 一条、**`camera` 一条（两个 scope 共用！）**、`preset:{槽位}` 一条；同轨追加、跨轨并行。`#aavt;queue` 把整行读成一条队列，接缝处写 `at=`。

## 2. 极限用例

### A. 规模

**A1 满行 12 条效果 + 队列标记**（压力最大的一条，建议先跑）
```
#aavt;queue
#aavt;char;1;set;x=-400;y=0;duration=500;easing=easeInOut
#aavt;char;1;move;dx=100;duration=500;easing=easeInOut
#aavt;char;3;set;x=0;y=0;rotation=0;duration=500;easing=easeInOut
#aavt;char;3;move;dy=60;duration=500;easing=easeInOut
#aavt;char;5;set;x=400;y=0;duration=500;easing=easeInOut
#aavt;char;5;move;dx=-100;duration=500;easing=easeInOut
#aavt;camera;set;zoom=1.2;duration=500;easing=easeInOut
#aavt;camera;set;scope=background;zoom=1.3;duration=500;easing=easeInOut
#aavt;fx;1;sway;amplitude=10;frequency=2;cycles=3;direction=right
#aavt;fx;3;squash;amplitude=0.2;frequency=3;cycles=3
#aavt;fx;5;spin;axis=y;frequency=1;cycles=2;direction=right
```
- 期望：`embedded-directive-capture … commands=11; queue=OneQueue`；**11 条 `queue-segment`**；总时长 **8500 ms**；
- 期望的 `at=` 恰好 6 个：`1000`（char:3 首段）、`2000`（char:5 首段）、`3000`（整体镜头）、`4000`（fx:1）、`5500`（fx:3）、`6500`（fx:5）；其余 5 条必须是 `placement=append`（同轨追加，**不该**写偏移）；
- 三个角色、两个镜头 scope、三个预设都在动，且没有任何 `queue-over-budget`。

**A2 同一条轨 10 段**（列表操作的压力）
```
#aavt;queue
#aavt;char;3;move;dx=20;duration=300
…（同样一行重复 10 次，dx 依次 +20）
```
- 期望：`actor=char:3` 10 条段，`startMs` 0/300/…/2700，**0 个 `at=`**（全是同轨追加）；总时长 3000 ms；
- 界面：`角色段 1/10` 循环选择、上移/下移/`载入第 k 段`/`替换第 k 段` 在第 1 段与第 10 段上都不出错。

**A3 超过家族上限**（应当**失败关闭**，不是静默）
```
#aavt;char;1;set;x=0;duration=100
#aavt;char;2;set;x=0;duration=100
#aavt;char;3;set;x=0;duration=100
#aavt;char;4;set;x=0;duration=100
#aavt;char;5;set;x=0;duration=100
#aavt;char;1;move;dx=10;duration=100
```
- 期望：编译失败，日志 `reason=embedded-command-invalid; node=…; scene=…; dialogue=…`，消息里出现 `at most five AAVT character directives`；界面上这一行的效果**全部不生效**（这是设计：宁可整行不播，也不静默丢一半）。

### B. 时间

**B1 预算边界：正好 10000 与 10001**
```
#aavt;queue
#aavt;char;3;move;dx=100;duration=5000
#aavt;char;3;move;dx=100;duration=5000
#aavt;camera;set;zoom=1.1;duration=1
```
- 期望：前两段 `kind=Animate`、`durationMs=5000`；镜头那段 `startMs=10000; durationMs=0; kind=Collapsed`，并出现 `queue-over-budget; …`。
- 把最后一行改成 `duration=0` 或删掉 → 总时长正好 10000，**不应**出现 `queue-over-budget`。

**B2 零时长段夹在队列中间**
```
#aavt;queue
#aavt;char;3;move;dx=100;duration=600
#aavt;char;3;set;x=0;y=0;duration=0
#aavt;char;3;move;dy=100;duration=600
```
- 期望：中间那段 `kind=Instant`、`startMs=600`、`durationMs=0`；**第三段仍在 600 开始**（瞬时段不占时间、不把后面的推后）。

**B3 单段打满预算**：`#aavt;queue` + `#aavt;char;3;move;dx=100;duration=600000`
- 期望：`durationMs=10000; kind=Collapsed` + `queue-over-budget`；这一段会**直接跳到结束状态**（不是动画）。

**B4 越界**：`duration=600001` → 整条指令报错（见 §5）。

### C. 队列搭配

**C1 交错四段**（人物-镜头-人物-镜头）
```
#aavt;queue
#aavt;char;3;move;dx=100;duration=600
#aavt;camera;set;zoom=1.4;duration=500
#aavt;char;3;move;dy=100;duration=600
#aavt;camera;set;scope=background;zoom=1.2;duration=500
```
- 期望：`0 / 600(镜头 at=600) / 1100(人物 at=1100) / 1700(背景镜头 append，因为它和上一个镜头同轨)`；总 2200 ms。
- 这说明"同一条 `camera` 轨的两个 scope 不是两段并行，而是一条队列里的两段"。

**C2 多槽位交叉**：`char;1` `char;3` `char;1` `char;3`
- 期望：第 3 段（`char:1` 的第二段）**必须带 `at=`**（它要跳到 char:3 之后），第 4 段是同轨追加。

**C3 起点预置段夹在中间**
```
#aavt;queue
#aavt;camera;set;zoom=1.2;duration=500
#aavt;charPending;3;set;x=100;flipX=true
#aavt;char;3;move;dx=100;duration=600
```
- 期望：`charPending` 那段 `placement=append`（**它不能带 at=**，校验器会拒），它后面的人物段 `at=500`（自己跳过空档）；总 1100 ms；
- 界面：把这行开关关掉再打开（或首次打开时），状态行会带一句「起点预置段（charp）不排队，它仍在同一帧提交」。

**C4 手写 `at=` 与队列冲突**
```
#aavt;queue
#aavt;char;3;move;dx=100;duration=600;at=2000
#aavt;camera;set;zoom=1.3;duration=500
```
- 期望：队列**重排**——人物段变成 `append`（`at=2000` 被丢掉），镜头段 `at=600`；总 1100 ms。这是设计：带标记的行以队列为准。

**C5 `interrupt=true` 与标记共存**：`#aavt;queue` + `#aavt;char;3;move;dx=10;duration=600;interrupt=true`
- 期望：**这一行不排队**，按原样播（interrupt 段当帧接管）；BepInEx 日志出现 `queue-refused` 与原因；界面开关按下去仍显示"串成一条"（行本身确实有标记）——这是当前已知的语义：标记在，但排不出来。

**C6 两个镜头 scope 各 3 段**（曾经误拒的用例）
```
#aavt;camera;set;zoom=1.1;duration=300
#aavt;camera;set;zoom=1.2;duration=300
#aavt;camera;set;zoom=1.3;duration=300
#aavt;camera;set;scope=background;zoom=1.1;duration=300
#aavt;camera;set;scope=background;zoom=1.2;duration=300
#aavt;camera;set;scope=background;zoom=1.3;duration=300
```
- 期望：编辑预览可以正常起（`status=EDITOR_PREVIEW_LEASE_QUEUED`，**不是** `REJECTED`）；6 段顺序执行（同一 `camera` 轨），不写多余 `at=`。

**C7 开关反复切**：同一行 开→关→开 三次
- 期望：文本里 `#aavt;queue` 只出现一次；第二次按"开"时日志 `alreadyPresent=True`；关掉后那一行**整体消失**（结尾最多留一个空行）。

**C8 两个行级标记共存**：`#aavt;queue` + `#aavt;continue`
- 期望：两者互不干扰；`embedded-directive-capture` 里 `queue=OneQueue; continue=True`。

### D. 编辑路径

**D1 跨窗口反复应用**：人物层 2 段 + 镜头层 2 段 → 镜头模式应用 → 人物模式应用 → 再回镜头模式应用
- 期望：三次都成功；任何一次都不该出现 `资源 X 在这一行里已经有 N 段`（那是旧的 1:1 预览路径的提示，层写入不该走它）；每层段数不变。

**D2 `载入第 k 段` / `替换第 k 段` 的四个位置**：第 1 段 / 最后一段 / 唯一一段 / 全部（先 `清空本层` 再加回）
- 期望：载入后界面数值/画面等于该段；替换后**位置不变**、其余段不动；`替换第 k 段` 在没有选中段时是灰的。

**D3 切换镜头 scope 后立刻 上移/删除**
- 期望：作用于**当前 scope 那一层**（切到"仅背景"后删的就是背景层那段，不能删到整体层）。

**D4 撤销**：应用一次（带队列与 `at=`）→ `撤销上次修改`
- 期望：文本回到应用前（标记与各段一起回滚），层编辑器的段数也跟着回到旧值。

**D5 官方位移过渡的槽位**：在日志里会报 `官方位移过渡` 的槽位上拖位置或写位置指令
- 期望：拒绝并说明（"该场景存在官方位移过渡：拖拽、X/Y 与整体重置会被播放索引拒绝；旋转与翻转不受影响"）。

### E. 应当失败关闭的输入（每条都该有可读原因，不能崩）

| 输入 | 期望 |
|---|---|
| `#aavt;queue;xxx` | 抽取报错（"这个标记不接受取值"），该指令行**不被 sanitize**，其余效果也不生效 |
| `#aavt;queue;serial` | 合法，等价 `#aavt;queue` |
| `#aavt;charPending;3;set;x=1;duration=500` | 报错（pending 不接受 duration/easing/at） |
| `…;duration=600;at=300;interrupt=true` | 报错：`at=` 与 `interrupt=` 互斥 |
| `#aavt;camera;set;zoom=0.05;duration=300` / `zoom=9` | 报错（0.1…8） |
| 整体 `zoom=4` + 背景 `zoom=4` | 报错（组合值 16 越界） |
| `#aavt;char;3;set;rotation=3601;duration=300` | 报错（±3600） |
| 同一 spine 轨两条（可选，spine 未做） | 报错（同一轨只能一条） |

| `queue-refused`（BepInEx 日志） | 标记在，但这一行排不出来（附原因） |
| `[layer-ui] queue marker · mode=…` | 队列开关按下的结果 |
| `[camera-layer] / [character-layer] loaded\|replace\|add-as-next\|applied` | 层编辑器的动作与结果 |
| `observation sequence=…; status=EDITOR_PREVIEW_LEASE_QUEUED\|REJECTED` | 编辑预览是否起得来 |

**通用通过判据**（任一不满足就算失败）：
1. 计划里每段的 `startMs` 与"队列应长"自洽（前一段结束 = 后一段开始，除同轨追加）；
2. 该有 `at=` 的接缝有、不该有 `at=` 的同轨追加没有；
3. 没有 `overlap`、没有 `queue-plan-failed`；
4. 指令里的目标值（x/y/zoom/rotation）与 `SCENE_*_DISPATCHED` 里的一致；
5. 失败用例**都被拒绝**，并且日志里能读出原因（不能只有"没生效"）。

## 6. 首轮实测记录（2026-10-14，用户执行）

跑了 A1（11 条）、A2（10 条）、C 组若干。**A1 完全符合预期**（`commands=11; queue=OneQueue; errors=0`，11 条 `queue-segment`）。A2 暴露了一个真 bug，已修：

**症状**：整份索引加载失败并每 ~2.5 s 重试一次：

```
index-load status=FAILED; reason=embedded-commands-invalid;
diagnostic=reason=embedded-projection-compile-failed; Embedded project commands did not compile:
Command ID at 13f88b44-…:1:1 is invalid or duplicated.
```

**根因**：一行里**两条完全相同的指令**（A2 的"同一行重复 10 次"如果 dx 没改，就是 10 条同一个字符串）会生成同一个"按文本派生"的命令 ID；时间轴对重复 ID 的答案是**整份工程编译失败**——也就是说**这一行写重一次，整个工程的所有效果全部失效**（不只是这一行）。日常使用里这非常容易发生：`＋ 加为下一段` 连按两次（或双击）、复制粘贴同一行，都会命中。而且旧消息只报一个命令 ID 和一个节点 GUID，作者无法把它对应到某一行。

**修法**（提交见 §7）：命令身份改为 `v2` 种子，**把序号算进去**（同一文本在不同位置是两条命令）；失败消息拆成"不是 GUID"/"被哪条指令重复"，后者带上指令原文。回归测试 `TwoIdenticalDirectivesInOneRowStayTwoCommands`（先在没有修复的版本上跑过，确实复现同一句错误）。

**另一处观察（未修）**：诊断日志本身没有上限。编辑器开着时 `embedded-directive-capture` 每次编译都写一行——3 分钟 374 KB（约 73 行同一状态）。每个会话一个新文件，没有大小上限。建议按"状态不变不重复写"节流（与 `LogCameraLayerOnce` 同一套做法），等用户决定。
