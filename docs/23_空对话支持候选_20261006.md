# 空对话支持 · 1.5.3 验证候选

基于 1.5.2 单独修订。此目录没有合并 1.6.0 的纵深功能，原纵深候选仍保留。本版本尚未完成 AA 原生验收，不能标为稳定发布版。

## 两个不同的问题

1.5.1 → 1.5.2 修复编辑器人物位移继承起点与重复绿色重播。当前改动针对无文字台词的正式播放定位和快速推进，不把这两个问题混为一谈。

已有映射利用唯一非空台词确认整个 Script 节点的连续记录。该节点内的空卡片有可靠锚点，原路线可以关联；整个节点都没有文字时，缺少锚点，不能凭卡片序号猜测它对应哪个播放记录。

## 运行时改动

- 保留普通 Completed 窗口的原有唯一编译身份匹配和重复身份行号消歧。
- 真正空字符串必须同时匹配实际行号和完整编译身份。未收到消息不等于收到空字符串；不会从空消息列表制造身份。
- 快速推进产生的 overlap 窗口可通过已加载的保存索引确认所属记录。编辑器仍先使用现有预览 lease，正式播放不借用编辑器选中台词。
- 同一次获准调用链的同一记录只领取一次，去重跨越多次队列消费；下一次真实重播允许再次执行。同链不同记录分别执行。
- 先领取再推进预设边界；重复 sibling 不会结束刚排队或已启动的预设。
- 保留声控的 original 门禁。较晚的其他 prefix 取消 original、nested 异常、错误收尾顺序、后续 postfix 异常，都会拒绝同链尚未消费的窗口。已消费窗口不追溯撤销。

## 整段空节点的编译对应关系

新增候选捕获边界只读取本机官方 interop 的方法声明并观察实际调用，不包含官方方法体或反编译源码。

`BuildVertices` 提供本次编译的源节点 GUID 与 Script 对象。`StudioCommon.ParseScript` / `ParseFunctionScript` 观察同一输出列表实际追加的记录。只在同一调用恰好追加一条记录时记录其 table offset。

用官方 `CompileBytes` 返回的实际 FlatBuffer DataList table 地址解析对应行号，而不是按创建顺序、节点序号或 GroupId 推断。官方安全保存完成后，要求临时输出、目标 AAS、本次编译输出的 SHA 一致，并且 AAP 未变化。

满足这些条件才生成 `工程名.aap.rukari-map.json`，内容包括 AAP/AAS SHA 与长度、源 SceneKey、实际播放行号、记录指纹与完整编译身份。加载时重新验证全部字段；归档、场景或记录内容变化时拒绝旧证据。只写本 Mod 的旁文件，不改写 AAP/AAS。保存成功后清理归档缓存并请求索引重载。

旁文件可随相同内容的工程移动，绑定不依赖原电脑的绝对路径。移动或分享工程时须一并带上对应的旁文件；修改后需要重新保存发布以重新捕获。

**关键原生边界尚未证明：** fix6 与 beta 的声明相同且可以构建，但声明不能证明生产编译一定调用 `StudioCommon.ParseScript`。若实际保存出现 `compile-mapping-capture: no observed script emissions; proof omitted`，该路径没有覆盖生产编译，整段空节点仍未修复。未触碰带 byref IL2CPP 值型闭包的生成 emitter，也不以卡片顺序替代缺失证据。

## 尚未声称解决的范围

- 从第一句直接 AUTO 的全部失效问题。首次 `NO_INDEX` 发现与异步加载时序没有放宽，未加载索引的窗口不会补猜、补发。
- 官方没有输出可观察的编译消息时，单凭行号不能授权效果。
- `.aap2` 正式播放的磁盘配对仍是原有已知边界。
- 仅代码和托管测试不能证明空节点在 fix6、beta、FL 共存时的实际调用覆盖。

## 原生测试矩阵

两份 AA 分别测试，不能以 fix6 的结果代替 beta：

1. 一个非空锚点后接两张空台词卡，在三号槽位设置不同位置；验证绿色重播、正式手动播放、从第一句 AUTO。
2. 整个 Script 节点都为空的两张卡，设置不同指令，保存发布；查看是否生成有效旁文件以及捕获日志。
3. 同时使用 FL 与 AAVT，再测普通台词和空台词，反复绿色重播。
4. 直到下一句的预设在真正换句时结束；重复窗口不能提前结束它。
5. 修改、重新发布、移动工程后重测，确认旧映射不被复用。

日志保留 `BepInEx/LogOutput.log`，以及活动 profile 中 `cfg/AzureArchive.VideoTools/diagnostics/player-command-observation-*.log`。profile 的实际配置路径以 BepInEx 启动记录为准。

托管回归涵盖真空字符串、裸换行、无消息、不同实际输出顺序、错行、重复领取、新调用链、归档变更、跨工程歧义、损坏 JSON 和原有映射。构建记录与部署记录保存在候选目录外的 reports / deployment-backups，原生结果仍待填写。
