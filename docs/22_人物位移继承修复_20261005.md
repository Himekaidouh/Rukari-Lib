# 人物位移继承修复 · 1.5.2 候选

## 用户可见问题与改动

连续两句对同一人物设置位移时，第二句应该从上一句的终点移动到自己的目标位置。报告中的异常是：本句指令仍然执行，但从官方默认位置重新起步。

本次修复完整读取编辑器节点连线，恢复前文效果的继承链；继承起点成功写入并读回后，更新本句重播基准，避免随后又被旧默认起点覆盖。连续重播相对位移仍使用同一 entry，不逐次累加。本句没有 AAVT 指令时，等待继承链的流程保留原有有界重试；未读取成功、未绑定人物或未成功应用，均不再标记为已经完成继承。

已执行本句指令的预览会保留预约，迟到的补链不能把本句目标位置拉回上一句起点。暂缺链源时仍沿用原有降级行为：本句可以先运行；下一次重播在链源就绪后重建正确起点。本次没有将所有指令执行改为强制等待索引。

配套版本为 Rukari lib 0.4.3、更多的画面效果 1.5.2、人物配音支持 1.6.7。只修改画面效果及其随包 Core；配音与基础库功能没有新增变化。

## 证据与来源

用户日志的模组版本为 0.4.3 / 1.5.1 / 1.6.7，未加载 FlandreScarletMod。日志反复出现仅有 Entry 的实时图、没有 Script 场景并回退磁盘，以及 `official-project-resource-path-mismatch`；没有成功的预览链就绪记录。这能证明链源读取断路，不能仅凭日志断定所有动画和正式播放时序。

实际发布源码来自 `artifacts/fl-preview-compat-20261003/repository` 工作树。顶层源码是已暂停的原生命令实验，不作为本批发布输入。修复前 447 项构建输入与昨晚构建来源核对一致；此前首发与 1.5.1 的实时遍历文件完全一致。入队、出队重复加入同一个集合的问题早已存在，不能说成仅昨晚新增的回归。

原文件在后继节点入队时已调用 `enqueued.Add(target)`，出队又用 `!enqueued.Add(node)` 跳过节点，使后继节点全部被忽略。现由 `LiveProjectGraphTraversal` 统一处理实际 BFS：根和后继只在入队时去重，保留边顺序、默认运行时对象相等规则、GUID 去重和 4096 节点上限。测试与游戏适配器调用同一遍历实现。

## 实现边界

- `CharacterTransformBaselineStore.SeedInheritedEntry` 只在继承成功并读回后更新受控 X/Y、X/Z 旋转与翻转基准；没有继承的轴和位置 Z 保留既有 entry。官方 origin 不改。
- `PreviewChainRecoveryPolicy` 保留原 90-update 重试预算和工程、代次过期限制。解析失败、人物不可绑定、应用失败都不是成功覆盖；部分成功不能代替全部成功。
- 有继承但缺少预期人物的槽位计入失败，不能以零个待应用槽位误报成功。
- 队列溢出移除待处理项时，按该项代次释放预约，不影响后续新代次。
- 存储路径不匹配仍停止磁盘工程绑定。本次增加两个官方路径、代次，以及布局、根目录、工程名匹配结果；没有取消防止绑定错误工程的校验。用户实际两条路径未提供，具体为什么不匹配仍待新的诊断日志确认。

## 自动验证与游戏内复测

完整 fix6 构建运行四模组、四示例和四套测试；850 项通过（Core 564、Lib 165、Voice 95、Spine 26），包含新增的多节点、分支汇合、循环、自环、重复边、节点上限、实际遍历到预览继承、晚到起点替换、祖先编辑、未控制轴保留及迟到补链保护。两个既有符号链接夹具仍受本机权限限制。每次候选打包绑定最终源码和 DLL 哈希；原生状态保持 `Native=not-run`。

建议用三号槽位的同一人物做三张连续台词卡，保持官方人物位置和人物标识一致。第一张写：

```text
#aavt;char;3;set;x=-250;duration=0;easing=linear
```

第二张写：

```text
#aavt;char;3;set;x=250;duration=1600;easing=linear
```

第三张不写 AAVT 指令。确认第二张从 -250 开始移动到 250，第三张保留继承终态；重复绿色重播第二张，起点仍为 -250。再将第一张改成 -400，确认第二张从 -400 开始。另测相对位移重复重播、换人物、跨节点、保存前后，以及正式播放。

自动测试不能代替上述游戏内确认。首次正式播放在索引尚未载入时可能遗漏第一条指令，是既有独立边界，本次未改变正式播放的初次加载架构。当前仍为候选修复，不复用旧版本的稳定验收记录。
