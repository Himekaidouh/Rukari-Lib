## fix6 声明变化与适配

只读取官方随包声明元数据，没有反编译官方方法体。本轮核对 13 个构建输入。GameAssembly、Assembly-CSharp 和两个 Spine interop 文件的字节发生变化；Spine 类型/成员声明比较没有变化。

关键变化是旧 `AudioManager.SetVoice(string name)` 改为 `SetVoice(string name, Il2CppSystem.Action onStarted = null)`。原精确单参数查找会失败；旧冷加载补救若吞掉原调用，再只传字符串重播，也会丢失官方提供的开始通知。

现按精确声明优先选双参数，仍识别旧单参数。补丁只映射字符串 `__0`，不读取、缓存或替换 Action。fix6 模式放行原 SetVoice，让官方完成加载、开始播放和通知；不再使用旧冷加载重播。Starting 等待受加载超时约束，既有播放安全超时和尾部等待保留。播放观察暂停时，新模式也在读取预加载 iterator 前放行原预加载，避免相互矛盾的拦截。

设置入口、WindowManager、当前编辑行扫描、人物变换、保存/编译及重点 Spine 成员的声明仍匹配。官方预加载 iterator 的声明形状也匹配，但编译器生成名、状态值和取消重复请求的实际行为不是稳定 API；其与新开始通知的运行时关系仍待验证。

fix6 修正了官方 AUTO 等待被减半的问题。本 Mod 的 `PostPlaybackDelaySeconds` 是播放后的额外等待，不重写官方 AUTO 设置。

## 全局配音音量

在「设置 → 模组设置 → 人物配音支持」调整「配音音量」。旧工具箱中的「播放设置」共用同一配置。

- 0–100%，默认 **50%**；50% 保留此前响度，0% 静音，100% 最多放大当前官方语音源输出两倍，受音源上限限制。它不是绕过游戏主音量或配音静音的独立增益器。
- 松开滑条或关闭设置页时保存到当前 Profile；当前正在播放的请求保留原设置。
- 首个满足播放资格的非默认请求只观察音源音量，同一音源后续不同请求才尝试写入；更换音源重新检查。
- fix6 必须在本请求中先观察到未播放，再观察到开始播放。非默认音量在原 SetVoice 前用既有播放谓词观察一次未播放，使已缓存、在原调用内立即开始的声音也能取得资格。若原调用前仍有旧声音播放，不授予资格，必须在原调用后实际观察到未播放，再观察到播放；首次只见到播放则保守跳过本次音量调整。这个条件不新增 clip 查询或访问官方回调；新增读取时机和状态与新片段的关联仍待实机验收，读取异常只停用音量子功能。
- 50% 默认路径没有新增音量访问，除非存在此前已经尝试写入、尚待清理的租约。不会持续逐帧读写音量。

配置位置：`E:\AA1.0 fix6\profiles\RukariFix6\configs\rukari.charactervoice.cfg`。本轮安装值为 `VolumePercent = 50`、`PostPlaybackDelaySeconds = 0`；其它既有设置迁入新 Profile，MoreEffects WorkspaceRoot 只改指新 Profile 自有工作区。

音量异常只停用音量子功能，不将正常配音判为失败。写入前标记 `WriteAttempted`，回读匹配才确认；异常保留纯托管原值/目标值，稍后独立清理。自然结束、替换、失败、Reset、Stop 均可清理；非 Mod SetVoice 在官方原调用之前清理。只有同音源当前值仍精确等于 Mod 目标值时才尝试恢复，避免覆盖可观察的外部改动。这不是原子操作，不能识别同值 ABA；恢复 setter 返回日志也不代表已回读验证恢复结果。

## 选句与预览保护

不再安装 `OnChildSelect(Selectable)` 黑名单补丁，也不读取 `selectedScriptItem` getter。MoreEffects 独占既有 DataList 观察 hook；Lib 不再对相同原生目标加第二实例。

DataList 先调用既有文档服务的可选兄弟能力 `IEditorSelectionInvalidation`。它只清托管 token/快照，保持 ready/mainThread/writing guards，无需读取中间选句或新增服务。即使 B 场景解析失败、用户又返回 A，也不能复活旧 A 草稿；写入仍要求重新核对当前行和内容。原 `IEditorDocumentService` 签名未改。

日志监听器只捕获实际首条 Unity 字符串的完整哈希、长度、行数和线程/窗口号；不保留原生对象。主线程既有 Update/LateUpdate 泵重新核对 marker 代序和完整场景地址后才发布身份。身份不是执行授权，原租约、内容、场景、代序和观察条件仍需要通过。request 是不透明官方值，0 合法，负值拒绝；没有用场景索引或虚构正数代替它。

这一衔接依赖 fix6 的实际 DataList/日志/预览时序。旧日志只帮助设计关联，不能当作新版已经运行通过的证据。
