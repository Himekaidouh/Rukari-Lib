# 保存与播放标准测试流程（2026-10-11）

这套流程用于验证“创建工程 → 拖拽节点 → 添加内容 → 保存项目 → 发布 → 播放项目”的完整链路。它把前台 UI 验证和离线文件验证分开，任何人都可以在独立测试副本中重复执行。

## 一、测试原则

- 测试使用独立 AA 副本和独立数据根，不直接改用户的正式工程。
- 每个阶段都保存文件时间、长度、SHA-256 和日志尾部，不能只凭画面判断成功。
- `.aap` 是编辑工程，`.aas` 是正式播放档；只有两者同名并在本轮发布后同步更新，才算发布成功。
- 预览成功不等于正式播放成功；必须分别验证编辑器预览和正式播放。
- 手动推进、AUTO、手动转 AUTO、AUTO 转手动分别测试。
- 空对白、只有指令的对白和有文字的对白必须分别测试。
- 失败时保留现场，先收集日志和文件，再重试；不要直接删除 `.lock` 或旧存档。

## 二、固定测试环境

每轮测试记录以下信息：

- AA 版本：1.0 beta、1.0 fix6 或 1.01；一轮只测一个版本。
- BepInEx、ModTheAzureArchive、Il2CppInterop 版本和 SHA-256。
- 模组版本：RukariLib、更多的画面效果、人物配音支持。
- 操作系统、分辨率、是否启用 FlandreScarletMod 等兼容模组。
- 工程数据根：`%USERPROFILE%\\AppData\\LocalLow\\foxxlight\\AzureArchive\\data`。
- 运行日志：`<AA根>\\BepInEx\\LogOutput.log`。
- AAVT 诊断：`<AA根>\\profiles\\<profile>\\configs\\AzureArchive.VideoTools\\diagnostics`。

开始前先复制整个测试数据根到带时间戳的目录，并记录基线清单：

```text
projects/<name>.aap
projects/<name>.aap2（如果版本生成）
saves/<name>.aas
saves/<name>.build.json
projects/<name>/（工程资源目录）
```

## 三、标准测试工程

每轮使用唯一工程名，例如 `Rukari-STD-20261011-01`。节点结构固定为：

```text
Entry → Script-文字 → Script-空白 → Script-指令 → Script-重复对白 → Exit
```

工程内容至少包括：

1. 普通中文对白：用于检查文字和角色映射；
2. 多行对白：包含换行、全角标点和较长文本；
3. 真正的空对白：文本长度为 0；
4. 只有 AAVT 指令的对白；
5. 与上一行完全相同的对白；
6. 一个不存在的语音文件名；
7. 一个合法的人物位置和镜头指令；
8. 一个非法或未知指令，用于确认官方错误隔离；
9. 至少两个角色、一个背景、一个音效和一个背景音乐；
10. 至少一个连续位移：第一句设置起点，第二句从上一句终点继续。

推荐的合法指令样例：

```text
#aavt;char;3;set;x=120;y=80;duration=600;easing=easeInOut
#aavt;camera;set;x=0;y=0;zoom=1.2;duration=600;easing=easeInOut
```

## 四、阶段 A：创建工程与拖拽节点

### A1. 创建

- 新建工程，填写唯一名称。
- 保存一次草稿。
- 关闭并重新打开编辑器。
- 确认工程名称、背景、节点数量和节点顺序保留。

### A2. 拖拽与连接

依次执行：

1. 将两个 Script 节点拖到不同位置；
2. 断开并重新连接 Entry、Script、Exit；
3. 交换两条 Script 节点的顺序；
4. 复制一条 Script，再删除复制品；
5. 拖动窗口和扩展工具大面板；
6. 关闭并重新打开扩展工具。

通过条件：

- 节点没有丢失、重复或自动改名；
- 连接关系与画面一致；
- 面板位置变化不影响节点数据；
- 重新打开后工程仍可读取。

## 五、阶段 B：添加内容

### B1. 文字、空白与指令

分别编辑普通对白、空对白和只有指令的对白。每次修改后都先切换到其他节点，再切回当前节点，确认输入没有被回滚。

极限输入：

- 0 字符；
- 只有空格；
- 只有换行；
- 4096 字符长文本；
- 中英日韩混排；
- 相同对白连续出现 3 次；
- 指令前后各带一行空白；
- 多条 AAVT 指令连续排列；
- 未知命名空间指令。

### B2. 人物与背景

- 添加 5 个槽位人物；
- 切换差分、表情和角色位置；
- 设置背景和背景音乐；
- 切换 Character / Environment 页面；
- 在三号槽位上设置位移和镜头，确认不会自动跳回一号槽位。

### B3. 语音

- 导入一次语音目录；
- 再次导入同一目录；
- 导入一个包含 0 个有效音频和一个缺失音频的目录；
- 检查列表是否重复、页码是否保留、搜索是否跳到正确页；
- 设置全局音量和 AUTO 延迟；
- 手动点击或 Enter 跳过语音，确认不会被 AUTO 延迟阻塞。

## 六、阶段 C：保存草稿

点击普通“保存工程”或等价草稿保存入口，记录保存前后：

- `.aap` 修改时间、长度、SHA-256；
- `.aas` 修改时间、长度、SHA-256；
- 日志中是否只有编辑保存而没有发布记录。

此阶段的预期是：AAP 更新；AAS 可以保持旧版本。关闭 AA 后重新打开工程，确认草稿能恢复。

如果 AAS 也被更新，仍要在报告中记录为“提前发布”，不能把它和正式发布阶段混在一起。

## 七、阶段 D：保存并发布

点击“工程保存 → 保存并发布”，等待页面显示完成。发布前后都记录文件快照。

必须同时满足：

- `<name>.aap` 存在；
- `<name>.aas` 存在；
- `<name>.build.json` 存在；
- 三个文件在本轮操作后更新时间接近；
- AAS 的 revision 或 SHA-256 发生变化；
- 日志依次出现：
  - `publish-receipt stage=AAP`；
  - `embedded-compile status=OK`；
  - `publish-receipt stage=PUBLISH`；
  - `index-load status=READY`。

失败判定：

- 只有 AAP 更新：草稿已保存，但没有完成发布；
- 只有 AAS 更新：发布来源不明，必须回查工程名和日志；
- 出现 `publish-pending` 且超过 10 秒：发布链未收敛；
- 出现 `auto-discover-no-active-pair`：播放索引没有找到有效 AAP/AAS 对；
- build.json 显示缺少语音资源：编译可能成功，但语音包不完整。

## 八、阶段 E：正式播放

关闭编辑器后，从工程对应的 AAS 开始正式播放。每种模式都从第一句重新开始。

### E1. 手动模式

- 第一条普通对白；
- 第一条 AAVT 人物指令；
- 第一条 AAVT 镜头指令；
- 空对白指令；
- 重复对白；
- 连续位移继承；
- 退出播放再重新进入。

### E2. AUTO 模式

- 一开始就打开 AUTO；
- 手动推进一条后切换 AUTO；
- AUTO 中途切回手动；
- 空对白连续执行 5 条；
- 带语音对白和无语音对白交替；
- 语音结束延迟设为 0、最大值和中间值。

### E3. 播放判据

每条指令都需要同时满足：

1. 画面变化正确；
2. 下一条对白按预期推进；
3. 没有官方“未识别指令”报错；
4. 日志能找到对应的 player dispatch 或等价记录；
5. 重播同一条不会叠加漂移。

## 九、阶段 F：极限与故障注入

以下测试在副本数据根执行：

| 编号 | 故障 | 预期 |
|---|---|---|
| F1 | 删除同名 AAS | 编辑器提示未发布，正式播放拒绝使用旧索引 |
| F2 | 删除同名 AAP | 播放档仍在时应明确提示来源缺失 |
| F3 | AAP 新、AAS 旧 | 显示发布未完成，不应静默播放旧档 |
| F4 | AAS 新、AAP 旧 | 回查发布来源，不应覆盖用户草稿 |
| F5 | 保留 `.lock` 后重启 | 不应直接删除；应提示锁状态或安全恢复 |
| F6 | 同一目录重复导入语音 | 列表去重，不能产生两份同名资源 |
| F7 | 缺失语音文件 | 编译继续，但报告具体缺失文件；其他语音仍可播放 |
| F8 | 10000 条语音目录 | UI 不冻结，导入结果明确，分页可跳转 |
| F9 | 5 个角色同时差分切换 | 不应丢槽位、跳槽位或错用角色 |
| F10 | 20 条连续 AAVT 指令 | 只执行一次有效批次，不重复写入 |
| F11 | 保存中关闭窗口 | 不损坏旧 AAP/AAS；下次启动可恢复或明确失败 |
| F12 | 播放中切换场景 | 不沿用上一场景的命令索引或人物基线 |
| F13 | 同名工程改名 | 新旧 AAP/AAS 配对清楚，不产生孤立文件 |
| F14 | 启用 FlandreScarletMod | AAVT 编辑预览和正式播放都应保持独立生效 |
| F15 | 1.0 beta / fix6 / 1.01 | 同一测试工程分别发布并播放，记录兼容差异 |

## 十、性能测试

每项重复 5 次，记录中位数和最大值：

- 首次启动到主界面；
- 打开工程列表；
- 打开含 10000 个语音文件的导入窗口；
- 打开含 19 个对白页的配音列表；
- 切换角色差分；
- 点击绿色预览；
- 保存并发布；
- 正式播放切场景；
- 连续 20 条 AAVT 指令的场景推进。

主线程单次卡顿超过 500 ms 记录为性能告警，超过 2 s 记录为失败候选，并附诊断日志中的 `main-thread stall` 行。
