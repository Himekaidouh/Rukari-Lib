# Android / PE 分段诊断与二分流程（2026-10-14）

配套文档：[Android/PE 适配交接](27_Android_PE端适配交接_20261006.md)、[PE 静态比对](49_Android_PE静态比对_20261014.md)。本文只解决一件事：**手机在手上时，用尽量少的会话次数定位"点开 Script 节点闪退"落在哪一组原生边界上。**

静态比对（docs/49）已排除"成员缺失 / 签名不符"：我们引用的成员在 PE 上全部存在（唯一例外 `UIInputOnGUI.OnGUI` 已有降级）。所以剩下的都是运行时/原生行为，必须实机二分。

## 1. 诊断开关（默认全关 = 生产行为不变）

新增的开关都在各模组配置文件的 `[AndroidDiagnostics]` 段。**每一项都需要重启游戏生效**，日志里会打印当前取值（Lib 与更多画面效果各有一行）。

| 开关 | 位置 | 打开后会发生什么 |
| --- | --- | --- |
| `SkipCompilePatch` | RukariLib | 不装共享编译补丁（`Script.get_ScriptKr` / `CompileScriptStandalone` / `CompileScriptContinuous`） |
| `SkipEditorHost` | RukariLib | 不初始化共享编辑器事务与工作区服务 |
| `SkipInputGuards` | RukariLib | 不装共享输入守卫（`UICamera.ProcessMouse` 等 Harmony 前缀）；**工具箱随之整体停用**（与守卫生效失败时的既有降级路径相同） |
| `SkipToolPages` | 更多的画面效果 | 不注册画面编辑器页与指令帮助页 |
| `SkipEditorProbes` | 更多的画面效果 | 不装选句日志探针与 `ScriptNodeInspector.DataList` 观察 |
| `SkipPlaybackPatches` | 更多的画面效果 | 不装自动对白延迟补丁与显式触发 Behaviour |

已有的开关可以一起用，不必新增代码：

| 现有开关 | 位置 | 作用 |
| --- | --- | --- |
| `[VisualEditor] Enabled=false` | 更多的画面效果 | 关掉画面编辑器本体与它的输入守卫 |
| `[PlayerCommandObservation] Stage=Disabled` | 更多的画面效果 | 关掉播放器命令观察运行时（连带其补丁、嵌入指令补丁、继续对白） |
| `[EditorEmbeddedCommands]` 段 | 更多的画面效果 | 单独控制嵌入指令（`#aavt` 净化）路径 |
| `[EditorSave] Enabled=false` | 更多的画面效果 | 不发布"保存→编译→发布"服务 |
| `[CommandHelp] Enabled=false`（默认已关） | RukariLib | 不往官方指令格式面板追加条目 |
| 配音侧的原生语音安装开关 | 人物配音支持 | `VoiceSupportPatch.Install` 的开关；关掉即不挂钩原生语音接口 |

## 2. 二分顺序（每一步：改配置 → 完整重启 → 复现 → 记录）

**每一步只改一项**，并保留 `LogOutput.log`。目标是在 3–4 次会话内把范围从"全部"缩到"一组"。

| 步骤 | 改动 | 若仍然闪退说明 | 若不再闪退说明 |
| --- | --- | --- | --- |
| A | 官方 Mod 管理里**关闭全部 Rukari Mod** | 与我们的 Mod 无关：先查 Launcher / AA 自身 | 基线干净，可以开始分组 |
| B | 只开 **RukariLib**（其余关闭），`SkipCompilePatch`/`SkipEditorHost`/`SkipInputGuards` 全开 | **Lib 的宿主本身**（`ModRuntimeHost.Start` + `AddComponent<RuntimeBehaviour>`）就出事 | 继续 C |
| C | 只开 RukariLib，只放开 `SkipCompilePatch`（即装共享编译补丁） | 共享编译补丁是触发点 | 继续 D |
| D | 只开 RukariLib，只放开 `SkipEditorHost` | 编辑器事务/工作区读取是触发点 | 继续 E |
| E | 只开 RukariLib，只放开 `SkipInputGuards` | 输入守卫（`UICamera` 前缀）或工具箱 UI 是触发点 | Lib 三组都干净 → 继续 F |
| F | Lib（全开）+ 更多画面效果，`SkipToolPages`/`SkipEditorProbes`/`SkipPlaybackPatches` 全开，`[VisualEditor] Enabled=false`，`Stage=Disabled` | 效果包加载期（`AzureArchiveApiHost.Create` / 配置绑定）有问题 | 继续 G |
| G | 在 F 基础上放开 `SkipPlaybackPatches` | 自动对白延迟补丁或显式触发 Behaviour | 继续 H |
| H | 在 G 基础上放开 `SkipEditorProbes` | 选句日志探针 / `DataList` 观察 | 继续 I |
| I | 在 H 基础上放开 `SkipToolPages` + `[VisualEditor] Enabled=true` | 画面编辑器页/窗口或它的输入守卫 | 继续 J |
| J | 在 I 基础上放开 `Stage`（播放器观察） | 播放器命令观察运行时 | 效果包整体干净 → 换配音包照同样方式二分 |

一旦某一步开始闪退，就在**上一步的配置**与**该步的配置**之间再做一次单变量细分（例如 E 步出事，就把输入守卫与工具箱 UI 分开：先只关工具箱页、留输入守卫）。

## 3. 每次会话的取证（与 docs/49 §5 相同）

```text
adb.exe 路径：artifacts\pe-audit-20261014\tools\scrcpy\scrcpy-win64-v5.0.1\adb.exe
采集脚本：    artifacts\pe-audit-20261014\capture-android.ps1   （只读：devices / dumpsys / logcat / pull）
```

1. 插入手机、开 USB 调试、允许本机调试授权；`adb devices` 应显示 `device`。
2. 跑采集脚本，90 秒窗口内复现一次闪退。
3. 助手读 `logcat.txt`、`crash-buffer.txt`、`BepInEx-LogOutput.log`，并核对 `android-diagnostics:` 那几行是否与本次配置一致（防止改错配置还以为在测另一组）。

**判断方向**：托管异常（`MissingMethod`/`TypeLoad`/`TypeInitialization`）→ 侧重 PE 声明与依赖；`SIGSEGV`/`SIGABRT` + `libil2cpp.so` 地址 → 侧重 ARM64 detour、封送、类注册与对象寿命；进程无 C# 异常直接退出 → 侧重 Launcher 诊断与系统 crash 原因。

## 5. 诊断版怎么装到手机（不覆盖旧版本，随时可回退）

分段开关只存在于**本次改动之后的构建**里（`Rukari.Lib.Runtime` 与 `Rukari.MoreEffects` 两个 DLL 变了，其余五个字节不变）。手机上现在装的是 0.4.2 / 1.4.1 / 1.6.4，做法是**并存而不是覆盖**：

1. 先用 adb 把手机现有版本目录拉到 PC 备份（`mods/RukariLib/0.4.2/`、`mods/更多的画面效果/1.4.1/`、`mods/人物配音支持/1.6.4/`，连同 `manifests`、配置与活动 Profile 记录）。
2. 新建目录并推入本次构建：`mods/RukariLib/0.4.4/`（`Rukari.Lib.dll`、`Rukari.Lib.Runtime.dll`、`manifest.json`、`icon.png`、`LICENSE`、`ART_NOTICE.md`、`ui/`）与 `mods/更多的画面效果/1.6.6/`（`Rukari.MoreEffects.dll`、`Core.dll`、`Formats.dll`、`manifest.json`、`icon.png`、`LICENSE`、`ART_NOTICE.md`）。
3. 配音包本次没有改动，保持 1.6.4 不动；`人物配音支持` 的依赖声明已接受 `RukariLib >=0.4.2 <0.5.0`，与 0.4.4 兼容。
4. 推完用 `adb shell sha256sum` 或拉回本地再算哈希，逐个核对本机构建输出；再在官方 Mod 管理里选择 0.4.4 / 1.6.6 并重启。
5. 回退：在 Mod 管理里切回 0.4.2 / 1.4.1，或把备份目录推回去。旧版本目录在整个过程中没有被改写。

## 6. 边界

诊断开关只影响"是否安装/初始化某一组"，**不改变任何已安装组的行为**；默认值全部为生产取值，因此不做二分时这批改动对 PC 与 PE 都没有影响。开关本身不能修复崩溃，它的用途只是把崩溃收敛到一组，再由实机堆栈确认根因。
